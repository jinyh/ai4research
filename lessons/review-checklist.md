# 逐课材料审校检查清单

本清单与 [备课规划.md](./备课规划.md) 的多引擎协作流程配合使用，覆盖事实准确性、教学节奏、跨文档一致性、可执行性和表述口吻。通用核心适用于每课；MI、图片、正式提交门和时效性规范只在材料实际涉及对应对象时触发。

## 一、表述口吻（第五审阅维）

目标：让材料读起来像一位资深研究者在讲课。结构化术语、状态名、权限层级和学术红线原样保留；指令性否定句优先改为可执行的正面动作。审查前先列出学术红线、安全权限、证据标准和虚构/脱敏标记，改写后逐条复核没有削弱边界。

- [ ] **对仗句式去密**：通篇"不是 X，而是 Y"是否页页/段段出现？保留 2-3 处确有张力的点睛句，其余转正面陈述。
- [ ] **meta 自白清除**：备注或正文中是否反复出现"本页只建立张力""本页是为了 X""这里引用它是为了 Y"等设计意图自白？改为教师面对学生的自然过渡语或直接陈述。
- [ ] **机械编号松绑**：备注里"先…再…最后…"是否滥用？保留必要编号，但把整齐的编号叙述改散句。
- [ ] **标题腔降格**：页/节标题是否清一色判断句、读成格言集？约半数改为更具体的指引式，少数保留有力判断句。
- [ ] **否定式指导克制**：视觉/制作指导是否靠"不要…"堆叠？保留功能性 2-3 处，其余转正面表述（如"使用极简封面"代"不使用 Logo 拼贴"）。
- [ ] **讲述与设计说明区分**：教师讲述备注是否写成设计理由（"X 从首课使用，是因为…"）？改为可直接说出口的讲述版本，设计理由并入"来源与事实边界"。

## 二、内容、节奏与跨文档一致性

- [ ] 贯穿案例衔接：演示案例与个人实践题池是否同质？若同一问题同时用于教师演示和学生作业，个人实践会沦为复刻。
- [ ] 跨页案例线索：从"一句 AI 总结"到"可检验问题"等贯穿案例，跨页是否有明确过渡，还是被读成两个不相干例子？
- [ ] 时间表自洽：节奏表页码区间与各页"建议时间"是否一致、有无重叠或遗漏？合计是否覆盖 0-90 分钟。
- [ ] 与 `handout.md` / `teaching-plan.md` / `slides.md` 口径一致：八阶段命名、正式提交课次、证据标准、平台定位、评分比例、案例边界和工件字段逐项核对；课次特有契约只按本课权威源检查，不升级为全课硬门。
- [ ] 备用题池与演示主题区分：题池首题是否复用课堂演示的研究问题？
- [ ] 当前页或段落与前后叙事有明确关系；同一概念没有在相邻页重复解释而不增加判断、证据或学生动作。

## 三、事实口径

- [ ] 引文核对：Nature/期刊论文的 DOI、卷期、页码、标题与 `references/library/papers/` 原件、`references/notes/nature.md`、`references/README.md` 四层自洽。
- [ ] 内部文档路径：所有 `../course/<file>` 相对链接指向的文件确实存在。
- [ ] 时效与分级：引用 `references/` 中材料时，A 级原件可直接用，B/C 二手整理（如 nature.md）须标注"授课前回源核验"。
- [ ] 不虚构文献、引文或真实研究结果。教师构造的练习、数值和工件明确标为“虚构教学示例、非实证结论”，不能用“未经核验”混淆教学构造与待核事实。
- [ ] AI 输出不作证据：AI 生成的摘要、推断只在核验后作为线索，不直接写成已证实事实。

## 四、条件触发模块

材料涉及下列对象时追加检查；未涉及时标记“不适用”，不把它们变成每课统一负担。

- [ ] **MI 或其他贯穿案例**：素材 ID 与 registry 一致；真实演示和虚构练习分线；公开/未发表边界、模型与仓库版本明确；未发表内容不进入 handout 或公开网站。
- [ ] **图片与屏显证据**：课级 `assets/README.md` 登记来源角色、出处、许可/虚构标记和脱敏状态；嵌入处一致；站点只发布白名单文件。
- [ ] **研究门课次**：门名称、条件、材料、未通过处理和评分证据逐项回到 `course/assignments.md`、`assessment.md` 核对。
- [ ] **规范、软件或时效事实**：记录核验日期和正式来源；授课前复核学校规则、产品能力、版本、许可和链接。
- [ ] **PPTX**：执行 `course/ppt-quality-gates.md` 与 `lessons/ppt-design-criteria.md`，核对最后一次磁盘写入后的正式路径。

## 五、版本与文件

- [ ] 不覆盖用户改动：重大改写前确认工作树和 diff；日常版本交给 Git，只有具备独立决策价值的历史稿才进入 `archive/`。
- [ ] 版本号合规：现行文件使用稳定短名称，版本号只在 front matter；不在 `lessons/` 保留 `v1/v2/final` 平行副本。
- [ ] 变更记录：front matter `变更记录` 追加本次版本条目，说明改了什么、未动什么。
- [ ] Git diff 干净：只含本任务涉及的文件，无凭据、敏感路径、孤儿文件或无关改动。
- [ ] 同步引用：逐课 MOC、`lessons/README.md` 和相关 `course/` 权威源在引用了被改文件版本时同步。

## 使用方式

1. 主笔完成初稿后按通用核心自检，再启用适用的条件模块，在 front matter 或课次 README 登记结论。
2. AI 审阅者可直接修复事实错误、路径/版本错误、客观跨文档不一致和可重复验证的技术问题，并在 diff 或台账中记录。
3. 教学取舍、课堂负荷、学校规范的课程化解释、真实/未发表材料授权和正式发布通过只提出建议，登记到 [教师复核台账](./teacher-review-ledger.md)。
4. 重要来源、时效性信息、Microsoft PowerPoint 和教室投影结果仍由人工最终确认。
