# 逐课材料审校检查清单

本清单与 [备课规划.md](./备课规划.md) 的多引擎协作流程配合使用，覆盖事实准确性、教学节奏、跨文档一致性、可执行性和表述口吻。通用核心适用于每课；MI、图片、正式提交门和时效性规范只在材料实际涉及对应对象时触发。

## 一、表述口吻（第五审阅维）

目标：让材料读起来像一位资深研究者在讲课。结构化术语、状态名、权限层级和学术红线原样保留；指令性否定句优先改为可执行的正面动作。审查前先列出学术红线、安全权限、证据标准和虚构/脱敏标记，改写后逐条复核没有削弱边界。

- [ ] **对仗句式去密**：通篇"不是 X，而是 Y"是否页页/段段出现？保留 2-3 处确有张力的点睛句，其余转正面陈述。
- [ ] **meta 自白清除**：备注或正文中是否反复出现"本页只建立张力""本页是为了 X""这里引用它是为了 Y"等设计意图自白？改为教师面对学生的自然过渡语或直接陈述。
- [ ] **机械编号松绑**：备注里"先…再…最后…"是否滥用？保留必要编号，但把整齐的编号叙述改散句。
- [ ] **标题腔降格**：页/节标题是否清一色判断句、读成格言集？约半数改为更具体的指引式，少数保留有力判断句。
- [ ] **否定式指导克制**：视觉/制作指导是否靠"不要…"堆叠？保留功能性 2-3 处，其余转正面表述（如"使用极简封面"代"不使用 Logo 拼贴"）。
- [ ] **讲述与设计说明区分**：教师讲述备注是否写成设计理由（"X 从首课使用，是因为…"）？改为可直接说出口的讲述版本，设计理由并入"来源与事实边界"。

## 二、内容、节奏与跨文档一致性

- [ ] **讲义独立阅读**：学生离开课堂后能否理解研究问题、术语、方法步骤与判断理由？讲义须提供必要解释、具体示例和证据位置，不能只有教师口头补充才能成立的提纲。
- [ ] **示例与任务连接**：每个主要示例帮助学生完成哪项研究动作？共同案例、个人迁移和上下课工件是否形成同一条可追踪主线？切换对象时明确条件差异和迁移方法。


- [ ] **案例连续性**：跨页及讲义、教案、PPT、材料包和演示文件中的研究对象、比较条件、指标、字段名是否一致？同一案例的输入、判断、变化和下一步能否追踪？切换案例时说明迁移的方法及新条件。
- [ ] **独立判断**：演示与实践可以沿用同一案例；学生是否仍需自己选择、说明理由和核验结果？完成标准不能退化为复制教师答案。备用题允许复用演示主题，但应给出需要学生独立决定的一处问题。
- [ ] 时间表自洽：节奏表页码区间与各页"建议时间"是否一致、有无重叠或遗漏？各段是否只以整数时长呈现、合计恰好 90 分钟、无绝对起止时间残留？个人实践是否每段 ≤15 分钟（超出已拆两段并插教师中点点评；同伴互查/轮转不受限）？屏显是否不含任何课堂分钟数（含阅读/准备时长估算）、讲义是否不含课堂计时分钟数？
- [ ] 与 `handout.md` / `teaching-plan.md` / `slides.md` 口径一致：八阶段命名、正式提交课次、证据标准、平台定位、评分比例、案例边界和工件字段逐项核对；课次特有契约只按本课权威源检查，不升级为全课硬门。
- [ ] **页面递进**：说清本页让学生理解或判断什么，下一页增加哪项证据、解释或动作；提问与方法是否逐项对应？保留有教学作用的分步揭示，合并没有信息增量的重复页，不固定要求合页。
- [ ] **概念对应**：阶段名、解释、案例动作和工件是否语义一致？必要条件、机制假设、方案形成、实际执行与结果回写应区分；实验规格不能代替实际验证，文件保存不能代替研究成立。
- [ ] **演示边界**：涉及演示时，教案明确谁讲、谁操作、学生观察或判断什么，以及输入、可见结果、失败备用路径和收束位置；说明本次操作完成哪个研究动作、哪些问题仍待验证。角色按本课条件安排，不固定为教师讲解或助教操作。

## 三、事实口径

- [ ] **结论完整性**：页面取舍是否遗漏会改变解释的重要结果、比较层级或反例？每项结论是否对应原文中的指标与范围？分清论文结果、作者解释和教学启示；不要求罗列全部结果，但不能因精简改变原意或将代理指标等同于更宽概念。
- [ ] 引文核对：Nature/期刊论文的 DOI、卷期、页码、标题与 `references/library/papers/` 原件、`references/notes/nature.md`、`references/README.md` 四层自洽。
- [ ] 内部文档路径：所有 `../course/<file>` 相对链接指向的文件确实存在。
- [ ] 时效与分级：引用 `references/` 中材料时，A 级原件可直接用，B/C 二手整理（如 nature.md）须标注"授课前回源核验"。
- [ ] 不虚构文献、引文或真实研究结果。教师构造的练习、数值和工件明确标为“虚构教学示例、非实证结论”，不能用“未经核验”混淆教学构造与待核事实。
- [ ] AI 输出不作证据：AI 生成的摘要、推断只在核验后作为线索，不直接写成已证实事实。

## 四、条件触发模块

材料涉及下列对象时追加检查；未涉及时标记“不适用”，不把它们变成每课统一负担。

- [ ] **MI 或其他贯穿案例**：素材 ID 与 registry 一致；真实演示和虚构练习分线；公开/未发表边界、模型与仓库版本明确；未发表内容不进入 handout 或公开网站。
- [ ] **图片与屏显证据**：课级 `assets/README.md` 登记来源角色、出处、许可/虚构标记和脱敏状态；嵌入处一致；站点只发布白名单文件。
- [ ] **研究门课次**：门名称、条件、材料、未通过处理和评分证据逐项回到 `course/assignments.md`、`assessment.md` 核对。
- [ ] **规范、软件或时效事实**：记录核验日期和正式来源；授课前复核学校规则、产品能力、版本、许可和链接。
- [ ] **PPTX 最终材料一致性**：执行 `course/ppt-quality-gates.md` 与 `lessons/ppt-design-criteria.md`，直接读取最后一次磁盘写入后的 PPTX 屏显与备注，并对照最终渲染、母稿、教案及演示输入输出。插页、删页或新增封面后核对实际页序、页脚与引用映射。旧预览、母稿或 PASS 记录不能替代本轮最终文件证据；历史记录保留当时页码并标明版本。

## 五、版本与文件

- [ ] 不覆盖用户改动：重大改写前确认工作树和 diff；日常版本交给 Git，只有具备独立决策价值的历史稿才进入 `archive/`。
- [ ] 版本号合规：现行文件使用稳定短名称，版本号只在 front matter；不在 `lessons/` 保留 `v1/v2/final` 平行副本。
- [ ] 变更记录：front matter `变更记录` 追加本次版本条目，说明改了什么、未动什么。
- [ ] Git diff 干净：只含本任务涉及的文件，无凭据、敏感路径、孤儿文件或无关改动。
- [ ] 同步引用：逐课 MOC、`lessons/README.md` 和相关 `course/` 权威源在引用了被改文件版本时同步。

## 使用方式

1. 主笔完成初稿后按通用核心自检，再启用适用的条件模块，在 front matter 或课次 README 登记结论。
   单纯审阅按用户指定范围检查相关页及必要的前后文，不自动改写或重制整课。发现项记录实际文件与页码、观察依据、学生理解受到的影响及最小修正；已验证、建议和待现场验证分别说明。
2. AI 审阅者可直接修复事实错误、路径/版本错误、客观跨文档不一致和可重复验证的技术问题，并在 diff 或台账中记录。
3. 教学取舍、课堂负荷、学校规范的课程化解释、真实/未发表材料授权和正式发布通过只提出建议，登记到 [教师复核台账](./teacher-review-ledger.md)。
4. 重要来源、时效性信息、Microsoft PowerPoint 和教室投影结果仍由人工最终确认。

## 研究判断与负荷验收（2026-10-12）

- 学生先独立作答再揭示教师依据；每课至少有一个必须核对原文、数据或 trace 才能决定的分歧。
- 检查决定、证据位置、验证与实际回写；有依据的“仍不能判断”可达标，记录下一项证据。
- 普通课默认按 5/10/10/10/5/15/5/15/10/5 分钟组织；L04按2026-10-21教学选目修订，将讨论与原文校准调整为5/10分钟，即5/10/10/5/10/15/5/15/10/5，总计90分钟，两段个人实践仍各15分钟。L8/L15/L16专用结构仍须90分钟，换场包含在内。
- 课外每课最多60分钟，包括阅读、排障、项目和提交；四门不叠加新必读。三卡在L4–L6课堂逐张形成。
- 实测填写：课次、准备/阅读/项目用时、提示次数、卡点、采用的备用路径、实际回写位置。未试做填写“待测”，不能用桌面推演冒充学生完成时间。
- 无 AI 错误、两条来源均通过、无改善、负结果、网络故障和同题独立判断均按真实证据验收；不设失败配额。
- 工程终稿须含本人实际执行、实质修改、同输入对照及 trace；保存输出回放和已公开参考判定保留其身份。
- 教师答案不进学生发布白名单/下载/搜索。内容复核、文件检查和现场教学验证分别登记，旧版通过不能继承。

## 本轮证据与复验

执行入口见[全课备课 Harness](../docs/lesson-harness.md)。每项观察绑定实际材料版本与章节／页码，记录影响、是否阻断、修改动作及复验结果。每轮保留“保留／重复／需改变的表达”差量。新文件不能继承旧检查通过；呈现阶段逐页渲染与联系表分别检查。运行状态区分通过、阻断、证据不足和执行故障；这些状态不替代教师批准。

## 教师 Demo、个人迁移与研究挑战性（2026-10-20）

- [ ] **演示身份**：MI 是教师贯穿 Demo；学生短时共同诊断后回到本人项目。三张精读卡、四个研究门和个人实践不隐含 MI 必做要求。
- [ ] **研究挑战性**：核心问题不能只凭措辞或模板答对；至少一种合理替代解释需要原文、数据、代码、推导或轨迹才能判断。准确采纳原解释也可成立。
- [ ] **跨方向迁移**：ML、系统／软件、文献／理论项目均有适配路径。无代码者可检查推导、数据或设计；GPU、机制图与三份数据划分只适用于相应项目。
- [ ] **实际推进**：本课产出影响本人下一项研究决定；教师背景讲解不挤占两段个人实践。未准备论文者有可用备用材料。
- [ ] **评审证据**：Agent 自检、独立会话、教师、助教试做与现场检查分别登记。引文逐字与位置校验不证明推理正确，模型结论仍须审查。

新一轮采用 `review_profile: personal-projects-v1`，增加 pedagogy.challenge 与 pedagogy.transfer 两项实际观察；旧报告保留旧身份。标准详见 [Harness](../docs/lesson-harness.md)。
