# 第 12 课教师教案｜Agent/Skill 背后的逻辑与个人工作流设计

## 一、本课定位（gate1）

- 学时：2 学时，90 分钟
- 模块：第 10-13 课"原型、自动化与个人工作流"模块，Agent/ML 实践类型
- 研究链路阶段：阶段 7 原型验证（工作流设计子阶段）
- 核心问题：如何把自己的科研动作封装为可审计工作流，而不是照搬现成 Skill？
- 教学类型：讲授 + 案例拆解 + 个人设计 + 同伴互查
- 课堂产出：个人 Agent Workflow 说明（八要素）、可运行或可演示原型草图、评价计划
- 正式提交：本课不正式提交；产出为第 13 课验证门材料包的前置状态

本课承接第 10-11 课：第 10 课把单次编码动作写成任务契约并约束权限，第 11 课把可重复动作改写为受限循环。本课把视角从"用一次 Agent"提升到"看懂并设计一个工作流"，用第 1 课 §四的八要素框架拆解现成 Agent/Skill，并要求学生为自己的真实科研动作设计可审计的个人 Agent Workflow。

本课必须建立三项共识：

1. 现成 Agent/Skill 不是黑箱，它们隐含八项可审计设计决定；
2. 不是所有动作都需要 Agent，确定性脚本、固定工作流、单 Agent、更复杂系统各有适用条件；
3. 个人 Agent Workflow 是验证门产出之一，评分看可审计与可评价，不看工具数量。

## 二、学习目标

完成本课后，学生能够：

1. 用八要素框架拆解一个现成 Agent/Skill；
2. 判断科研动作适合确定性脚本、固定工作流、单 Agent 还是更复杂系统；
3. 为自己真实科研动作写出个人 Agent Workflow 说明（输入、输出、成功标准、不适用范围、权限、停止条件、人工审核点、失败恢复）；
4. 为该工作流设计一次可重复评价（baseline、指标、对照）；
5. 在 OpenCode 或等价环境中完成可运行或可演示最小原型草图；
6. 把上述产物组织成验证门前置状态。

## 三、课前准备

### 教师

- [ ] 中文 PPT（逐页母稿见 [slides.md](./slides.md)）；继承交大模板母版、版式、字体与品牌元素
- [ ] 一个可在课堂拆解的现成 Skill/Agent 案例（建议 AutoResearch 或课程案例池中一个 MCP server），预先用八要素填好拆解卡
- [ ] 一个个人 Agent Workflow 草图演示项目（公开或虚构内容，含任务契约、权限边界、运行记录、至少一次失败）
- [ ] 八要素拆解卡模板（A4 单页，对应 handout §二）
- [ ] 个人工作流设计模板（对应 handout §4.2）
- [ ] 同伴互查用三问反馈卡
- [ ] 备用环境说明：OpenCode 不可用时的纸面或 Markdown 模板路径

### 学生

- [ ] 已完成第 11 课受限循环设计（本课在其上扩展）
- [ ] 携带个人项目中一个真实科研动作（可来自第 1-11 课推进）
- [ ] OpenCode 或等价环境可用；不可用者提前报告
- [ ] 已阅读 Wooldridge & Jennings 1995 选段和 Anthropic *Building Effective Agents*

### 安全与资源口径

- 不要求学生自费购买 API token；
- 不把未公开论文、敏感数据、学生资料或私人凭据用于课堂演示；
- 演示项目不得包含真实学生资料或凭据；
- 不要求开启全盘读写或无确认命令执行；
- 现成 Skill 仓库仅作案例拆解对象，不作为学习目标。

## 四、90 分钟流程（gate3）

| 时间 | 内容 | 主要形式 | 产出 |
| --- | --- | --- | --- |
| 0-6 | 开场：从"用 Agent"到"看懂 Agent" | 讲授 + 快问 | 核心问题 |
| 6-20 | 八要素拆解演示：用一个现成 Skill 现场填八要素 | 教师示范 + 学生跟随 | 拆解卡 |
| 20-32 | 何时不用 Agent：脚本/工作流/Agent 取舍 | 讲授 + 情境判断 | 取舍判断 |
| 32-50 | 个人工作流设计：从动作到八要素契约 | 个人设计 | 工作流说明草稿 |
| 50-60 | 教师演示：一个个人 Agent Workflow 草图原型 | 教师示范 | 原型草图与运行记录 |
| 60-78 | 个人实践：写契约、定权限、画循环、设 baseline | 个人实践 | 原型草图与评价计划 |
| 78-86 | 同伴互查：八要素是否齐、是否有越权、是否有 baseline | 2 人互查 | 反馈记录 |
| 86-90 | 知识点总结；退出卡与第 13 课验证门预告 | 总结 + 个人填写 | 知识回收与验证门准备 |

> 节奏逐项对齐 `备课规划.md` 第 12 课权威 8 段逐时间表；`slides.md` P01-P20 已按同一 8 段完成页码映射与段内时间分配。

**第一次学生动手时间**：32 分钟（P11 开始个人工作流设计）；60-78 分钟为持续个人实践与自检。

**最小课堂产出**：一份八要素工作流契约 + 一张目录树或流程图 + baseline/指标/人工确认点 + 失败 trace 与恢复位置。

**备用路径**：若现场环境故障，使用纸面或 Markdown 模板完成同一字段的契约与原型草图，不把课程时间消耗在逐台排障。

## 六、教师演示脚本

### 演示一：八要素拆解

- 演示对象：AutoResearch 或课程案例池中一个 Skill/MCP server
- 演示前状态：拆解卡模板已发学生，教师手中有一份填好的参考版
- 判断点：
  1. 这个 Skill 的任务契约是否写明不适用范围？
  2. 它默认能读哪些目录、能联网吗？
  3. 它的停止条件是预算还是模型自决？
  4. 它的失败如何记录？

### 演示二：个人工作流原型草图

- 演示项目：公开或虚构的"每周证据地图更新"工作流（对应 handout §五）
- 演示前状态：项目含任务契约、权限边界、一次运行记录、一次失败记录
- 判断点：
  1. 这次运行留下了哪些可复核 trace？
  2. 评价代码与执行代码是否隔离？
  3. 失败如何回写为研究判断？
  4. 哪些步骤必须人工确认？

### 失败演示

可预先准备一个越界请求：让 Agent"顺便帮你联网搜相关论文加进证据地图"。让学生指出它越过了哪些边界（不适用范围、权限、人工审核点、失败恢复），再改写为受限版本。

## 七、课堂产出验收

- [ ] 八要素拆解卡至少填了 6 项，并指出两处隐含设计决定
- [ ] 个人工作流说明按模板填了任务契约、Context、工具与权限、执行循环、Evals 计划、人工审核点
- [ ] 任务契约写明不适用范围，成功标准可测量
- [ ] 权限按五档划分，至少一个需确认点
- [ ] 评价计划有 baseline 和对照或等价依据
- [ ] 原型草图可运行或可演示（纸面或环境均可）
- [ ] 至少保留一次失败或局限的记录位置
- [ ] 同伴反馈由作者自己决定是否采纳

本课不要求正式提交。学生保留并继续推进，第 13 课随验证门统一检查。

### Checkpoint 3 前置覆盖复核

本课不提前降低第 13 课门条件；十项条件在本课与下一课的分工如下：

| Checkpoint 3 条件 | 本课形成的前置状态 | 第 13 课完成项 |
| --- | --- | --- |
| 明确科研动作与任务契约四字段 | 写入工作流说明 | 复核边界 |
| 可运行或可演示原型 | 建立最小原型草图 | 运行或演示 |
| Context、Memory、工件、工具/MCP、数据来源 | 写入八要素契约 | 核对实际运行 |
| 权限、预算、停止、人工确认 | 写入八要素契约 | 核对越权与停止记录 |
| 可重复评价及 baseline/对照 | 写评价计划 | 完成评价 |
| 失败、无效建议或局限 | 预留并演示失败记录 | 至少保留一次实际记录 |
| AI 输出人工审核 | 指定审核点与记录位置 | 完成人工审核记录 |
| 对原研究动作的实际影响 | 明确评价问题 | 完成影响报告 |
| 关键结论的证据强度、冲突与缺口 | 指定追踪工件 | 完成结果回写 |
| 伦理、数据访问、权限与外部服务边界 | 复核权限与禁止项 | 更新合规说明 |

## 八、讲后复盘

教师课后记录：

- 学生是否把"看懂 Agent"和"调用 Agent"混淆？
- 八要素拆解中哪一项最难判断？
- 学生科研动作是否过宽，导致工作流无法在验证门内评价？
- 是否出现越权、敏感材料或凭据风险？
- 个人工作流评价计划是否普遍缺 baseline？
- 第 13 课需要补哪些评价与失败复盘内容？
