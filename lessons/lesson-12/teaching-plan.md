# 第 12 课教师教案｜Agent/Skill 背后的逻辑与个人工作流设计


## 整体复审补充：板书、诊断与串词（2026-09-15）

本节替换同类口头提示，不增加既有时段。开场诊断嵌入现有开场/回顾，后续再沿原实践时段操作。

- **板书主线**：科研动作 → 输入 → 执行 → 评价 → 人工判断。
- **诊断问题**：接口拒绝gold，能否证明任意程序都读不到它？
- **预期回答**：不能，只证明该入口的角色控制；真实隔离另验。
- **常见误答后的追问**：若选型只写Agent，先问固定链为何不足。
- **过渡串词**：“有了可演示路径，第13课用已有结果评价它的实际影响。”
- **当堂最小产出**：一个本人科研动作的工作流说明和可演示路径。
- **退出记录**：写“已完成的动作、本人项目仍缺的证据/工件、下次补齐位置”。使用教师包时标明课堂方法练习，不能据此宣称本人研究门通过；正式提交课次仍为第 6、9、13、16 课。


## 一、本课定位（gate1）

- 学时：2 学时，90 分钟
- 模块：第 10-13 课"原型、自动化与个人工作流"模块，Agent/ML 实践类型
- 研究链路阶段：阶段 7 原型验证（工作流设计子阶段）
- 核心问题：如何把自己的科研动作封装为可审计工作流，而不是照搬现成 Skill？
- 教学类型：讲授 + 案例拆解 + 个人设计 + 同伴互查
- 课堂产出：个人 Agent Workflow 说明（八要素）、可运行或可复现演示的最小原型、评价计划
- 正式提交：本课不正式提交；产出为第 13 课验证门材料包的前置状态

本课承接第 10-11 课：第 10 课把单次编码动作写成任务契约并约束权限，第 11 课把可重复动作改写为受限循环。本课把视角从"用一次 Agent"提升到"看懂并设计一个工作流"，用第 1 课 §四的八要素框架拆解现成 Agent/Skill，并要求学生为自己的真实科研动作设计可审计的个人 Agent Workflow。

本课必须建立三项共识：

1. 现成 Agent/Skill 不是黑箱，它们隐含八项可审计设计决定；
2. 不是所有动作都需要 Agent，确定性脚本、固定工作流、单 Agent、更复杂系统各有适用条件；
3. 个人 Agent Workflow 是验证门产出之一，评分看可审计与可评价，不看工具数量。

## 二、学习目标

完成本课后，学生能够：

1. 用八要素框架拆解一个现成 Agent/Skill；
2. 判断科研动作适合确定性脚本、固定工作流、单 Agent 还是更复杂系统；
3. 为自己真实科研动作写出个人 Agent Workflow 说明（输入、输出、成功标准、不适用范围、权限、停止条件、人工审核点、失败恢复）；
4. 为该工作流设计一次可重复评价（baseline、指标、对照）；
5. 在 OpenCode 或等价环境中完成可运行或可复现演示的最小原型；
6. 把上述产物组织成验证门前置状态。

## 四、90 分钟流程（gate3）

| 时间 | 内容 | 主要形式 | 产出 |
| --- | --- | --- | --- |
| 5 分钟 | 回看第 10–11 课的契约、四约束与 trace；学生标出一项尚未封装的状态 | 个人标记 + 快问 | 工作流输入 |
| 10 分钟 | 八要素只补第 10–11 课尚未显式化的 Context、Memory、工件、Evals 与人工审核 | 短讲 + 工件对照 | 完整工作流契约 |
| 10 分钟 | 根据任务变异性在确定性脚本、固定链与 Agent 之间做选择 | 讲授 + 情境判断 | 执行模式及理由 |
| 15 分钟 | 教师演示：将同一阅读卡生成任务封装为固定链，运行或演示一个最小路径并保留 trace | 教师演示 | 可运行/可演示原型 |
| 10 分钟 | 个人实践第一段：把现有任务写成工作流契约并选择执行模式 | 个人实践 | `agent-workflow.md` 初版 |
| 5 分钟 | 教师中点点评：处理任务过宽、自主性过度和 Evals 与执行未隔离 | 教师点评 | 原型收窄方向 |
| 10 分钟 | 个人实践第二段：运行或演示最小路径，保留一条 trace 与失败恢复位置 | 个人实践 | 原型 + trace |
| 15 分钟 | 同伴互查：任务、模式、权限、Evals 和 trace 是否一致 | 2–3 人互查 | 互查问题与作者决定 |
| 10 分钟 | 确认课后补全与第 13 课所需的既有运行结果，完成退出卡 | 总结 + 个人回写 | 评价前置状态 |

> 各段只使用整数时长，合计 90 分钟。个人实践拆成两段，中间由教师处理共性卡点。

**第一次学生动手**：开场即标记尚未封装的状态。持续个人实践为两个 10 分钟段，中间含 5 分钟教师点评。

**最小课堂产出**：在同一前置任务上完成八要素工作流契约的最小字段 + 一个模式选择及理由 + 一个可运行或可演示的最小原型 + 一条 trace + 失败恢复位置。

**课后补全**：写回 `agent-workflow.md`，并在第 13 课前准备一次可用于评价的运行结果。验证门完整条件不在本课课堂一次补齐。

**备用路径**：若现场环境故障，先用 Markdown 完成契约，再用教师预置输入与 trace 走通离线演示路径，不把纸面流程图当作原型，也不把课程时间消耗在逐台排障。

## 六、教师演示脚本

1. 继续打开 L11 同一小包，依次指出输入、events、state、评价入口和人工审核点。
2. 选择固定链的理由是当前输入与步骤已固定；真实任务有变异时再考虑 Agent。
3. 执行 access-check 展示 executor 读 gold 被接口拒绝，说明它不是操作系统级隔离。
4. 同伴从输出反查一项源文本条件及版本；离线也按实际输入和 trace 走完整路径。
5. 课后将本人项目评价输入准备好，L13 使用已有结果。

## 七、课堂产出验收

- [ ] 指定本人一个科研动作与任务契约，不另起独立研究项目
- [ ] 在工作流说明中定位输入、执行、评价、权限及人工审核；缺项如实标记
- [ ] 最小路径可运行，或用预置输入与实际 trace 完成可反查演示
- [ ] 指出一项失败/局限和下一步评价证据需求

八要素是课后完善与第 13 课门条件核对框架，不要求课堂把所有字段填成成稿。教师小包只用于方法练习，个人项目的运行、评价和人工核验须继续补齐。

### Checkpoint 3 前置覆盖复核

本课不提前降低第 13 课门条件；十项条件在本课与下一课的分工如下：

| Checkpoint 3 条件 | 本课形成的前置状态 | 第 13 课完成项 |
| --- | --- | --- |
| 明确科研动作与任务契约四字段 | 写入工作流说明 | 复核边界 |
| 可运行或可演示原型 | 建立最小原型草图 | 运行或演示 |
| Context、Memory、工件、工具/MCP、数据来源 | 写入八要素契约 | 核对实际运行 |
| 权限、预算、停止、人工确认 | 写入八要素契约 | 核对越权与停止记录 |
| 可重复评价及 baseline/对照 | 写评价计划 | 完成评价 |
| 失败、无效建议或局限 | 预留并演示失败记录 | 至少保留一次实际记录 |
| AI 输出人工审核 | 指定审核点与记录位置 | 完成人工审核记录 |
| 对原研究动作的实际影响 | 明确评价问题 | 完成影响报告 |
| 关键结论的证据强度、冲突与缺口 | 指定追踪工件 | 完成结果回写 |
| 伦理、数据访问、权限与外部服务边界 | 复核权限与禁止项 | 更新合规说明 |

## 八、讲后复盘

教师课后记录：

- 学生是否把"看懂 Agent"和"调用 Agent"混淆？
- 八要素拆解中哪一项最难判断？
- 学生科研动作是否过宽，导致工作流无法在验证门内评价？
- 是否出现越权、敏感材料或凭据风险？
- 个人工作流评价计划是否普遍缺 baseline？
- 第 13 课需要补哪些评价与失败复盘内容？
