# 第 12 课共同诊断｜自主性与实质工作流设计

## 先独立判断

**问题：这个任务需要 Agent 自主选择吗？**

输入：L11 可恢复动作与 trace。先记录判断和依据，再与同伴比较；课堂校准后可修订并写明改变原因。答案有分歧时回到具体记录。已有示例可作方法参考，不替代本人的初始判断。

## 原始材料与待比较选项

同一教学构造需求：输入公开阅读记录；拒绝不合法记录；人工判定语义；汇总两条件结果；失败可恢复。

| 设计 | 控制与信息 |
| --- | --- |
| A 确定性脚本 | 固定校验→排队→人工标注→汇总，输入版本冻结 |
| B 固定链 | 先导航，再提取，人工审核后进入相同评价器 |
| C Agent | 自行挑资料、重试和改提示；可读 gold；得分上升即采用 |

团队已有 A 的可运行起点，B/C 尚无独立效果数据。

**待决定：**选择最小满足任务的设计；如增加自主性，指出必要条件、预算和独立评价方式。

把“初始判断—证据位置—仍缺什么—核验后决定”写在现有笔记中。允许回答“仍不能判断”，同时指出下一项能改变判断的证据。

实际实现入口：[个人微型项目](../../course/micro-project.md)，与原回放包服务同一个人项目。

## 迁移到本人项目

在个人副本接入 L10 校验，或增加分组盲化/任务状态持久化等一个实质环节。对真实输入走通输入→处理→人工检查→评价 trace；输出标明 accepted/rejected 与理由，正常项守恒。

**验证：**同一输入运行 baseline 与改动版；检查拒绝记录仍在账本中，gold 不参与执行端选择。只换提示词措辞、改标题或画流程图不能替代实际实现。

**保存位置与达标证据：**本人可运行工作流、实质 diff、任务契约与端到端 trace。

**下课去向：**L13 按冻结协议评价 baseline 和改动版。

## 完成标准

| 尺度 | 判断依据 |
| --- | --- |
| 需支持 | 完成操作，但理由、证据定位或验证仍有缺口。 |
| 达标 | 独立决定，证据可定位，完成相称验证，并更新本人项目。 |
| 优秀 | 识别替代解释或有效性威胁，以额外检查改变或加强判断。 |

课堂尺度对应课程的待改、达标、卓越；不新增每周成绩或提交。优秀依判断质量，不要求更多课外时长。

断网时保留同样的判断要求，使用包内文本、存档或本地工件。工程课纸面诊断仅作备用练习，最终仍须补本人实际执行、实质修改和对照评价。提前完成者可寻找一个使自己决定改变的反例；不增加课后任务。
