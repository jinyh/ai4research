# 第 12 课逐页脚本｜Agent/Skill 背后的逻辑与个人工作流设计

## 一、使用说明

### 本课唯一主目标

> 学生为自己的真实科研动作设计一份可审计的个人 Agent Workflow。

本课不追求在 90 分钟内讲透所有 Agent 架构，也不把任何现成 Skill 的安装和调用当作学习目标。八要素框架用于拆解现成工具；贯穿案例用于演示设计结果；个人实践用于把"我会用 Agent"升级为"我能设计并审计一个工作流"。

### 适用条件

- 21-40 人；
- 连续 90 分钟；
- 中文授课，英文仅保留论文名、工具名和必要术语；
- 正式 PPT 继承 [交大模版.pptx](../../references/library/template/交大模版.pptx) 的母版、版式、字体与品牌元素；
- OpenCode、Git 和模型后端尽量在课前完成环境确认；
- 学生携带个人项目中一个真实科研动作；
- 本课无正式提交，产出为第 13 课验证门前置状态。

## P01｜从会用 Agent，到看懂谁替你做决定

### 屏显内容

你最近一次用一个 Agent 或 Skill 完成科研动作时，是谁决定了：

- 它能读哪些文件？
- 它能写哪些目录？
- 它什么时候停？
- 失败了怎么办？

> 调用不等于看懂。

本课目标：

1. 用八要素拆解一个现成 Agent/Skill；
2. 判断动作是否需要 Agent；
3. 为自己的真实科研动作设计可审计工作流；
4. 为第 13 课验证门评价做准备。

> 不正式提交；产出是验证门前置状态。

### 视觉结构

左侧四个问题 + 下方四项目标清单，右侧一个空白的"拆解卡"轮廓占主体。不用等宽卡片矩阵。右侧标注"第 13 课验证门"门槛。

### 教师讲述备注

开场放下工具清单。本课不要求你装更多 Skill，而是要求你看懂一个现成 Agent 隐含的设计决定。这些决定如果是别人替你做的，你的研究动作边界就让渡给了一个你未审计的配置。第 10 课写单次任务契约，第 11 课写受限循环，本课把两者升级为完整可审计工作流；第 13 课做评价和失败复盘。

### 互动／操作

请学生举手：最近一次用 Agent 时，是否看过它的权限声明或停止条件？只听回答，不评价。

### 建议时间

0:00-3:00。

### 来源与事实边界

课程定位以 [curriculum.md](../../course/curriculum.md) 第 4-5 条为准；[assignments.md](../../course/assignments.md) 验证门条件；[syllabus.md](../../course/syllabus.md) 第 12 课。

## P02｜八要素把黑箱改写成可审计的设计决定

### 屏显内容

八要素：

任务契约｜Context｜Memory / 状态｜工具与权限｜执行循环｜工件与追踪｜Evals 与人工审核｜失败恢复

> 每项都是设计决定，不是默认配置。

演示对象：[AutoResearch](https://github.com/karpathy/autoresearch) / 课程案例 Skill

- README 声明：……
- 默认权限：……
- 停止条件：……
- 失败处理：……

> 今天要填它的八要素拆解卡。

### 视觉结构

顶部八要素单线排列，节点下方各有一个"拆解时问/设计时问"小标签。下方左侧为 Skill 的 README 截图或重绘仓库树，右侧为空白拆解卡模板。

### 教师讲述备注

这八项从第 1 课贯穿到本课。今天用同一框架做两件事：拆解别人做的 Agent，设计自己的工作流。下面几页用现成 Skill 现场填。教师选一个可在课堂拆解的对象。AutoResearch 适合作为受限循环案例（第 11 课已用）。如果选 MCP server，需在授课前复核当前协议版本。

### 互动／操作

## P03｜任务契约必须把成功与禁止项一起写明

### 屏显内容

任务契约：输入｜输出｜成功标准｜不适用范围

AutoResearch 当前 `program.md` 示例：

- 输入 / 范围：`README.md` + 只读 `prepare.py` + 唯一可改 `train.py`
- 输出：`run.log` + `results.tsv` + 保留实验的 commit
- 成功标准：固定 5 分钟预算内降低 `val_bpb`
- 不适用范围：不得改评价器 / 数据准备，不得新增依赖

> 不写不适用范围，边界就由模型自决。

模糊意图：帮我把相关论文整理一下。

任务契约改写：

- 输入：按证据角色标注的论文清单（≤30 篇，每篇 DOI + PDF）
- 输出：证据地图表，含原文位置
- 成功标准：每条主张可定位到原文页码
- 不适用范围：清单外论文、非中英文、需实验复现的论断

### 视觉结构

上栏模糊意图（灰色），下栏改写后的契约（实色）。左侧拆解卡"任务契约"格填入 AutoResearch 实例，右侧对照"我的工作流"空格。

### 教师讲述备注

先看现成对象的任务契约。AutoResearch 的 `program.md` 同时写了唯一可改文件、固定时间预算、评价指标和禁止项，说明“不适用范围”可以直接进入执行契约。学生常把“研究问题”和“任务输出”混淆。任务契约写的是这次工作流要产出什么，不是研究问题本身。

### 互动／操作

请学生指出 AutoResearch 契约里的两个禁止项，并说出自己工作流的输入和成功标准各一句。

### 建议时间

6:00-8:20。

### 来源与事实边界

AutoResearch [`program.md`](https://github.com/karpathy/autoresearch/blob/master/program.md)（课堂使用前固定 commit）；[handout.md §二·1](./handout.md)。

## P04｜Context 是输入，Memory 必须落到可审计工件

### 屏显内容

Context：当前任务明确提供的材料与状态（不是"能看就看"）

Memory：跨步骤保留的状态（优先可审计工件，而非会话记忆）

> 关掉会话后仍能复原当时状态，才算可审计 Memory。

最小 Context：

- 只给完成当前任务所需的最小材料
- 其余即使可读也不主动提供
- Context 选择记录理由

> 把整个仓库塞进 Context ≠ 信息充分。

### 视觉结构

左侧一个会话气泡轮廓（不可审计），右侧一个工件树 `evidence-map.md` / `experiment-log.md` / `ai-usage-log.md`（可审计）。下方对照两栏：左"全仓 Context"（红色边界），右"最小 Context"（绿色边界）。

### 教师讲述备注

AutoResearch 把状态写在文件和日志里，这是它的优点。会话记忆可作为缓存，但不能是唯一来源。Context 选择本身是研究判断，要记录为什么纳入、为什么排除。Context 过大既增加越权与许可风险，也导致引用错位。

### 互动／操作

请学生判断：你最近一次用 Agent 时，状态主要存在哪？并列出自己工作流应给 Agent 的最小材料清单。

### 建议时间

8:20-10:40。

### 来源与事实边界

[第 1 课讲义 §四](../lesson-01/handout.md)；[starter-template.md](../../course/starter-template.md) AI 使用记录字段；[handout.md §二·2](./handout.md)。

## P05｜工具权限分五档，外部动作必须人工确认

### 屏显内容

五档权限：

- 只读
- 可写
- 可执行
- 需确认
- 禁止

> 评价代码与执行代码必须隔离，Agent 不能改评价以"通过"。

常见权限失败模式：

- 为方便一次性开放全盘读写
- 允许 Agent 自行扩大权限
- 把"能执行 shell"当作"能执行任意 shell"
- 评价代码与执行代码未隔离

### 视觉结构

五档权限条，"禁止"档突出。右下角放一个"评价代码隔离"小图。下方否定清单四条"不做"，配一句正面对照"权限按五档划分，至少一个需确认点"。

### 教师讲述备注

最小权限原则。关键判断（改实验规格、删失败记录、联网发未公开数据、改评价代码）必须人工确认。AutoResearch 默认权限是否含 shell 执行，需在拆解时指出。这是第 1 课和第 2 课已建立的底线，本课在工作流设计中复用。

### 互动／操作

请学生指出自己工作流的"需确认"动作至少一项。

### 建议时间

10:40-13:00。

### 来源与事实边界

[第 1 课讲义 §四·3 最小权限原则](../lesson-01/handout.md)；[第 2 课权限矩阵]；[handout.md §二·4](./handout.md)。

## P06｜执行模式越自主，评价与停止越要独立

### 屏显内容

执行循环：计划→行动→观察→评价→停止

停止条件：任务完成？预算耗尽？人喊停？

> 不是所有任务都需要自主循环。

| 模式 | 适用 |
| --- | --- |
| prompt chaining | 步骤清楚、每步可验收 |
| routing | 输入分类后走不同分支 |
| parallelization | 独立子任务可同时跑 |
| orchestrator-workers | 子任务动态分配 |
| evaluator-optimizer | 有明确评价器可迭代 |
| autonomous agent | 步骤不可预定、需观察后决策 |

### 视觉结构

顶部单线循环图，"停止"节点旁标注三种触发条件。下方六行模式表，每行配一个极简结构图标。不展开每模式的实现细节。

### 教师讲述备注

AutoResearch 是受限循环：固定指标、固定预算、固定保留/丢弃。本质更接近 evaluator-optimizer，而非完全自主 Agent。理解这一点有助于判断自己的动作是否需要自主性。选用时先看可控性和可审计性，再看能力。

### 互动／操作

请学生判断自己的科研动作需要固定链还是自主循环，并把自己的工作流对号入座。

### 建议时间

13:00-15:20。

### 来源与事实边界

[第 11 课 AutoResearch 循环](../lesson-11/handout.md)；Anthropic, [*Building Effective Agents*](https://www.anthropic.com/engineering/building-effective-agents)。六种模式标注为工程博客，非学术论文。

## P09｜先判断动作是否值得交给 Agent

### 屏显内容

四个动作：

1. 下载 100 篇已知 DOI 的 PDF
2. 为每篇生成阅读卡并核验原文
3. 调试一个未知训练失败
4. 自动探索超参组合并保留所有结果

哪些需要 Agent？

### 视觉结构

四栏情境，每栏下方留空让学生判断。

### 教师讲述备注

1 是确定性脚本；2 是固定链；3 可能需要单 Agent；4 是受限循环（第 11 课）。先让学生判断，再揭晓。

### 互动／操作

请学生举手判断每个动作适合哪一类。

## P10｜脚本、工作流、Agent 与复杂系统各有边界

### 屏显内容

| --- | --- | --- |
| 确定性脚本 | 步骤清楚、无模型判断 | 错误时全链失败 |

## P13｜可审计工作流要让评价代码与执行代码隔离

### 屏显内容

可审计工作流必须：

1. 一次运行留下可复核 trace
2. AI 生成主张能回到原文/数据/实验 ID
3. 评价代码与执行代码隔离
4. 失败和越权被保留
5. 工件进入项目，第 13 课可统一检查

评价代码隔离：

- Agent 可写执行代码
- 评价代码只读、需确认
- 评价协议运行期间不可改

> Agent 改评价以"通过" = 评价失效。

### 视觉结构

### 教师讲述备注

这五条对应验证门条件，学生在设计时就应嵌入。这是第 11 课"避免评价协议漂移"在工作流设计中的落实。学生应在模板里明确评价代码的只读/需确认档。

## P14｜虚构案例：每周证据地图更新的完整契约

### 屏显内容

课程虚构教学案例｜不预设真实效果

动作：把本周新增论文整理进证据地图

- 输入：本周清单（≤10 篇，DOI + PDF）

### 教师讲述备注

这是课程虚构案例，不预设结论。它演示从动作到契约的填充结果。注意"需确认写回 evidence-map"——正式工件写入必须人工确认。"禁止联网"防止 Agent 自行补充清单外文献。
