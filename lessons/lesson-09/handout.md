# 第九讲｜Baseline、实验规格、可复现性与判断门

## 导读

第 7 课你把第 6 课的可证伪命题扩成了机制假设列表、研究判断记录初版和实验规格草图；第 8 课你用 3 分钟向固定同伴组陈述了问题、关键证据、机制假设、最小验证和最大风险，并拿到了一份结构化反馈。"能跑通"和"能复现"之间的距离，恰好就是判断门要检查的距离。

本课对应八阶段研究链路的阶段六"研究判断"成案与阶段七"原型验证"起始，是"假设、研究判断与方案分享"模块的末课，也是全课第二次正式提交——判断门。它的核心转换是：

> 从"我有一个实验设计草图"转向"我有一个可复现的 baseline、一份完整的实验规格和一份能让别人重新跑起来的复现说明"，从"我倾向于这样做"转向"判断已落档、风险已识别、同伴反馈已处理"。

完成本课后，你将提交判断门材料包：一个可执行 baseline、一份完整实验规格、一份复现说明、至少 2 条研究判断、第 8 课同伴反馈处理记录、当前最大风险与失败预案，以及从轻量脚手架迁移到完整项目模板的当前版本。第 10 课将在这些材料上展开受限 Agent 执行。

## 学习目标

完成本讲后，你应该能够：

1. 选择一个可解释、公平且能在课程周期内运行的 baseline，并说明它为什么是公平对照；
2. 把第 7 课的实验规格草图补全为包含假设对应、变量、步骤、度量标准、对照和停止条件的完整规格；
3. 记录使实验可复现的最小集合：环境、配置、随机种子、数据来源与使用限制、代码位置与运行命令；
4. 处理机器学习实验中方差来源，避免把单次运行的差异写成结论；
5. 把第 8 课同伴反馈逐条归档为采纳/拒绝/暂缓并记录理由；
6. 从 `starter-template.md` 迁移到 `project-template.md`，且不丢失 AI 使用记录和伦理说明；
7. 对照判断门条件完成提交前自查。

## 二、Baseline 选择与公平性

### 1. 什么是 baseline

baseline 不是"任意一个对比组"，而是用来回答"我观察到的方法效应是否真的来自我假设的机制"的公平参照。一个 baseline 公平，当且仅当：

- 控制变量真正一致（同模型、同数据、同解码参数、同评价协议）；
- 混杂变量被识别并尽可能消除；
- baseline 的失败不会被归结为"它本身就坏"——它必须在公平条件下被认真运行。

如果 baseline 不公平，"我的方法有效"的结论无法成立——任何差异都可能来自未控制的变量，而非你的干预。

> 来源参考：Pineau, J. et al. "Improving Reproducibility in Machine Learning Research." *Journal of Machine Learning Research* 22(164), 1–20 (2021). [JMLR 正式页面](https://www.jmlr.org/papers/v22/20-303.html)。用途：把 ML reproducibility checklist 转化为 baseline、超参、数据和超参选择的报告要求（见 [reading-list.md](../../course/reading-list.md) 第 9 课）。

### 2. 三类常见 baseline

在 CS/AI 与科研方法项目中，常见三类 baseline，选哪一类取决于你的研究问题：

| 类型 | 含义 | 适用 | 贯穿案例示例 |
| --- | --- | --- | --- |
| 朴素 baseline | 不使用任何目标机制的简单方法 | 检验"目标机制是否真的必要" | 自由摘要：直接让模型生成摘要，不强制阅读卡结构 |
| 强 baseline | 已公开、可比的现成方法 | 检验"目标方法是否在公平条件下更好" | 已公开的"提示词工程摘要"方法（如 few-shot 摘要），固定 prompt 与解码参数 |
| 自身消融 baseline | 你的方法去掉某关键模块 | 检验"哪个模块是效应来源" | 阅读卡去掉"原文位置"字段，保留其他字段 |

判断门只要求"一个可执行 baseline 或最小验证原型"。但在判断门材料中必须说明这个 baseline 为什么是公平的——也就是说，如果你只有一个朴素 baseline，要写清楚为什么强 baseline 暂不在范围（如第 8 课同伴反馈指出"强 baseline 需要外部数据集，超出周期"）。

### 3. 公平性检查清单

对每个 baseline，至少回答：

1. baseline 与实验组是否使用同一批数据 / 论文 / 任务实例？
2. 模型、解码参数（温度、最大长度、top-p）、随机种子是否一致？
3. 评价协议是否一致（同一 rubric、同一批标注者、同一计算口径）？
4. baseline 是否被认真运行（运行次数、停止条件与实验组相同）？
5. baseline 的失败是否被记录而不是被删除？

> 来源参考：Bouthillier, X. et al. "Accounting for Variance in Machine Learning Benchmarks." *Proceedings of Machine Learning and Systems* 3 (2021). [MLSys 正式页面](https://proceedings.mlsys.org/paper_files/paper/2021/hash/0184b0cd3cfb185989f858a1d9f5c1eb-Abstract.html)。用途：识别随机性、数据划分、超参选择和种子对结果的方差贡献，避免把单次运行的差异写成结论。

### 4. baseline 不公平的典型反例

- **数据不一致**：实验组用 A 集，baseline 用 B 集，差异可能来自数据难度。
- **超参不对等**：baseline 没有调参，实验组做了超参搜索——这是"调参 vs 不调参"的差异，不是机制差异。
- **评价不一致**：实验组用盲评，baseline 用非盲评；或实验组用 rubric v2，baseline 用 rubric v1。
- **运行次数不对等**：实验组跑 5 次取均值，baseline 只跑 1 次。
- **失败被静默删除**：baseline 因协议错误跑不通，只保留实验组的成功结果。

> 来源参考：ACM. *Artifact Review and Badging, Version 1.1* (2020). [官方页面](https://www.acm.org/publications/policies/artifact-review-and-badging-current)。用途：区分"代码可下载""工件可运行"和"结果得到独立验证"——判断门要求 baseline 可执行，结果可追溯，但不要求通过 ACM 完整 badges。

## 三、实验规格完善

实验规格不等于"代码能跑"。它回答：验证哪个假设、怎么验证、什么是公平对照、什么结果支持或推翻、什么时候停。第 7 课已建立"假设—指标—实验—可能结论"映射和变量清单草案，本课把它补全为判断门可检查的完整规格。

### 1. 七字段规格

判断门条件之五要求实验规格完整，包括假设对应、变量、步骤、度量标准、对照和停止条件。本课要求把它写成一张七字段表：

| 字段 | 内容 | 贯穿案例样例 |
| --- | --- | --- |
| 假设对应 | 验证 H1 还是 A1/A2/A3 | H1：字段约束 → 生成时强制标注 → 错读更易暴露 |
| 变量 | 自变量 / 因变量 / 控制变量 / 混杂变量 | 自：是否使用阅读卡；因：限定条件遗漏率；控：模型、温度、最大长度、论文集；混：论文结构差异、标注者训练 |
| 步骤 | 从准备到运行到标注到统计的顺序，每步谁执行、谁审核 | 1) 抽 20 篇 CS 论文；2) 随机分两组；3) 阅读卡组与自由摘要组分别生成；4) 标注者盲评；5) 计算遗漏率与一致性 |
| 度量标准 | 指标操作定义、计算口径、标注协议、标注者一致性指标 | 限定条件字段缺失率 = 缺失字段数 / 应有限定条件字段数；Cohen's kappa ≥ 0.7 |
| 对照 | baseline 是什么、为什么公平、控制变量清单 | 朴素 baseline = 自由摘要；公平性：同模型、同论文集、同温度、同评价 rubric、同运行次数 |
| 随机化与重复 | 是否需要随机分配或重复运行；若需要，种子、重复计划与汇总方式如何记录；若不需要，哪些等价复现条件可追溯 | 教学样例选择 20 篇论文并记录分组种子；为了声称方差，预先规定 3 个种子。这是样例设计，不是全班普适门槛 |
| 停止条件 | 跑多少次、何时停、什么条件下提前停 | 主比较：5 次运行 × 2 组 = 10 次实验；提前停条件：发现标注协议错误或数据污染 |

### 2. 停止条件为什么容易被忽略

最常见的隐性偏倚是"跑到出现显著结果为止"。如果不预先写明运行次数和停止规则，研究者会在结果有利时停、不利时继续跑，最终把噪声差异写成方法效应。停止条件就是预先承诺：跑到第几次就停，提前停只在协议错误或数据污染时触发，不在结果不利时触发。

> 来源参考：Wilson, G. et al. "Good Enough Practices in Scientific Computing." *PLOS Computational Biology* 13(6):e1005510 (2017). DOI: [10.1371/journal.pcbi.1005510](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1005510)。用途：建立项目组织、数据管理、版本记录、脚本和协作的最低可靠实践（见 [reading-list.md](../../course/reading-list.md) 第 9 课）。

### 3. 度量标准与标注协议

度量标准不是"用什么指标"，而是"这个指标怎么算出来"。判断门条件之二要求"数据、材料、评价指标和使用限制说明"。一个度量至少要写明：

- **操作定义**：从原始数据到指标数字的公式或步骤；
- **计算口径**：分母是什么、分子是什么、缺失值如何处理；
- **标注协议**：标注者人数、标注者训练、盲评与否、双标注如何解决分歧；
- **一致性指标**：标注者间一致性（如 Cohen's kappa 或 Krippendorff's alpha）；若未计算，写明为什么（如样本量不足），并标记为待验证项。

### 4. 失败预案

失败预案是判断门条件之七“当前最大风险和失败预案”的直接来源。先选当前最大风险，为它写一条完整、可执行的预案，至少回答：触发条件是什么、采取什么动作、写入哪里、会怎样改变当前主张或项目范围。

可从下列情形中选择与本人最大风险相符的一项，也可以写其他风险；课程不要求同时覆盖所有类型：

- baseline 跑不通（如换用更小样本、回退到朴素 baseline）；
- 结果不支持假设（如检查是否 A1/A2/A3 替代假设被触发，记录为待验证项而非删除）；
- 数据不可用（如换用公开替代数据，并在判断门材料中说明限制）；
- 标注者一致性过低（如增加训练、修订 rubric、降级为弱结论）。

### 5. 与 Agent / 自动化的关系

如果实验流程使用 Agent 或自动化循环（第 10-12 课系统展开），实验规格还需写明：

- 允许 Agent 访问哪些文件、数据与网络资源；
- 允许写入和执行什么；
- 哪些动作必须人工确认；
- 是否允许修改评价代码或标注协议；
- 失败日志是否保留；
- 工作流何时停止（沿用第 1 课 §2.7 与第 7 课 §四·4）。

本课不要求把这些写全，但要求在实验规格中标出"哪些步骤拟用 Agent、哪些步骤必须人工"，作为第 10 课受限 Agent 执行的输入。

## 四、可复现性：环境、随机种子、数据与代码

可复现性不是"代码能跑"，而是"另一位研究者在另一台机器上能重新跑出可比的结果"。判断门条件之三要求"环境、配置、随机种子或等价复现条件"。

### 1. 可复现的最小集合

> 来源参考：Sandve, G. K. et al. "Ten Simple Rules for Reproducible Computational Research." *PLOS Computational Biology* 9(10):e1003285 (2013). DOI: [10.1371/journal.pcbi.1003285](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1003285)。用途：建立结果—脚本—参数—输入—随机种子的可执行追踪链。该文是第 11 课核心阅读，本课借用其最小追踪链概念。

最小复现集合包括：

| 类别 | 字段 | 贯穿案例样例 |
| --- | --- | --- |
| 环境 | 操作系统、Python/PyTorch 版本、关键库版本 | Python 3.10, transformers 4.40.0, anthropic SDK 0.34.0 |
| 配置 | 模型名、解码参数、prompt 模板、rubric 版本 | model=claude-3-5-sonnet-20241022, temperature=0, max_tokens=1024, rubric v1.2 |
| 随机种子 | 数据划分种子、运行种子、采样种子 | split_seed=42, run_seeds=[100,200,300] |
| 数据 | 数据来源、版本、划分方式、使用限制 | 20 篇 CS 论文来自 ACL Anthology 2024-05 快照；仅用于课程项目，不二次分发 |
| 代码 | 仓库位置、commit、运行命令、入口脚本 | github.com/.../project, commit abc123, `python src/run_baseline.py --config configs/exp01.yaml` |
| 结果 | 实验日志位置、原始输出、聚合结果 | `experiments/exp01/log.jsonl`, `experiments/exp01/results.csv` |

### 2. 随机种子与方差报告

机器学习实验中，随机性来自多个层面：数据划分、模型初始化、采样、解码。Bouthillier et al. (2021) 指出，单次运行的差异往往大于方法间的差异——如果只跑一次，你可能把种子噪声写成方法效应。

判断门要求随机性或等价复现条件可追溯，具体方案由主张决定：

- 存在随机源时，记录所有已使用随机种子的来源和值；没有随机源时写明确定性或其他等价复现条件；
- 要声称方差、稳定性或稳健性时，预先设计足以估计相应不确定性的重复计划和汇总方式；
- 如果只跑一次，必须写明边界（如时间约束），并把观察标记为待验证，不能写成稳定方法效应。

课程不设统一“至少 3 次”硬门。可核验的最小实跑对象见[可核验复现工件](./assets/reproducibility-example/README.md)：它用合成输入、实际 `config.json`、`run.py`、`results.json` 和 `run-log.jsonl` 演示确定性等价复现；它不是实证研究结果。

> 这与 assessment.md "实验设计与可复现性"维度的要求一致："实验配置、随机种子、环境依赖和运行命令记录完整"和"能说明威胁有效性和可能的混杂因素"。

### 3. 数据使用限制与许可

判断门条件之二要求"数据、材料、评价指标和使用限制说明"。数据部分至少回答：

- 数据来源（公开数据集 / 自采 / 课程提供）；
- 许可证或使用限制（如 ACL Anthology 论文是否允许二次分发）；
- 是否含隐私或敏感内容；
- 是否上传到外部模型（沿用第 2 课伦理检查）；
- 如果使用 API（如大模型），是否记录了 API 提供方、版本、调用日期。

把论文全文发送到外部 API 时，确认你拥有相应权限；课程默认不向外部模型发送未公开论文、学生作业或敏感数据（沿用 [starter-template.md](../../course/starter-template.md) §7-8 与 [reading-list.md](../../course/reading-list.md) §二）。

### 4. 工件状态与 ACM Badging 视角

判断门要求 baseline 可执行、结果可追溯，但不要求通过 ACM 完整 badges。可以用 ACM Artifact Review and Badging 的三个最低档作为自查视角：

- **documented**：基本运行说明存在；
- **consistent**：说明中的步骤与代码实际行为一致；
- **exercisable**：工件能被独立运行，不只是"在我机器上能跑"。

判断门对应这三档：documented 由实验规格覆盖；consistent 由复现说明与代码一致覆盖；exercisable 由 baseline 可执行覆盖。更高档（complete、results validated、available）是验证门和论证门的目标，本课不要求。

承接第 7 课贯穿案例。第 7 课产出：机制假设列表（H1 主假设 + A1/A2/A3 替代假设）+ 研究判断记录 J1（采用限定条件遗漏率而非通用语言质量评分）+ 实验规格草图（变量清单草案）。第 8 课产出：3 分钟陈述 + 同伴反馈（含"建议增加强 baseline""建议报告方差""质疑样本量过小"等）。

本课动作链：

**第一步：选择 baseline（§二）**

朴素 baseline = 自由摘要（不强制阅读卡结构）。理由：回答 H1"字段约束是否必要"，朴素 baseline 直接检验"没有字段约束会怎样"。强 baseline（few-shot 摘要）暂不在范围——第 8 课同伴反馈指出需要外部 prompt 数据集，超出课程周期。

**第二步：补全实验规格七字段（§三·1）**

H1 对应；变量四类如 §三·1 样例；步骤含 5 步（抽 20 篇 → 随机分两组 → 生成 → 盲评 → 计算）；度量标准含操作定义与 kappa；对照为朴素 baseline；随机化含 split_seed=42 与 run_seeds=[100,200,300]；停止条件为 5 次×2 组=10 次实验或发现协议错误。

**第三步：补全可复现说明（§四）**

环境：Python 3.10, anthropic SDK 0.34.0；配置：model=claude-3-5-sonnet-20241022, temperature=0, rubric v1.2；种子：split_seed=42, run_seeds=[100,200,300]；数据：20 篇 ACL Anthology 2024-05 快照，仅课程使用，不二次分发；代码：commit abc123, `python src/run_baseline.py --config configs/exp01.yaml`；结果：`experiments/exp01/log.jsonl`。

**第四步：补写第二条研究判断（§五与第 7 课 §三）**

J2：baseline 选择朴素而非强 baseline。取舍理由：第 8 课同伴反馈指出强 baseline 需外部数据集，超出周期；朴素 baseline 已能检验 H1"字段约束是否必要"。适用边界：结论只能支持"字段约束相比无约束更好"，不能支持"阅读卡优于其他结构化方法"。依据：第 8 课同伴反馈记录 + 第一性原理"主张必须能定位原文"。待验证状态：强 baseline 留作后续工作。

**第五步：处理第 8 课同伴反馈（§六·2 之 6）**

逐条归档：

- 反馈"增加强 baseline"——拒绝（J2 已记录理由，超出周期）；
- 反馈"报告方差"——采纳（实验规格已含 3 次运行与标准差）；
- 反馈"样本量过小"——暂缓（标记为待验证项，结论将标记为"小样本下的初步证据"）。

**第六步：写最大风险与失败预案（§三·4）**

最大风险：20 篇样本可能不足以支持稳定结论。失败预案：若 kappa < 0.7，增加标注者训练并修订 rubric；若 baseline 跑不通，回退到只用主假设行的最小验证；若结果不支持 H1，检查是否触发 A1/A2/A3 并记录为待验证项。

## 八、常见错误

1. **baseline 不公平**：对照组与实验组在模型、数据、温度、运行次数上不一致。结论无法成立。
2. **只跑一次就作稳定性结论**：把单次运行的差异写成稳定方法效应。应根据主张强度预先说明足够的重复或等价复现计划，并报告相称的不确定性；课程不设统一次数硬门。
3. **无停止条件**：跑到出现显著结果为止，构成隐性 p-hacking。应预先写明运行次数与停止规则。
4. **度量无操作定义**：只写"用遗漏率"，不写分子分母与缺失值处理。应补全计算口径。
5. **复现说明缺种子**：环境记录了，但随机种子丢失。应记录所有种子来源与值。
6. **数据使用限制未写**：未说明数据许可证与是否上传外部 API。应补全数据使用限制。
7. **同伴反馈未归档**：第 8 课拿了反馈但没处理记录。应逐条归档为采纳/拒绝/暂缓。
8. **迁移丢失 AI 使用记录**：搬到 project-template 时漏掉了第 1-8 课的 AI 使用条目。应按迁移对照表逐项核对。
9. **第二条研究判断不完整**：只有一条研究判断，或第二条缺适用边界。应补全六字段。
10. **把"代码能跑"当可复现**：能跑不等于别人能复现。应对照 ACM Badging 三档自查。
11. **最大风险写成"时间不够"**：不具体。应写具体风险（如样本量不足、kappa 可能过低）。
12. **失败预案与最大风险脱节**：只写泛化的“如果跑不通就缩小范围”，但没有触发条件、动作与记录位置。应先为当前最大风险写一条可执行预案；baseline 跑不通、结果不支持、数据不可用只是可选例库，不是必须同时覆盖的三类硬门。

## 九、课堂练习

### 练习 1：baseline 类型判断

下面三个候选 baseline，判断各属朴素/强/消融，并说明为什么公平或不公平：

1. 用 GPT-4 生成摘要 vs. 用 Llama-3 生成摘要。
2. 阅读卡摘要 vs. 自由摘要，同模型同论文同温度。
3. 阅读卡摘要 vs. 去掉"原文位置"字段的阅读卡摘要。

参考判断：1 在模型层面不公平；2 是朴素 baseline，公平；3 是消融 baseline。

### 练习 2：补全七字段实验规格

用你第 7 课的实验规格草图，补全七字段表。重点检查：停止条件是否预先写明？随机化是否记录种子？度量是否有操作定义？

### 练习 3：写复现说明

为你的 baseline 写一份复现说明，至少包含环境、配置、种子、数据、代码、结果六类字段。检查所有随机种子是否记录。

### 练习 4：写第二条研究判断

在第 7 课 J1 基础上，写第二条研究判断（六字段）。建议主题：baseline 选择、度量选择或样本量决定。

### 练习 5：处理第 8 课同伴反馈

把第 8 课拿到的同伴反馈逐条归档为采纳/拒绝/暂缓，每条写明理由。被拒绝的反馈要写拒绝依据，不能只写"不同意"。

### 练习 6：方差距察

让你的 baseline 与实验组各运行 3 次（不同种子），报告均值与标准差。如果均值差异小于标准差，你会如何写结论？标记为待验证还是稳定结论？

### 练习 7：模板迁移核对

对照 §五·2 迁移对照表，把 starter-template 中的字段搬到 project-template 对应位置。检查 AI 使用记录条目数是否 ≥ 第 1-8 课总和，伦理说明是否补了数据使用限制。

### 练习 8：判断门材料自查

对照 §六·2 的 8 项门条件，逐项自查当前项目版本。标注已满足、待补全和未满足的条目，并写出未满足条目的修复计划。

## 十、术语表

| 术语 | 本课程中的含义 |
| --- | --- |
| baseline | 用来回答"方法效应是否真的来自假设机制"的公平参照；控制变量须一致，混杂变量须被识别 |
| 朴素 baseline | 不使用任何目标机制的简单方法，检验目标机制是否必要 |
| 强 baseline | 已公开、可比的现成方法，检验目标方法在公平条件下是否更好 |
| 消融 baseline | 你的方法去掉某关键模块，检验哪个模块是效应来源 |
| 公平性 | baseline 与实验组在控制变量上真正一致，混杂变量被识别并尽可能消除 |
| 控制变量 | 必须保持一致以使比较公平的变量 |
| 混杂变量 | 可能影响结果但未被控制的变量 |
| 实验规格 | 回答验证哪个假设、怎么验证、什么是公平对照、什么结果支持或推翻、什么时候停的完整规格 |
| 七字段规格 | 假设对应、变量、步骤、度量标准、对照、随机化与重复、停止条件 |
| 停止条件 | 预先写明的运行次数与停止规则，防止"跑到显著为止"的隐性偏倚 |
| 失败预案 | 针对当前最大风险，预先写明触发条件、回退动作、记录位置及其对主张或范围的影响 |
| 可复现性 | 另一位研究者在另一台机器上能重新跑出可比的结果 |
| 随机种子 | 决定数据划分、模型初始化、采样、解码等随机过程的种子值 |
| 方差报告 | 对关键比较多次运行并报告均值与标准差，避免把种子噪声写成方法效应 |
| 工件状态 | draft → review → approved → stable，追踪成熟度与门检查结果 |
| 判断门 | 第 9 课后的第二次正式提交，检查 baseline 可执行、实验规格完整、复现说明充分、研究判断成案、同伴反馈处理、风险与失败预案、模板迁移 |
| ACM Badging | ACM 工件评审徽章体系；本课只用 documented/consistent/exercisable 三档作自查视角 |
| 同伴反馈处理 | 第 8 课反馈逐条归档为采纳/拒绝/暂缓并写明理由 |

正式书目（见 [reading-list.md](../../course/reading-list.md) 第 9 课）：

1. Wilson, G. et al. "Good Enough Practices in Scientific Computing." *PLOS Computational Biology* 13(6):e1005510 (2017). DOI: [10.1371/journal.pcbi.1005510](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1005510)。用途：建立项目组织、数据管理、版本记录、脚本和协作的最低可靠实践。核心阅读，约 25 分钟。
2. Pineau, J. et al. "Improving Reproducibility in Machine Learning Research." *Journal of Machine Learning Research* 22(164), 1–20 (2021). [JMLR 正式页面](https://www.jmlr.org/papers/v22/20-303.html)。用途：将 ML reproducibility checklist 转化为 baseline、环境和实验报告要求。任选，约 25 分钟。
3. ACM. [*Artifact Review and Badging, Version 1.1*](https://www.acm.org/publications/policies/artifact-review-and-badging-current) (2020)。选读 documented、consistent、complete、exercisable、available 和 results validated 的定义。用途：区分"代码可下载""工件可运行"和"结果得到独立验证"。任选，约 15 分钟。
4. Bouthillier, X. et al. "Accounting for Variance in Machine Learning Benchmarks." *Proceedings of Machine Learning and Systems* 3 (2021). [MLSys 正式页面](https://proceedings.mlsys.org/paper_files/paper/2021/hash/0184b0cd3cfb185989f858a1d9f5c1eb-Abstract.html)。用途：检查随机性、方差来源和不公平 benchmark 比较。任选，约 20 分钟。

课后阅读采用"AI 导航 → 原文核验 → AI 质疑 → 偏差审计 → 人工定稿"流程。本课核心阅读为 Wilson et al. 2017，约 25 分钟。精读卡持续保存在个人项目 `notes/`，不逐周正式提交，判断门统一检查实验规格与复现说明。
