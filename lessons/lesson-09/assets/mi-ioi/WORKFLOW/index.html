    IOI 研究 Agent 任务与评价¶

    输入与授权¶

    向当前已经接入模型的 Agent 提供公开问题、IOI 文献与开发运行记录，允许读取本包、运行 run.py、在自己的 policy 文件和研究笔记中写入。协议、评价实现和原始结果保持只读。默认不向 Agent 提供 heldout 结果。

    可直接使用的任务：

    判断当前层／位置的干预结果是否足以支持“干预恢复了答案偏好”。检查逐模板结果与 noop、random 对照，提出一个可区分的解释和下一项实验。只修改本人 policy 文件；每轮最多两项候选，总计最多三轮。运行开发实验，保留失败和成本。每轮根据结果决定继续、调整或停止，并说明依据。最终提交一个冻结策略及允许写出的结论，不读取 heldout 结果。

    这是研究任务说明，不绑定某个平台或 API。保留实际 Agent 身份、输入上下文、决策输出、运行命令、diff 和结果位置。外部消息、发布或传送非公开材料不在授权内。

    基线与改进¶

    先保存本人原有 AI 用法和一次实际运行。可以是固定提示的结果解释与下一实验建议，也可以是已经使用的 Agent 流程，不能故意减弱它。改进必须针对实测缺口，如忽略 noop、只按总均值选择、重复失败实验或没有成本停止条件。

    两种工作方式使用相同公开材料、模型、工具、每轮至多两项候选和三轮上限；分别记录实际消耗，不把上限相同写成消耗完全相同。固定提示基线也可以得到完整开发反馈，只是改进规则不跨轮更新。若已有流程已能有效解决问题，允许无改善结论。

    评价包括：关键主张能否反查、对照检查是否完整、最终实验策略在保留模板的行为、工具调用／前向次数与时间、失败与越界尝试。科学 patch 效果不能独自证明 Agent 工作方式更好；没有独立重复时，只报告本次运行的探索性比较。

    三个改进层次¶

    • 任务纠错：本次报告补上漏掉的对照。
    • 工作流改进：后续每次分析都检查对照，再选择实验。
    • 递归改进：产生下一轮实验的改进规则也由系统修改，新规则实际用于后续轮次，并与固定规则作可比评价。

    保留旧规则、新规则、触发证据和实际后续行为。单纯重试或固定规则下扫描参数不能标为 RSI。课堂深入实验选做；教师演示同样遵守预算和证据分离，不声称无限加速或跨任务普遍提升。
