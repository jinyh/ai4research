# 第 9 课教师教案｜Baseline、实验规格、可复现性与判断门

## 一、本课定位

- 学时：2 学时，90 分钟
- 研究链路：阶段六"研究判断成案"+ 阶段七"原型验证起始"
- 教学类型：讲授 + 教师演示 + 个人实践 + 同伴互查
- 核心问题：如何把实验规格草图变成可复现的 baseline 和判断门可检查的材料？
- 课堂产出：判断门材料初版（experiment-spec.md 七字段 + 可复现说明 + 第二条研究判断 + 同伴反馈处理 + 失败预案）
- 正式提交：**判断门材料包**（第 9 课后）

本课必须建立三项共识：

1. baseline 不是任意对比组，而是公平参照；控制变量一致和混杂变量被识别是公平性的底线。
2. 可复现不是"代码能跑"，而是"另一位研究者在另一台机器上能重新跑出可比结果"——环境、配置、种子、数据、代码、结果六类必须齐全。
3. 判断门检查的是当前项目版本是否满足 8 项条件，不是重新制作材料；第 1-8 课所有产出都已回写同一项目。

本课是全课第二次正式提交节点。第 10 课将在这些材料上展开受限 Agent 执行——实验规格中"哪些步骤拟用 Agent、哪些步骤必须人工"将成为第 10 课的直接输入。

## 二、学习目标

完成本课后，学生能够：

1. 选择一个可解释、公平且能在课程周期内运行的 baseline，并说明它为什么是公平对照；
2. 把第 7 课的实验规格草图补全为包含假设对应、变量、步骤、度量标准、对照和停止条件的完整规格；
3. 记录使实验可复现的最小集合：环境、配置、随机种子、数据来源与使用限制、代码位置与运行命令；
4. 处理机器学习实验中方差来源，避免把单次运行的差异写成结论；
5. 把第 8 课同伴反馈逐条归档为采纳/拒绝/暂缓并记录理由；
6. 从 starter-template.md 迁移到 project-template.md，且不丢失 AI 使用记录和伦理说明；
7. 对照判断门条件完成提交前自查。

### 安全与资源口径

- 不要求学生自费购买 API token；复现说明可在纸面或 Markdown 模板中完成。
- 不向外部模型发送未公开论文、敏感数据或学生私人材料（沿用第 2 课伦理检查）。
- baseline 运行如使用大模型 API，记录 API 提供方、版本、调用日期；调用费用由学生自控，不构成评分项。
- 判断门材料提交指向当前项目版本，不重复制作汇报文档。

## 六、教师演示脚本

### 演示前状态

- 演示项目只含公开或贯穿案例内容；
- 投屏前确认终端不显示凭据；
- 准备第 7 课贯穿案例的实验规格草图（七字段草案）；
- 准备 experiment-spec.md 完整版样例（七字段填满 + 复现说明）；
- 准备"不可复现实验"反例（缺种子、单次运行、baseline 不公平）；
- 准备判断门条件自查清单（8 项，可投屏）；
- 准备 starter-template → project-template 迁移对照表。

### 演示步骤

1. **baseline 选择与公平性（0-20 分钟段，P04-P07）**：展示贯穿案例的三个候选 baseline（朴素自由摘要、强 few-shot、消融"去原文位置字段"），说明为什么选朴素 baseline（回答 H1"字段约束是否必要"），强 baseline 因第 8 课同伴反馈指出超出周期而暂不在范围。审计一个"不可复现实验"反例：缺种子、单次运行、baseline 用不同温度，让学生指出不公平点。

2. **实验规格七字段补全（20-40 分钟段，P08-P10）**：在第 7 课草图基础上补全七字段表。以下数值均为虚构教学规格，不是课程普适阈值：停止条件（5 次×2 组=10 次或发现协议错误提前停）、随机化（split_seed=42, run_seeds=[100,200,300]）、度量操作定义（限定条件字段缺失率 = 缺失字段数 / 应有限定条件字段数；Cohen's kappa ≥ 0.7）。失败预案只要求先对准当前最大风险写一条可执行路径；kappa 偏低、baseline 跑不通、结果不支持 H1 仅作例库。

3. **可复现说明（20-36 分钟段尾，P11-P13）**：先用明确标为虚构教学规格的六类字段演示填写，再打开真实可运行课次工件 `assets/reproducibility-example/`，运行 `python3 assets/reproducibility-example/run.py --verify`，核对 `experiment-spec.md`、`config.json`、合成输入、`results.json` 与 `run-log.jsonl` 的追踪链。强调：存在随机性时须记录种子；没有相应随机源时写等价复现条件，不把示例 seed 或重复次数当普适硬门；实跑教学工件不是实证研究结论。

4. **模板迁移、门条件速览、同伴反馈处理与第二条研究判断（36-40 分钟段，P14-P16）**：快速展示 starter→project 迁移对照表与新增字段（P14），用 P15 八项清单标出本课补全范围，再用 P16 演示一条反馈处理和 J2 写法。完整的逐项迁移、反馈归档与判断撰写留给 40-60 分钟学生在自己的项目中完成，教师不在此段替学生代填。

5. **判断门材料自查（37:20-38:40，P15）**：只作 80 秒权威条件速览，不逐条讲授。学生先标出“已满足/待补全”；完整自查在持续实践中进行。强调条件以 `assignments.md` Checkpoint 2 为准。

6. **个人补全持续实践（40-60 分钟段，P17-P18）**：40:00-42:00 说明任务；42:00-60:00 学生持续独立补全 `experiment-spec.md` 七字段、复现说明、J2、同伴反馈处理与最大风险预案，P17/P18 持续投屏。课堂最低产出是这些材料的可复盘初版，模板迁移和八项门条件在课堂内启动、课后完成。

### 演示判断点

1. baseline 公平与不公平的区别是什么？
2. 为什么要预先写停止条件，而不是"跑到出现显著结果"？
3. 可复现的最小集合是什么？为什么缺种子等于不可复现？
4. 同伴反馈被拒绝时应该怎么记录？
5. 从 starter-template 迁移到 project-template 时，AI 使用记录和伦理说明应该怎么处理？

### 失败演示

可预先准备两个反例：

- **反例一：不可复现实验**。展示一个写着"用 GPT-4 生成摘要，效果好"的实验记录，让学生指出缺什么——模型版本、温度、种子、数据来源、运行次数、评价协议。改写为可复现版本。

- **反例二：baseline 不公平**。展示一个 baseline 用不同温度、不同数据集的"实验组 vs 对照组"，让学生指出不公平点。改写为公平版本。

失败不重跑到成功。让学生指出问题，再改写为受限版本。

## 八、讲后复盘

教师课后记录：

- 学生是否仍把 baseline 当作任意对比组？
- 停止条件是否真正预先写明，还是事后补的？
- 复现说明是否齐到种子？还是只记了环境？
- 同伴反馈是否被逐条处理，还是只写"已收到"？
- 模板迁移是否丢失了 AI 使用记录或伦理说明？
- 判断门 8 项条件中，哪一项学生最容易不满足？
- 第 10 课需要在受限 Agent 执行中重点补哪个环节？实验规格中"哪些步骤拟用 Agent、哪些步骤必须人工"是否被填写？
