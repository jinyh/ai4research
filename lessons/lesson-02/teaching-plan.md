# 第 2 课教师教案｜科研伦理、Agent 权限、研究工件与追踪

## 一、本课定位

- 学时：2 学时，90 分钟
- 研究链路：全链路约束
- 教学类型：案例判断 + 方法讲授 + OpenCode 演示 + 个人实践 + 同伴互查
- 核心问题：如何把科研伦理原则转成 Agent 可执行、研究者可检查的边界？
- 课堂产出：权限矩阵、五字段风险卡、轻量工件追踪表、更新后的 AI 使用记录
- 正式提交：无

本课不把伦理讲成法规条文清单，而建立三层关系：

1. 价值和规范说明哪些研究质量不能牺牲；
2. 风险卡和权限矩阵把原则翻译成具体动作边界；
3. 工件状态、人工确认和日志保存责任链。

## 二、学习目标

学生完成本课后能够：

1. 从数据、证据、署名、版权、隐私、保密和双重用途等维度识别风险；
2. 对一项 AI 辅助科研动作作出“允许／有条件允许／禁止”的判断，并用五字段风险卡说明理由；
3. 根据默认拒绝、最小权限、完全仲裁和权限分离填写 Agent 权限矩阵和人工确认点；
4. 区分研究工件的 `draft → review → approved → stable` 四种成熟度；
5. 用日志、状态和实际文件变化保存一条可追溯记录。

## 三、课前准备

### 教师

- [ ] 复核中国科学院《诚信提醒》官方页面及课堂引用日期

- [ ] 准备“过宽权限”和“最小权限”两份演示配置
- [ ] 演示仓库只含公开或虚构材料，不显示密钥、私人路径或真实账户
- [ ] 预置 `AGENTS.md`、`agent-permissions.md`、`artifact-tracking.md`、`ethics-and-compliance.md`、`ai-usage-log.md`
- [ ] 准备无模型／无网络时可使用的截图或文本回放
- [ ] 将 [classroom-pack.md](./classroom-pack.md) 中的案例、模板和离线路径发给学生

### 学生

- [ ] 带上第 1 课个人项目
- [ ] 保留初步问题、链路草图和首条 AI 使用记录
- [ ] OpenCode 可启动；不可用者使用 Markdown 备用路径
- [ ] 不把真实保密材料用于课堂练习

## 六、教师演示脚本

### 演示项目

```text
demo-project/
├── AGENTS.md
├── problem-definition.md
├── agent-permissions.md
├── artifact-tracking.md
├── ethics-and-compliance.md
└── ai-usage-log.md
```

全部内容必须公开或虚构。`AGENTS.md` 默认：

- 只读 `problem-definition.md` 和当前模板；
- 不联网；
- 不访问项目外目录；
- 第一轮不写文件；
- 权限扩大和状态迁移必须等待人工确认。

### 第一轮：只读分析

```text
读取 AGENTS.md、problem-definition.md 和 agent-permissions.md。

任务：
1. 为“使用公开论文摘要生成候选关键词”填写一张五字段风险卡；
2. 指出当前权限矩阵中过宽或缺失的地方；
3. 提出最小修改建议。

限制：
- 不修改文件；
- 不联网；
- 不假设任何材料已获额外授权；
- 不把建议写成已批准决定。
```

教师判断一项建议是否值得采用，并说明拒绝其他建议的理由。

### 第二轮：限定写回

```text
仅执行以下已批准修改：
1. 更新 agent-permissions.md 的“文献与网络”一行；
2. 在 ethics-and-compliance.md 增加本次风险卡；
3. 在 ai-usage-log.md 记录本次交互。

不要修改问题定义、工件状态或其他文件。
完成后列出实际修改文件，等待人工检查。
```

最后检查：

- `git diff -- agent-permissions.md ethics-and-compliance.md ai-usage-log.md`
- 是否出现未授权文件变化；
- AI 使用记录是否写明 Context、用途和人工核验；
- Agent 是否擅自把工件状态改为 `approved` 或 `stable`。

## 七、课堂实践验收

### 55:00–78:00 课堂最低闭环

- [ ] 权限矩阵至少填写一项当前科研动作
- [ ] 只读、可写、可执行和网络范围可区分
- [ ] 至少有一个具体人工确认点
- [ ] 至少有一个明确禁止事项
- [ ] 五字段风险卡包含责任人
- [ ] 追踪表至少新增一项早期工件，且包含状态、当前依据和下一步
- [ ] 状态变化没有以“Agent 已完成”为唯一依据
- [ ] AI 使用记录包含 Context、输出用途和核验方式

### 第 3 课前完整项目更新

- [ ] `artifact-tracking.md` 已包含问题定义、AI 使用记录、权限矩阵和伦理清单四项早期工件
- [ ] 四项工件均有状态、当前依据和下一步

本课不正式提交，但不是没有课后任务。第 3 课前完成：

1. **核心阅读，约 15 分钟**：阅读中国科学院《关于在科研活动中规范使用人工智能技术的诚信提醒》，记录一条与个人项目直接相关的底线及其工作流影响。
2. **项目更新，约 20 分钟**：补全一行权限矩阵、一张五字段风险卡、四项早期工件追踪和一条 AI 使用记录。
3. **检索准备，约 10 分钟**：写出一个公开研究问题、3–5 个关键词和一项来源或网络访问边界。
4. **任选阅读**：NASEM *Fostering Integrity in Research* Chapter 2，或 Saltzer、Schroeder 论文中 fail-safe defaults、complete mediation、separation of privilege、least privilege 四项原则，二选一。

以上内容持续回写个人项目，不单独提交、不计周作业分。第 3 课开场安排 3–5 分钟自查或同伴互看；第 6 课问题门再检查与项目直接相关的工件成熟度。

## 八、容易出现的偏差

- 把“使用 AI”本身判为允许或禁止，而不看材料和动作；
- 把“有条件允许”写成无法检查的模糊承诺；
- 权限矩阵只有“允许／禁止”，没有路径、命令、网络和确认点；
- 把平台弹窗当成完整权限设计；
- 让 Agent 自行扩大 Context 或修改评价协议；
- 把日志当作免责证明，不记录拒绝和失败；
- 把 `stable` 当成“写完了”；
- 课堂讨论真实学生、合作或评审材料。

## 九、讲后复盘

- 学生最容易忽略哪一种材料风险？
- “有条件允许”的条件是否足够可操作？
- 哪个权限原则最难迁移到 Agent 场景？
- 学生能否区分工件状态和任务进度？
- 演示是否清楚呈现人工判断，而非只展示成功操作？
- 第 3 课检索活动需要继承哪些网络和来源边界？
