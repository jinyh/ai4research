# 第 2 课课堂材料包

## 一、虚构演示项目

情境：研究者准备为一份虚构未公开合作稿梳理研究问题与相关线索。原稿保留在本地且不向 Agent 开放；演示假设已确认获准讨论的问题描述和符合要求的处理环境。演示项目仅保存虚构对象描述与获准的问题描述，不包含真实合作稿、个人信息、密钥或账户。真实任务须在运行前核实内容授权与环境，抽象化本身不构成授权。

```text
demo-project/
├── AGENTS.md
├── problem-definition.md
├── agent-permissions.md
├── artifact-tracking.md
├── ethics-and-compliance.md
└── ai-usage-log.md
```

本演示的“不联网”指不进行额外网络操作，模型后端的传输、存储和训练条件须先核查。第一轮只读权限矩阵与人工写好的虚构对象描述，不读取原稿、不联网、不写文件。第二轮经人工确认后，只写权限一行、风险卡和 AI 使用记录，完成后检查 diff。

**助教演示交接**：教师在 P21 交代虚构材料身份并请学生预测暂停点；助教在 P22 展示只读输入与过宽权限建议后停下，由教师主持学生判断；教师在 P23 明确批准文件、段落和范围后，助教写回并展示实际 diff。第 1 课阅读卡问题的有限写回只作口头衔接，本包的合作稿与记录仍为课堂构造。助教备好干净起点、完成版和可恢复副本；若授课设备上的限制配置未验证，使用预制 trace 或 Markdown 回放并明确标注实际执行方式。

完整六字段填写示例见 [讲义中的同一合作稿案例](./handout.md#l02-partner-draft-permission)。

## 三、同伴互查

1. 只读范围是否已经缩小到完成任务所需的最小集合？
2. 哪一项动作最需要明确的人工确认点？
3. 风险理由、权限边界和日志能否相互解释？

## 四、无模型／无网络备用路径

直接编辑以上 Markdown 表格，并在 AI 使用记录的“工具 / 模型”与“输出用途”字段写明“未执行：模型不可用”，保留预期任务、Context 边界和人工核验方式。这一路径不伪造 AI 执行记录。

课后将风险卡、权限矩阵和 AI 使用记录的状态回写 `artifact-tracking.md`；这一步不作为本课课堂第四张表。
