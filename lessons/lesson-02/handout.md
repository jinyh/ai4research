# 第二讲｜科研伦理与 Agent 边界

## 导读与学习目标

教师以 MI（Mechanistic Interpretability，机制可解释性）展示研究方法，学生持续维护自己的一个个人项目。共同诊断后，个人实践回到本人问题；已有课题、拟开展方向或公开小问题均可。尚未确定课题者先使用可替换的小问题，至 L6 收敛。L4–L6 的三张精读卡围绕本人问题累计，个人验证按项目选择实验、系统测试、数据审计或论证检查。

L1 已留下问题版本、AI 建议、本人决定和实际变化。本课继续问：**完成下一项研究动作需要什么上下文和权限，实际记录能证明哪些边界得到执行？** 尚无实验结果者使用问题定义和公开材料即可。

完成本课后，应能识别材料与动作风险，写出一行任务授权及五字段风险卡，区分声明、人工控制、工具限制与操作系统隔离，并检查允许与拒绝动作的记录。工件状态用于追踪检查程度，课堂不增加第四张表。

## 共同诊断的输入与顺序

打开 [课堂材料包](./classroom-pack.md) 的目录、授权和 E1–E5 构造轨迹。先独立判断在哪一步需要停止、哪些记录不足以支持“权限全部通过”，再讨论。输入中的 private/ 和 heldout/ 只有虚构对象描述，现场不读取真实敏感资料。

个人实践从自己的一个动作出发，如检查问题表述、整理公开材料或准备检索任务；不要求提供开发实验结果。上下文清单并入既有权限文件，执行记录并入使用日志。

## 一、科研伦理首先是研究质量问题

科研诚信常被理解成“不要造假”，但可信研究还依赖更积极的价值。美国国家科学院 2017 年共识报告把研究诚信概括为六项核心价值：

- 客观（objectivity）；
- 诚实（honesty）；
- 开放（openness）；
- 公平（fairness）；
- 问责（accountability）；
- 守护责任（stewardship）。

AI 不会自动破坏这些价值，也不会自动保障这些价值。风险往往来自“研究对象、Agent 动作和使用情境”的组合。例如：

- 用 AI 整理公开论文，和把未公开评审稿上传到未经授权的平台，不是同一风险；
- 用生成数据做压力测试，和把生成数据标成真实实验观测，不是同一行为；
- 让 Agent 建议评价指标，和让它在看到结果后自行修改指标，不是同一权限。

因此，伦理判断不能只问“是否使用 AI”，而要问：

> 谁，对什么对象，执行什么动作，可能造成什么后果，由谁核验和承担责任？

### 中国科学院《诚信提醒》的课堂用法

中国科学院科研道德委员会 2024 年发布的《诚信提醒》覆盖选题调研、申报、数据、音视频与图表、成果撰写、同行评议、使用声明和工具选择八类情境。对本课程最重要的不是逐条记忆，而是识别三条贯穿原则：

1. **核验**：AI 生成的调研、建议、数据解释、文献和成果内容不能未经核实直接使用；
2. **披露**：工具、版本、日期、参与环节和使用过程应如实记录；
3. **保护**：不得因使用 AI 未经授权泄露评审材料、个人隐私、受限数据或知识产权内容。

课程规范是教学底线，不替代学校、实验室、数据提供方、期刊或项目的正式要求；当多项规则同时适用时，执行更严格且与具体材料相匹配的要求。

## 二、把风险判断写成五个字段

面对一项 AI 辅助科研动作，可以先填写一个五字段风险卡：

| 字段 | 要回答的问题 |
| --- | --- |
| 对象（Asset） | 涉及什么材料、数据、账户、文件或外部系统？ |
| 动作（Action） | Agent 要读取、生成、修改、执行、发送还是公开什么？ |
| 风险（Risk） | 可能损害真实性、隐私、保密、许可、安全、公平或可复现性的哪一项？ |
| 控制（Control） | 通过缩小 Context、脱敏、本地处理、只读、人工确认、日志或停止条件如何降低风险？ |
| 责任（Owner） | 谁决定是否继续，谁核验结果，谁对最终使用负责？ |

五个字段的用途是迫使判断落到具体动作。只写“注意伦理风险”不能指导 Agent，也不能支持事后复核。

### 校级规范与任务级处置

上海交通大学《关于在教育教学中使用 AI 的规范》将使用场景分为“禁止使用、有限使用、鼓励使用、开放使用”四类，是课程最近制度基线。本课的任务级风险处置使用“禁止／有条件允许／允许”三档，映射关系如下：

- 校级“禁止使用”对应任务级“禁止”；
- 校级“有限使用”对应任务级“有条件允许”；
- 校级“鼓励使用”“开放使用”对应任务级“允许”，但仍须服从材料授权、课程要求和披露责任。

校级分类是场景治理，任务级处置是具体动作边界。校级“鼓励使用”或“开放使用”不等于无须风险卡和权限矩阵；当材料许可、共同作者、机构或期刊规则更严格时，执行更严格要求。授课前应复核学校规范是否有修订。

### 三种处置

完成风险卡后，给动作一个处置结论：

#### 1. 允许

风险较低，现有控制充分，可以在当前边界内执行。

例：Agent 只读公开论文的书目信息，生成候选关键词；学生随后回原始来源核验。

#### 2. 有条件允许

可以执行，但必须先满足明确条件。

例：含用户反馈的数据只有在获得授权、完成必要脱敏、限定只读目录并禁止外部传输后，才允许本地分析。

#### 3. 禁止

风险无法在当前课程条件下合理控制，或者动作本身破坏研究诚信。

例：把 AI 生成的模拟数据伪装成真实实验数据；把保密评审稿上传到未经评议组织者认可的外部工具；让 Agent 删除不利结果以“清理实验”。

“有条件允许”不是模糊中间态。条件必须可以检查，例如：

- 使用哪一个获授权的数据副本；
- 哪些字段需要删除或替换；
- 网络是否关闭；
- 哪个文件只读；
- 哪一步必须由谁确认；
- 失败后保存什么记录。

## 三、六类常见风险

### 1. 数据、隐私与保密

检查材料是否包含个人信息、敏感属性、未公开论文、同行评议材料、学生资料、商业秘密、受限数据或凭据。不要因为材料已经在本机，就假定可以发送给外部模型。

控制方式包括：

- 先确认材料属于作者团队工作稿、正式同行评议稿还是第三方受限材料；
- 获得共同作者或其他材料权利人的明确授权；
- 只提供完成任务所需的最小片段；
- 删除身份字段和无关元数据；
- 使用获授权的本地或机构环境；
- 禁止联网与跨目录访问；
- 记录数据来源、许可和处理方式。

### 2. 证据真实性与可复现性

AI 输出可能混淆事实、推断和虚构。生成内容必须保留来源角色：

- AI 建议：候选；
- 原文或原始数据：可核验输入；
- 分析脚本输出：在给定环境和配置下的结果；
- 人工判断：基于证据作出的决定。

不得把生成数据、补写结果或无法复现的图表当成真实观测。

### 3. 署名、贡献与披露

AI 工具可以参与研究与产出内容，但不替代个人作者身份、贡献披露和研究责任。使用者需要说明：

- 使用了什么工具或模型；
- 在什么环节使用；
- 提供了什么 Context；
- 输出如何被使用或放弃；
- 采用了什么人工核验；
- 哪些核心判断由研究者完成。

### 4. 版权、许可与知识产权

能访问不等于能上传、改写、再发布或训练。论文全文、图表、代码、模型权重和数据集可能分别受到数据库条款、出版许可、开源许可或项目协议约束。

### 5. 公平、偏见与社会影响

数据覆盖不足、标签偏差、语言和地域差异可能让工作流系统性忽略某些群体或研究方向。风险评估需要记录谁可能受益、谁可能受损、哪些群体在数据中不可见。

### 6. 安全与双重用途

部分研究材料或自动化能力可能同时支持有益与有害用途。课程项目应缩小到可安全展示和复核的范围；对无法在课堂条件下合理控制的高风险任务，不以“研究探索”为由扩大 Agent 权限。

## 四、Agent 权限不是一个总开关

“允许使用 Pi Agent”不等于“允许 Agent 做任何事”。权限应按对象和动作拆开：

| 维度 | 例子 |
| --- | --- |
| 文件读取 | 指定公开论文、项目 Markdown、只读数据副本 |
| 文件写入 | 指定目标文件或目录，不默认整个项目 |
| 命令执行 | 明确允许的测试、格式检查或只读命令 |
| 网络访问 | 关闭、限定域名、限定检索任务或逐次确认 |
| 外部系统 | API、MCP、云盘、数据库、消息和发布平台 |
| 不可逆动作 | 删除、覆盖、公开、发送、导入和账户变更 |

### 四个经典保护原则

Saltzer 与 Schroeder 1975 年提出的保护原则虽然早于现代 Agent，但非常适合解释权限设计。

#### Fail-safe defaults｜默认拒绝

没有明确授权的动作默认不允许，而不是“只要没写禁止就可以”。

#### Least privilege｜最小权限

每次任务只获得完成当前动作所需的最小权限，任务变化后重新评估。

#### Complete mediation｜每次访问都检查

不能只在第一次检查权限，随后允许 Agent 在长循环中任意扩大范围。重要访问和外部动作需要持续检查。

#### Separation of privilege｜关键动作需要多项条件

高风险动作不能由单一信号触发。例如公开结果应同时满足：指定文件、通过人工复核、无敏感信息、明确发布目标。

这些原则不是机械规则，而是风险警报。如果工作流必须违反某项原则，需要记录原因、补偿控制和责任人。

### 研究 harness：声明边界并强制执行

权限矩阵、任务契约、版本化协议（如实验规格）和工件追踪记录，都是研究者把研究边界**声明**出来的工件；Pi Agent 是主要执行环境，但不会仅凭这些声明自动强制限制行为；工具配置、经核验的权限扩展或隔离环境负责落实**执行限制**。声明加执行，再加上例外走人工确认，构成"研究 harness"。它不是某个产品的功能名，而是这一整套边界机制的统称：研究者声明边界，harness 执行边界，例外必须经人工确认并留记录。后续课程（受限 Agent 执行与自主工作流设计）会继续使用这个概念。

## 五、权限矩阵怎样填写

本课程使用以下结构：

| 对象或能力 | 只读范围 | 可写范围 | 是否允许执行 | 人工确认点 | 禁止事项 |
| --- | --- | --- | --- | --- | --- |
| 项目 Markdown | `problem-definition.md`、公开说明 | `agent-permissions.md` 等指定文件 | 不适用 | 写入前确认目标段落 | 不批量重写其他工件 |
| 代码与命令 | `src/`、测试配置 | 当前任务指定文件 | 只运行白名单命令 | 安装依赖、长时任务前确认 | 不删除失败记录 |
| 文献与网络 | 已批准公开来源 | 检索记录 | 按任务决定 | 登录、下载或发送全文前确认 | 不上传正式评审稿或未获授权材料 |
| 数据目录 | 获授权只读副本 | 派生结果目录 | 仅批准脚本 | 改变清洗规则前确认 | 不接触原始敏感目录 |
| 外部 API / MCP | 明确服务和字段 | 明确目标系统 | 默认关闭 | 外部写入逐次确认 | 不发送凭据和未获授权的未公开内容 |

### 同一 IOI 任务的一行权限 {#l02-ioi-permission}

本课使用 [课堂材料包](./classroom-pack.md) 的虚构目录与轨迹。任务是根据 L1 的问题和已提供公开观察，提出下一项取证计划。只读提供文本，批准后仅写 notes/next-check.md 的计划段。目录中的来源清单虽然公开，仍在本次授权外；未公开材料和保留评价占位分别涉及内容授权与评价有效性。

| 对象或能力 | 只读范围 | 可写范围 | 是否允许执行 | 人工确认点 | 禁止事项 |
| --- | --- | --- | --- | --- | --- |
| 本次取证计划 | 当前问题、已提供的公开观察与任务说明 | 批准后 notes/next-check.md 计划段 | 本轮不执行实验或额外联网 | 扩大读取、写入、执行或传输范围前核对新授权 | 不读取 private/、heldout/ 或未列入的文件，不修改问题、指标与原始记录 |

已授权范围内可连续行动；出现新需求时先说明必要性并补授权。风险卡、权限行和日志由人在核验后更新，属于治理记录，不计为未经批准的 Agent 写入。

### 把权限写入任务契约

每次 Agent 任务至少说明：

```text
Task：本次只解决什么问题？
Context：允许读取哪些文件和材料？
Output：输出格式和目标文件是什么？
Permission：允许读取、写入、执行和联网到什么范围？
Non-goal：本次明确不做什么？
Review：哪一步暂停并等待人工确认？
```

权限矩阵提供长期边界，任务契约提供本次边界；两者都是研究 harness 的声明工件。两者冲突时执行更窄的授权。

## 六、研究工件不是“文件列表”

研究工件是可以被审查、追踪和回写的研究产出，例如问题定义、精读卡、证据地图、实验规格、判断记录和评价报告。一个文件存在，不代表其中的主张已经成熟。

### 四种状态

| 状态 | 含义 | 可以怎样使用 |
| --- | --- | --- |
| `draft` | 初步内容，可能缺失来源、边界或核验 | 用于思考和讨论，不作为正式结论 |
| `review` | 已具备最小结构，等待本人或同伴检查 | 用于审查和修改 |
| `approved` | 已通过对应研究门或明确人工批准 | 可作为下一阶段输入 |
| `stable` | 工件经过充分检查，关键结论满足课程稳定状态要求 | 可在新证据下修订；有限结论和未决项也可如实进入报告 |

来源核验、证据作用、结论方向和工件成熟度分别记录。`stable` 不表示引用资格。

状态描述的是成熟度，不是“做到第几步”。把文件从 `draft` 改成 `stable`，不会自动增加证据。

### 状态迁移必须有依据

每次迁移至少记录：

- 谁发起变化；
- 谁进行了复核；
- 新增或核验了什么证据；
- 解决了哪些问题；
- 仍有哪些边界；
- 变化将被用于哪个后续动作。

`stable` 不是“写得很流畅”。本课程要求关键结论至少绑定一项可核验直接证据或实验结果；准备标为 `stable` 的结论原则上需要两项相互独立证据。只有单一证据时，应保持边界和待验证状态。

### 轻量追踪表

| 工件 | 状态 | 来源 | 依据 | 后续用途 |
| --- | --- | --- | --- | --- |
| 问题定义 | draft | 个人兴趣、领域现象 | 初步观察 | 检索与问题门 |
| AI 使用记录 | review | 工具交互 | 实际 prompt、diff、人工核验 | 透明披露 |
| 权限矩阵 | review | 当前任务和材料 | 风险卡、人工确认点 | 后续 Agent 任务 |
| 伦理清单 | draft | 数据与使用情境 | 许可和风险判断 | 项目范围调整 |

## 七、日志怎样避免成为形式主义

日志的价值不是证明“我写过日志”，而是让后来者可以回答：

1. AI 在哪一步参与？
2. 它看到了什么 Context？
3. 它提出或修改了什么？
4. 人为什么采纳或拒绝？
5. 哪些内容经过怎样的核验？
6. 实际文件变化是否与 Agent 自述一致？

一条有用的 AI 使用记录包括：

| 日期 | 工具／模型 | 用途 | 关键输入 | Context／数据来源 | 输出用途 | 人工核验方式 | 问题或误导 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 例 | Pi Agent + 某模型 | 收敛研究问题 | 任务契约摘要 | `AGENTS.md`、问题初稿 | 采用建议 2 | 检查定义、来源和 diff | 建议 1 扩大了数据范围 |

以下记录没有足够信息：

- “用 AI 帮我改了一下”；
- “模型说没有问题”；
- “已人工核验”但不写核验对象和方法；
- 只保存最终成功输出，删除失败和拒绝原因；
- 只相信 Agent 的完成报告，不检查文件、命令和外部状态。

## 八、按风险查阅的对照案例

课堂主任务沿用 L1 的公开 IOI 问题与取证计划。以下对照案例分别解释材料授权、数据身份与评价协议；教师按本班卡点选用，学生不额外完成三套任务。

### 案例 A：未公开稿件

AI 可以协助探讨原创问题、机制假设和相关研究线索。未公开状态本身不决定是否可以讨论，判断仍取决于输入内容的授权、适用规则和处理环境。本人可以自主决定分享的想法，在符合要求的环境中可以用于讨论；合作项目内容须确认相应权利人的同意与使用范围。抽象问题仍可能暴露受限的核心内容，必要时继续缩小输入或使用获批准处理该内容的环境；本地运行本身不替代材料授权。研究者核验 AI 输出的依据，并记录采纳、修改或拒绝的理由。

任务：你是共同作者，想把一篇尚未投稿的合作论文上传到个人账户下的外部模型，帮助梳理研究问题和相关研究线索。

初步判断：**默认不直接上传全文；满足明确条件后可以转为有条件允许。**

条件至少包括：

- 所有共同作者或材料权利人同意；
- 合作协议、资助要求、机构规定和投稿规则允许；
- 使用经项目或机构认可、数据训练与保存规则可接受的处理环境；
- 不包含敏感数据、第三方保密材料或尚未获得保护的关键知识产权；
- 只提供必要范围，保存 AI 使用记录，并由作者人工核验输出。

个人付费订阅不等于获得处理授权；即使平台提供关闭训练或临时会话选项，也只能降低部分平台风险，不能替代共同作者同意和项目规则。不同账户类型和服务的数据处理规则可能不同，使用前应核对供应商当前说明，例如 [OpenAI 数据使用说明](https://help.openai.com/en/articles/5722486-how-your-data-is-used-to-improve-model-performance) 与 [Anthropic 数据训练说明](https://privacy.claude.com/en/articles/10023580-is-my-data-used-for-model-training)。若条件不能满足，改用以下替代路径：

- 公开版本；
- 最小必要片段；
- 抽象化问题；
- 内部人工审阅；
- 获批准的本地／机构环境。

缩小输入的两个常见做法：只提供必要摘要与结构；把未公开数据替换为占位符，只提交要分析的问题。两者仍须核查授权、适用规则与处理环境；摘要或抽象描述也可能暴露受限核心内容。

如果未获授权的材料已经外发：停止继续发送；评估已发送内容的敏感级别（摘要／全文／数据）；向共同作者说明并保留记录；后续改用上述合规路径。事后删除或隐瞒不能消除已经发生的泄露。

如果材料是作为审稿人收到的正式评审稿，判断应更严格：除非期刊或评议组织者明确批准具体工具并能保障保密，否则不得上传，也不能把 AI 输出冒充正式同行评议。中国科学院《诚信提醒》第六条以及 [Nature](https://www.nature.com/nature-portfolio/editorial-policies/ai) 和 [ICMJE](https://www.icmje.org/recommendations/browse/artificial-intelligence/ai-use-by-reviewers.html) 的审稿人政策均强调评审保密与组织者规则。

### 案例 B：生成数据

任务：让 Agent 生成模拟样本，用于测试分析脚本能否处理缺失值和异常值。

初步判断：**有条件允许。**

条件：明确标记为模拟数据；与真实实验数据分开存储；记录生成逻辑和用途；不得用它替代真实观测或夸大实验结论。

一个可操作的区分：模拟缺失值可以测试分析脚本是否会崩溃、异常值处理是否按预期运行；它可以支持“脚本在这组模拟条件下通过”的方法结论，不能支持“真实人群中该方法有效”或“现实数据呈现同样规律”的经验结论。后两类结论仍需要真实、获授权并符合研究设计的数据。

### 案例 C：评价协议

任务：自动实验循环发现当前指标下结果不理想，准备自行修改指标并继续搜索。

初步判断：**禁止 Agent 自行修改。**

原因：指标决定什么算“改善”。看到结果后无记录地改指标，会污染比较并产生选择性报告。Agent 可以提出修改建议，但必须暂停，由研究者说明理由、版本化协议并决定旧结果如何保留。

## 九、一次允许动作与受控拒绝检查

默认路径使用执行前人工审核。先写 Task、Context、Output 和已有授权；研究者核准一项必要动作，例如让 AI 只根据提供的公开问题提出检索词。运行并保存实际输入输出。随后提出一项超出授权的模拟请求，例如读取未列入清单的公开 notes/source-list.md；人在执行前拒绝，记录请求、理由、拦截点和后续可行路径。被拒绝的文件不实际读取。

这次记录证明人工审核发生过，不能证明模型自动拒绝、路径沙箱或任意代码的系统隔离。若授课环境已有经验证的限制配置，可另做工具层拒绝并记录配置和错误；直接读文件的其他路径是否受控仍需单独验证。后续课的 access-check 接口不是本课先修依赖。

| 证据 | 能支持的判断 | 仍需补查 |
| --- | --- | --- |
| 提示词与权限行 | 已声明什么边界 | 工具实际如何执行 |
| 人工拦截记录 | 某次请求执行前被人停止 | 没有人介入时的控制能力 |
| 工具拒绝响应 | 某个已测接口拒绝了请求 | 其他路径和整个系统是否受限 |
| 完整 trace 与文件变化 | 已记录动作及最终修改 | 是否遗漏读取、外部传输或其他工具 |

`NETWORK off` 在课堂契约中指不作额外检索或外部操作；调用远程模型本身仍有数据传输。Context 清单是计划提供的材料，实际工具读取和自动加载内容还要查看环境与记录。启动方式见 [Pi 说明](../../course/pi-setup.md)。

## 十、本人实践与 L3 交接

从 L1 选择一个动作，列必要输入、现有授权、输出位置和停止条件。给这次动作写一行权限与风险卡；完成一次真实已授权 AI 动作和一次人工受控拒绝检查。日志如实区分模型输出、本人决定与实际操作者。

- ML 项目可整理问题或公开数据说明，不要求已完成实验。
- 系统／软件项目可核对接口需求、公开故障或负载描述。
- 文献／理论项目可核对定义、来源范围或检索任务，不要求代码和数据划分。

权限行、风险卡、使用记录必须指向同一动作；无模型时先在构造输入上完成人工审核，标记实际 AI 动作待补。不要以日志里写了“拒绝”推断工具已经执行拒绝。

交给 L3：本人问题、可公开检索表述、已批准来源与工具、网络和数据边界、结果保存位置、允许／拒绝检查记录，以及一个拟检索缺口。L3 在这些范围内开展实际文献发现。
