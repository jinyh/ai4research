# 第二讲｜科研伦理、Agent 权限、研究工件与追踪

## 导读

第一讲建立了一个最小可审计交互：Agent 先只读分析，研究者审核建议，再授权有限写入，最后检查实际文件变化并记录 AI 使用。第二讲继续追问：

> 当 Agent 能够读取材料、调用工具、修改文件和访问网络时，研究者如何把伦理原则变成可执行的边界？

科研伦理不是课程末尾附加的一份声明，也不是背诵若干禁止事项。它至少要进入四个具体位置：

1. 选择什么材料可以进入 AI Context；
2. 决定 Agent 可以读取、修改、执行和发送什么；
3. 判断哪些动作必须由人确认；
4. 记录研究工件为何从初稿变成可引用结论。

本讲不要求你解决项目的全部合规问题，而是建立一套可以持续修改的早期控制面：`agent-permissions.md`、`ethics-and-compliance.md`、`artifact-tracking.md` 和 `ai-usage-log.md`。

## 学习目标

完成本讲后，你应该能够：

1. 从数据、证据、署名、版权、隐私、保密和双重用途等维度识别风险；
2. 对一项 AI 辅助科研动作作出“允许／有条件允许／禁止”的判断，并用五字段风险卡说明理由；
3. 根据默认拒绝、最小权限、完全仲裁和权限分离填写 Agent 权限矩阵和人工确认点；
4. 区分研究工件的 `draft → review → approved → stable` 四种成熟度；
5. 用日志、状态和实际文件变化保存一条可追溯记录。

## 一、科研伦理首先是研究质量问题

科研诚信常被理解成“不要造假”，但可信研究还依赖更积极的价值。美国国家科学院 2017 年共识报告把研究诚信概括为六项核心价值：

- 客观（objectivity）；
- 诚实（honesty）；
- 开放（openness）；
- 公平（fairness）；
- 问责（accountability）；
- 守护责任（stewardship）。

AI 不会自动破坏这些价值，也不会自动保障这些价值。风险往往来自“研究对象、Agent 动作和使用情境”的组合。例如：

- 用 AI 整理公开论文，和把未公开评审稿上传到未经授权的平台，不是同一风险；
- 用生成数据做压力测试，和把生成数据标成真实实验观测，不是同一行为；
- 让 Agent 建议评价指标，和让它在看到结果后自行修改指标，不是同一权限。

因此，伦理判断不能只问“是否使用 AI”，而要问：

> 谁，对什么对象，执行什么动作，可能造成什么后果，由谁核验和承担责任？

### 中国科学院《诚信提醒》的课堂用法

中国科学院科研道德委员会 2024 年发布的《诚信提醒》覆盖选题调研、申报、数据、音视频与图表、成果撰写、同行评议、使用声明和工具选择八类情境。对本课程最重要的不是逐条记忆，而是识别三条贯穿原则：

1. **核验**：AI 生成的调研、建议、数据解释、文献和成果内容不能未经核实直接使用；
2. **披露**：工具、版本、日期、参与环节和使用过程应如实记录；
3. **保护**：不得因使用 AI 未经授权泄露评审材料、个人隐私、受限数据或知识产权内容。

课程规范是教学底线，不替代学校、实验室、数据提供方、期刊或项目的正式要求；当多项规则同时适用时，执行更严格且与具体材料相匹配的要求。

## 二、把风险判断写成五个字段

面对一项 AI 辅助科研动作，可以先填写一个五字段风险卡：

| 字段 | 要回答的问题 |
| --- | --- |
| 对象（Asset） | 涉及什么材料、数据、账户、文件或外部系统？ |
| 动作（Action） | Agent 要读取、生成、修改、执行、发送还是公开什么？ |
| 风险（Risk） | 可能损害真实性、隐私、保密、许可、安全、公平或可复现性的哪一项？ |
| 控制（Control） | 通过缩小 Context、脱敏、本地处理、只读、人工确认、日志或停止条件如何降低风险？ |
| 责任（Owner） | 谁决定是否继续，谁核验结果，谁对最终使用负责？ |

五个字段的用途是迫使判断落到具体动作。只写“注意伦理风险”不能指导 Agent，也不能支持事后复核。

### 校级规范与任务级处置

上海交通大学《关于在教育教学中使用 AI 的规范》将使用场景分为禁止、限制、鼓励和开放四类，是课程最近制度基线。本课的任务级风险处置使用“禁止／有条件允许／允许”三档，映射关系如下：

- 校级“禁止”对应任务级“禁止”；
- 校级“限制”对应任务级“有条件允许”；
- 校级“鼓励”“开放”对应任务级“允许”，但仍须服从材料授权、课程要求和披露责任。

校级分类是场景治理，任务级处置是具体动作边界。校级“鼓励”或“开放”不等于无须风险卡和权限矩阵；当材料许可、共同作者、机构或期刊规则更严格时，执行更严格要求。授课前应复核学校规范是否有修订。

### 三种处置

完成风险卡后，给动作一个处置结论：

#### 1. 允许

风险较低，现有控制充分，可以在当前边界内执行。

例：Agent 只读公开论文的书目信息，生成候选关键词；学生随后回原始来源核验。

#### 2. 有条件允许

可以执行，但必须先满足明确条件。

例：含用户反馈的数据只有在获得授权、完成必要脱敏、限定只读目录并禁止外部传输后，才允许本地分析。

#### 3. 禁止

风险无法在当前课程条件下合理控制，或者动作本身破坏研究诚信。

例：把 AI 生成的模拟数据伪装成真实实验数据；把保密评审稿上传到未经评议组织者认可的外部工具；让 Agent 删除不利结果以“清理实验”。

“有条件允许”不是模糊中间态。条件必须可以检查，例如：

- 使用哪一个获授权的数据副本；
- 哪些字段需要删除或替换；
- 网络是否关闭；
- 哪个文件只读；
- 哪一步必须由谁确认；
- 失败后保存什么记录。

## 三、六类常见风险

### 1. 数据、隐私与保密

检查材料是否包含个人信息、敏感属性、未公开论文、同行评议材料、学生资料、商业秘密、受限数据或凭据。不要因为材料已经在本机，就假定可以发送给外部模型。

控制方式包括：

- 先确认材料属于作者团队工作稿、正式同行评议稿还是第三方受限材料；
- 获得共同作者或其他材料权利人的明确授权；
- 只提供完成任务所需的最小片段；
- 删除身份字段和无关元数据；
- 使用获授权的本地或机构环境；
- 禁止联网与跨目录访问；
- 记录数据来源、许可和处理方式。

### 2. 证据真实性与可复现性

AI 输出可能混淆事实、推断和虚构。生成内容必须保留来源角色：

- AI 建议：候选；
- 原文或原始数据：可核验输入；
- 分析脚本输出：在给定环境和配置下的结果；
- 人工判断：基于证据作出的决定。

不得把生成数据、补写结果或无法复现的图表当成真实观测。

### 3. 署名、贡献与披露

AI 工具不是作者，也不能承担科研责任。使用者需要说明：

- 使用了什么工具或模型；
- 在什么环节使用；
- 提供了什么 Context；
- 输出如何被使用或放弃；
- 采用了什么人工核验；
- 哪些核心判断由研究者完成。

### 4. 版权、许可与知识产权

能访问不等于能上传、改写、再发布或训练。论文全文、图表、代码、模型权重和数据集可能分别受到数据库条款、出版许可、开源许可或项目协议约束。

### 5. 公平、偏见与社会影响

数据覆盖不足、标签偏差、语言和地域差异可能让工作流系统性忽略某些群体或研究方向。风险评估需要记录谁可能受益、谁可能受损、哪些群体在数据中不可见。

### 6. 安全与双重用途

部分研究材料或自动化能力可能同时支持有益与有害用途。课程项目应缩小到可安全展示和复核的范围；对无法在课堂条件下合理控制的高风险任务，不以“研究探索”为由扩大 Agent 权限。

## 四、Agent 权限不是一个总开关

“允许使用 OpenCode”不等于“允许 Agent 做任何事”。权限应按对象和动作拆开：

| 维度 | 例子 |
| --- | --- |
| 文件读取 | 指定公开论文、项目 Markdown、只读数据副本 |
| 文件写入 | 指定目标文件或目录，不默认整个项目 |
| 命令执行 | 明确允许的测试、格式检查或只读命令 |
| 网络访问 | 关闭、限定域名、限定检索任务或逐次确认 |
| 外部系统 | API、MCP、云盘、数据库、消息和发布平台 |
| 不可逆动作 | 删除、覆盖、公开、发送、导入和账户变更 |

### 四个经典保护原则

Saltzer 与 Schroeder 1975 年提出的保护原则虽然早于现代 Agent，但非常适合解释权限设计。

#### Fail-safe defaults｜默认拒绝

没有明确授权的动作默认不允许，而不是“只要没写禁止就可以”。

#### Least privilege｜最小权限

每次任务只获得完成当前动作所需的最小权限，任务变化后重新评估。

#### Complete mediation｜每次访问都检查

不能只在第一次检查权限，随后允许 Agent 在长循环中任意扩大范围。重要访问和外部动作需要持续检查。

#### Separation of privilege｜关键动作需要多项条件

高风险动作不能由单一信号触发。例如公开结果应同时满足：指定文件、通过人工复核、无敏感信息、明确发布目标。

这些原则不是机械规则，而是风险警报。如果工作流必须违反某项原则，需要记录原因、补偿控制和责任人。

## 五、权限矩阵怎样填写

本课程使用以下结构：

| 对象或能力 | 只读范围 | 可写范围 | 是否允许执行 | 人工确认点 | 禁止事项 |
| --- | --- | --- | --- | --- | --- |
| 项目 Markdown | `problem-definition.md`、公开说明 | `agent-permissions.md` 等指定文件 | 不适用 | 写入前确认目标段落 | 不批量重写其他工件 |
| 代码与命令 | `src/`、测试配置 | 当前任务指定文件 | 只运行白名单命令 | 安装依赖、长时任务前确认 | 不删除失败记录 |
| 文献与网络 | 已批准公开来源 | 检索记录 | 按任务决定 | 登录、下载或发送全文前确认 | 不上传正式评审稿或未获授权材料 |
| 数据目录 | 获授权只读副本 | 派生结果目录 | 仅批准脚本 | 改变清洗规则前确认 | 不接触原始敏感目录 |
| 外部 API / MCP | 明确服务和字段 | 明确目标系统 | 默认关闭 | 外部写入逐次确认 | 不发送凭据和未获授权的未公开内容 |

矩阵中最容易遗漏的是“人工确认点”。它应该描述触发条件，而不是只写“需要人工确认”：

- 第一次从只读变为写入；
- 修改研究问题、评价指标或停止条件；
- 安装依赖或运行高成本任务；
- 访问网络、登录账户或调用外部 API；
- 处理敏感、保密或受许可限制材料；
- 删除、覆盖、发送、公开或导入外部系统；
- 将工件状态改为 `approved` 或 `stable`。

### 把权限写入任务契约

每次 Agent 任务至少说明：

```text
Task：本次只解决什么问题？
Context：允许读取哪些文件和材料？
Output：输出格式和目标文件是什么？
Permission：允许读取、写入、执行和联网到什么范围？
Non-goal：本次明确不做什么？
Review：哪一步暂停并等待人工确认？
```

权限矩阵提供长期边界，任务契约提供本次边界。两者冲突时执行更窄的授权。

## 六、研究工件不是“文件列表”

研究工件是可以被审查、追踪和回写的研究产出，例如问题定义、精读卡、证据地图、实验规格、判断记录和评价报告。一个文件存在，不代表其中的主张已经成熟。

### 四种状态

| 状态 | 含义 | 可以怎样使用 |
| --- | --- | --- |
| `draft` | 初步内容，可能缺失来源、边界或核验 | 用于思考和讨论，不作为正式结论 |
| `review` | 已具备最小结构，等待本人或同伴检查 | 用于审查和修改 |
| `approved` | 已通过对应研究门或明确人工批准 | 可作为下一阶段输入 |
| `stable` | 证据与边界足以支持稳定引用 | 可进入最终论证，但仍可在新证据下修订 |

状态描述的是成熟度，不是“做到第几步”。把文件从 `draft` 改成 `stable`，不会自动增加证据。

### 状态迁移必须有依据

每次迁移至少记录：

- 谁发起变化；
- 谁进行了复核；
- 新增或核验了什么证据；
- 解决了哪些问题；
- 仍有哪些边界；
- 变化将被用于哪个后续动作。

`stable` 不是“写得很流畅”。本课程要求关键结论至少绑定一项可核验直接证据或实验结果；准备标为 `stable` 的结论原则上需要两项相互独立证据。只有单一证据时，应保持边界和待验证状态。

### 轻量追踪表

| 工件 | 状态 | 来源 | 依据 | 后续用途 |
| --- | --- | --- | --- | --- |
| 问题定义 | draft | 个人兴趣、领域现象 | 初步观察 | 检索与问题门 |
| AI 使用记录 | review | 工具交互 | 实际 prompt、diff、人工核验 | 透明披露 |
| 权限矩阵 | review | 当前任务和材料 | 风险卡、人工确认点 | 后续 Agent 任务 |
| 伦理清单 | draft | 数据与使用情境 | 许可和风险判断 | 项目范围调整 |

## 七、日志怎样避免成为形式主义

日志的价值不是证明“我写过日志”，而是让后来者可以回答：

1. AI 在哪一步参与？
2. 它看到了什么 Context？
3. 它提出或修改了什么？
4. 人为什么采纳或拒绝？
5. 哪些内容经过怎样的核验？
6. 实际文件变化是否与 Agent 自述一致？

一条有用的 AI 使用记录包括：

| 日期 | 工具／模型 | 用途 | 关键输入 | Context／数据来源 | 输出用途 | 人工核验方式 | 问题或误导 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 例 | OpenCode + 某模型 | 收敛研究问题 | 任务契约摘要 | `AGENTS.md`、问题初稿 | 采用建议 2 | 检查定义、来源和 diff | 建议 1 扩大了数据范围 |

以下记录没有足够信息：

- “用 AI 帮我改了一下”；
- “模型说没有问题”；
- “已人工核验”但不写核验对象和方法；
- 只保存最终成功输出，删除失败和拒绝原因；
- 只相信 Agent 的完成报告，不检查文件、命令和外部状态。

## 八、三个案例

### 案例 A：未公开稿件

任务：你是共同作者，想把一篇尚未投稿的合作论文上传到个人订阅的外部模型，让它生成供作者内部使用的模拟审稿意见。

初步判断：**默认不直接上传全文；满足明确条件后可以转为有条件允许。**

条件至少包括：

- 所有共同作者或材料权利人同意；
- 合作协议、资助要求、机构规定和投稿规则允许；
- 使用经项目或机构认可、数据训练与保存规则可接受的处理环境；
- 不包含敏感数据、第三方保密材料或尚未获得保护的关键知识产权；
- 只提供必要范围，保存 AI 使用记录，并由作者人工核验输出。

个人付费订阅不等于获得处理授权；即使平台提供关闭训练或临时会话选项，也只能降低部分平台风险，不能替代共同作者同意和项目规则。不同账户类型和服务的数据处理规则可能不同，使用前应核对供应商当前说明，例如 [OpenAI 数据使用说明](https://help.openai.com/en/articles/5722486-how-your-data-is-used-to-improve-model-performance) 与 [Anthropic 数据训练说明](https://privacy.claude.com/en/articles/10023580-is-my-data-used-for-model-training)。若条件不能满足，应改用公开版本、最小必要片段、抽象化问题、内部人工审阅，或获批准的本地／机构环境。

如果材料是作为审稿人收到的正式评审稿，判断应更严格：除非期刊或评议组织者明确批准具体工具并能保障保密，否则不得上传，也不能把 AI 输出冒充正式同行评议。中国科学院《诚信提醒》第六条以及 [Nature](https://www.nature.com/nature-portfolio/editorial-policies/ai) 和 [ICMJE](https://www.icmje.org/recommendations/browse/artificial-intelligence/ai-use-by-reviewers.html) 的审稿人政策均强调评审保密与组织者规则。

### 案例 B：生成数据

任务：让 Agent 生成模拟样本，用于测试分析脚本能否处理缺失值和异常值。

初步判断：**有条件允许。**

条件：明确标记为模拟数据；与真实实验数据分开存储；记录生成逻辑和用途；不得用它替代真实观测或夸大实验结论。

### 案例 C：评价协议

任务：自动实验循环发现当前指标下结果不理想，准备自行修改指标并继续搜索。

初步判断：**禁止 Agent 自行修改。**

原因：指标决定什么算“改善”。看到结果后无记录地改指标，会污染比较并产生选择性报告。Agent 可以提出修改建议，但必须暂停，由研究者说明理由、版本化协议并决定旧结果如何保留。

## 十一、术语表

- **AI Context**：Agent 在一次任务中能读取的材料和指令范围；它决定 Agent 实际看到什么，是权限控制的第一层。
- **风险卡五字段**（Asset / Action / Risk / Control / Owner）：把伦理担忧拆成对象、动作、风险、控制和责任人五项，使判断可记录、可复核。
- **允许 / 有条件允许 / 禁止**：对一项 AI 辅助动作的三种处置；“有条件允许”的条件必须可检查（指定数据、脱敏字段、网络开关、确认点等）。
- **fail-safe defaults（默认拒绝）**：没有明确授权的动作默认不允许，而非“没写禁止即可”。
- **least privilege（最小权限）**：每次任务只获得完成当前动作所需的最小权限，任务变化后重新评估。
- **complete mediation（完全仲裁）**：重要访问和外部动作在长循环中持续检查，而非只在入口检查一次。
- **separation of privilege（权限分离）**：高风险动作需多项独立条件同时满足才能触发，如公开需指定文件、人工复核、无敏感信息、明确发布目标四者兼备。
- **权限矩阵**：按对象和能力列出只读、可写、执行、人工确认点和禁止事项的长期边界表，提供项目级边界。
- **任务契约**（Task / Context / Output / Permission / Non-goal / Review）：规定本次任务边界的六字段说明；与权限矩阵冲突时执行更窄授权。
- **人工确认点**：规定 Agent 在哪些触发条件下暂停等待研究者判断，如首次写入、修改指标、状态迁移为 `approved` / `stable`。
- **研究工件**：可被审查、追踪和回写的研究产出（问题定义、精读卡、证据地图、实验规格等），其成熟度独立于文件是否存在。
- **draft / review / approved / stable**：工件成熟度四状态；状态描述被检查程度，不等于完成比例，`stable` 可因新证据回退。
- **AI 使用记录**：记录 AI 参与环节、Context、输出用途、人工核验方式和问题的日志，用于事后还原判断与披露。
