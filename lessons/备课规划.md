# 智能科研方法——详细备课规划

本文件是 16 次课的教学执行指南。课程设计、门条件和评分的规范来源分别是：

- [syllabus.md](../course/syllabus.md)
- [assignments.md](../course/assignments.md)
- [assessment.md](../course/assessment.md)

如三者与本文件不一致，先修正课程设计文档，再同步本文件，不在课堂材料中另立规则。

## 一、执行原则

1. 课程主线是八阶段研究链路，不是 AI 工具清单。
2. OpenCode 从第 1 课起作为主要课堂工作平台，但不限制模型或后端，也不因平台选择加分。
3. 不以安装、记忆或调用现成 Skills 为教学目标。案例用于分析任务契约、Context、Memory、工具与权限、状态与工件、执行循环、Evals、人工审核点和失败恢复。
4. 每位学生独立维护项目仓库、证据、判断、实验、个人 Agent Workflow、AI 使用记录和反思。
5. 3-4 人固定同伴组只用于课堂分享、互查和同行评审，不共同提交。
6. 正式提交只有四次：第 6、9、13、16 课。第 8 课分享和第 15 课预检是形成性活动，不增加正式作业。
7. AI 输出只是线索。关键结论至少绑定一项可核验的直接证据或实验结果及上游决定；`stable` 结论原则上有两项相互独立的证据。
8. 伦理、权限、可追溯性、失败记录和人工核验贯穿所有课次。
9. “第一性原理分析”只指识别问题的基本约束、作用机制和不可违背条件，并由此推导待验证前提；它不是脱离文献、数据和既有工作的通用捷径，推导结果必须继续接受外部证据检验。
10. 来源的载体级别与论证角色分开判断：研究论文可支持研究主张，正式规范可支持行为边界，新闻、评论与 Careers feature 只用于背景、案例或线索，产品文档只支持经核验的产品行为。
11. 涉及课程中的 AI 使用边界时，先以学校当前正式规范为最近制度基线，再按任务补充国家/学会规范、出版或会议政策及服务条款；二手整理不能替代正式原文。
12. 处理未发表教学素材的任何环节（脱敏、制图、润色）不得送入外部 LLM 或在线服务；脱敏由教师人工执行、用户复核后入库。

## 二、总体节奏

| 模块 | 课次 | 学时 | 核心问题 | 阶段产出 |
| --- | --- | ---: | --- | --- |
| 课程框架、平台与规范 | 1-2 | 4 | 如何安全、可审计地用 Agent 支撑科研？ | 项目工作区、链路草图、权限矩阵、伦理清单 |
| 文献、证据与问题 | 3-6 | 8 | 如何从外部输入形成可检验问题？ | 检索记录、阅读卡、证据地图、问题门材料 |
| 假设、判断与方案分享 | 7-9 | 6 | 如何把问题变成有依据的实验规格？ | 机制假设、研究判断、分享反馈、判断门材料 |
| 原型、自动化与个人工作流 | 10-13 | 8 | 如何实现、评价并约束一个科研工作流？ | 原型、实验记录、个人 Agent Workflow、验证门材料 |
| 回写、评审与表达 | 14-16 | 6 | 如何把结果写成可追溯论证？ | 论文式短文、评审记录、论证门与期末项目 |

每次课 90 分钟，默认节奏：

- 回顾与工件检查：5-10 分钟
- 方法讲授与案例：25-35 分钟
- 演示或诊断：15-20 分钟
- 个人实践与同伴反馈：25-35 分钟
- 回写与退出卡：5 分钟

“课堂产出”默认回写到持续项目，不等于正式提交。

### 前两课整改原则

前两课只建立一个连续闭环，不并列铺开全部课程概念：第 1 课让学生完成一次“AI 建议 → 人工判断 → 有限写回 → 留下 diff/log”的可观察操作；第 2 课在同一个操作上补写材料边界、权限和披露要求。八阶段链路与四个研究门用于定位这次操作，不要求首课背诵完整术语或一次填满所有工件。

### PPT 启动门

前两课进入新一轮 PPT 制作前，依次满足：

1. 内容门：讲义、教案、逐页内容母稿、课程规则和来源角色已对齐，只有一套现行口径。
2. 节奏门：完成 90 分钟桌面推演，逐段时间合计准确，学生第一次动手时间和最小课堂产出明确。
3. 映射门：每页先写清页面任务、对应内容母稿位置、证据角色和预期学生动作，再决定版式。
4. 视觉门：前三门通过后才制作 PPTX；交大样例只提供品牌元素与版式线索，不被当作完整设计系统。

当前阶段停在前三门，不启动新的 PPTX 制作。

## 三、课堂环境与项目组织

### OpenCode 起步环境

第 1 课前准备一份最小启动说明，覆盖：

- 安装与启动方式，以及无法安装时的浏览器/远程替代方案
- 课程项目目录和 `AGENTS.md`
- 模型与后端选择原则：可用、合规、成本可控、能够保留必要记录
- 默认只读范围、允许写入的项目目录、命令执行确认和网络访问边界
- AI 使用记录、工件状态表和 Agent 权限矩阵
- 一次最小任务演示：读取课程说明，生成链路草图建议，由学生审核后写入项目文件

不要把第 1 课变成安装排障课。预先准备环境检查脚本、截图版备用演示和两人临时共用设备方案；课堂产出仍由每位学生写回自己的仓库。

### 个人项目与同伴组

- 每人一个仓库或明确隔离的个人目录。
- 同伴组固定 3-4 人，主要用于第 6、8、9、13、15、16 课的检查与反馈。
- 反馈必须留下记录，但反馈者不替代作者修改。
- 高计算量项目若申请双人协作，应分别提交个人研究判断、个人 Agent Workflow、AI 使用记录和反思；是否批准由教师在问题门前确认。

## 四、逐课备课

## 第 1 课｜AI 辅助科研导论、OpenCode 与八阶段研究链路

教学目标：

- 区分“生成一份报告”和“完成可审查的科研闭环”。
- 能用八阶段研究链路与四个研究门定位一次研究判断，而不是只背诵名称。
- 启动个人 OpenCode 工作区，完成最小可审计交互。

90 分钟建议：

| 时间 | 活动 |
| --- | --- |
| 0-6 | 开场诊断：一份看似完整的 AI 研究输出，为什么仍不能提交 |
| 6-14 | 课程契约：个人项目、四次正式提交、同伴反馈与责任边界 |
| 14-26 | 用同一条研究主张定位八阶段链路与四个研究门 |
| 26-43 | 教师演示：AI 提建议，研究者核验并只写回一处，保留 diff 与日志 |
| 43-48 | 发放练习任务、确认工作区与备用路径 |
| 48-75 | 个人实践：完成一次可审计交互并记录人工判断 |
| 75-85 | 同伴互查：能否从工件复原“建议—判断—修改” |
| 85-90 | 退出卡与下一课衔接 |

课堂最小产出：个人工作区；`problem-definition.md` 中一处经人工确认的修改；`ai-usage-log.md` 一条记录；对应 diff；一张只标当前不确定位置的八阶段链路草图。不得要求首课填满整套模板。
课后推进：完善初步问题，不正式提交。

## 第 2 课｜科研伦理、Agent 权限、研究工件与追踪

教学目标：

- 能识别数据、引用、署名、隐私、双重用途和 AI 使用风险。
- 能写出 Agent 权限矩阵与人工确认点。
- 理解 `draft → review → approved → stable` 的用途。

核心活动：

- 使用本课一份未公开协作草稿案例，先按学校规范判断可否使用 AI，再写成任务级边界。
- 对同一任务比较过宽权限和最小权限配置，确定人工确认点。
- 在已有 `ai-usage-log.md` 上补一条披露记录，并完成风险卡与权限矩阵的最小行。

规范映射：以上海交通大学《关于在教育教学中使用 AI 的规范》为最近制度基线。校级“禁止、限制、鼓励、开放”是场景治理分类；本课任务级矩阵使用“禁止、有条件允许、允许”，其中“限制”落为“有条件允许”，“鼓励/开放”仍须服从材料授权、课程要求和披露责任。原文入口见 [上海交通大学正式文件](https://soo.sjtu.edu.cn/upload/file/20250217/20250217162021.pdf)，授课前复核是否有修订。

90 分钟建议：

| 时间 | 活动 |
| --- | --- |
| 0-5 | 回看第 1 课 diff/log：哪些事实还无法从记录判断 |
| 5-18 | 一个未公开协作草稿案例与学校/科研/发表规范的适用顺序 |
| 18-30 | 完成五字段风险卡：对象、动作、环境、条件、责任人 |
| 30-42 | 把风险判断写成权限矩阵与人工确认点 |
| 42-55 | 教师演示：OpenCode 在最小权限下请求确认、写回并披露 |
| 55-78 | 个人实践：为自己的同一研究动作补齐风险、权限和日志 |
| 78-86 | 同伴互查：规则是否可执行，是否存在默认外发或越权 |
| 86-90 | 退出卡与后续项目回写 |

强调：未公开材料、学生资料和敏感数据不得默认发送给外部模型；Agent 不得自行扩大访问范围、修改评价协议或删除失败记录。

课堂最小产出：风险卡一张、权限矩阵一行、AI 使用记录一条。完整伦理清单和工件状态追踪只在课堂启动，不要求当场填满。
课后推进：根据选题补全风险边界，不正式提交。

## 第 3 课｜文献检索与证据角色

教学目标：

- 从研究问题生成可复盘的关键词、检索式和筛选条件。
- 区分主证据、补充证据、对比证据与探索线索。
- 回到原始来源核验 AI 检索结果。

核心活动：

- 从一个宽泛主题逐步构造检索式。
- 对同一问题的 AI 综合报告和原始论文列表做来源审计。
- 学生为自己的项目建立候选文献表和纳入/排除理由。

90 分钟建议：

| 时间 | 活动 | 形式 | 产出 |
| --- | --- | --- | --- |
| 0-5 | 回扣第 2 课：受限交互之后，研究材料为何仍不可信 | 讲授 | 检索方法入口 |
| 5-10 | 本课目标与"搜得多"≠证据充分 | 讲授 | 目标共识 |
| 10-27 | 方法：外部输入类型、关键词、检索式、纳入排除、证据角色四类 | 讲授 | 检索与角色框架 |
| 27-43 | 教师演示：检索式 + 来源审计 + 候选文献表 + 判断点 | 演示 | 可复盘 trace |
| 43-48 | 实践说明：任务、模板与备用路径 | 讲授 | 选择问题进入实践 |
| 48-75 | 个人实践：检索式、来源审计、候选文献表第一版 | 个人实践 | 候选文献表初稿 |
| 75-85 | 两人互查：检索可复盘、角色清楚、AI 回原文 | 同伴互查 | 反馈记录 |
| 85-90 | 退出卡与第 4 课预告 | 回写 | 卡点与需求 |

课堂产出：检索记录、候选文献表、证据角色初标。
课后推进：继续筛选和回源，不正式提交。

## 第 4 课｜AI 辅助精读与主张核验

教学目标：

- 提取论文的问题、方法、设置、结果、局限和可复现信息。
- 识别 AI 错读、过度概括和伪造引用。
- 建立“原文位置—主张—人工判断”的追踪关系。

核心活动：

- 教师示范一次结构化精读。
- 学生审计一份故意含错误的 AI 摘要。
- 为关键论文建立阅读卡，记录页码、图表或章节位置。

90 分钟建议：

| 时间 | 活动 | 形式 | 产出 |
| --- | --- | --- | --- |
| 0-5 | 回扣第 3 课：verified 之后，"已读"仍未核验 | 讲授 | 精读方法入口 |
| 5-10 | 本课目标与"读懂摘要但误解贡献" | 讲授 | 目标共识 |
| 10-27 | 方法：五步流程 + 主张核验五项 + 阅读卡字段 | 讲授 | 精读与核验框架 |
| 27-43 | 教师演示：AI 导航 + 原文核验 + 偏差审计 + 阅读卡 | 演示 | 可复盘 trace |
| 43-48 | 实践说明：任务、模板与备用路径 | 讲授 | 选择论文进入实践 |
| 48-75 | 个人实践：五步流程、阅读卡第一版、偏差审计表 | 个人实践 | 阅读卡初稿 |
| 75-85 | 两人互查：主张有位置、AI 与原文分栏、偏差审计有记录 | 同伴互查 | 反馈记录 |
| 85-90 | 退出卡与第 5 课预告 | 回写 | 卡点与需求 |

课堂最低产出：至少 1 张完整阅读卡、一条偏差审计记录和一条 AI 使用记录。
课后推进：扩展关键论文阅读，第 6 课问题门前累计至少 3 张完整精读卡；不逐周正式提交。

## 第 5 课｜综述结构、证据地图与研究空白

教学目标：

- 从摘要堆叠转向按冲突、条件和机制组织综述。
- 区分问题的多条生成路径，识别冲突空白、缺角空白和新问题空白，并从多条路径生成候选题池（≥3 候选题、覆盖 ≥2 条路径、含 ≥1 个非文献空白路径候选；当堂记候选题与路径标签，完整题池第 6 课前补齐）。
- 说明现有证据支持什么、不能支持什么。

核心活动：

- 将五篇文献从”按论文排列”重组为”按研究问题排列”。
- 绘制证据地图，显式保留冲突和缺失证据。
- 对问题门材料做第一次同伴诊断。

90 分钟建议：

| 时间 | 活动 | 形式 | 产出 |
| --- | --- | --- | --- |
| 0-5 | 回扣第 4 课：阅读卡完成后，为什么仍不算综述 | 讲授 | 综述方法入口 |
| 5-10 | 本课目标与”摘要堆叠”为何不算综述 | 讲授 | 目标共识 |
| 10-28 | 方法：叙事性 vs 系统性综述、相关工作矩阵、证据地图四类、研究空白三类、三步检验、问题生成路径与候选题池、AI 综述核验清单 | 讲授 | 综述与地图框架 |
| 28-43 | 教师演示：阅读卡 → 矩阵 → 证据地图 → 空白候选 → 三步检验 → 候选题记录 → AI 综述核验 | 演示 | 可复盘 trace |
| 43-48 | 实践说明：任务、模板与备用路径 | 讲授 | 进入个人实践 |
| 48-75 | 个人实践：构造矩阵、证据地图、空白候选、AI 综述核验 | 个人实践 | 证据地图初版 |
| 75-85 | 两人互查：按问题组织、冲突保留、空白经三步检验 | 同伴互查 | 反馈记录 |

| P1 | 写作与评审包 | 14-16 | 证据断裂反例、追踪表、评审表、展示 rubric |
| P2 | 延伸案例包 | 1、5、11、12 | Deep Research/STORM、AutoResearch、AI Scientist 等对比材料 |

正式讲义应面向学生并可独立阅读，包含方法解释、完整案例、与课堂或个人项目直接相关的练习、术语与来源入口，不固定设置课后自测。课后学习只有在直接服务下一课、个人项目或研究门时才设置，并明确核心/任选、预计时间、产出位置和是否提交。教师教案负责 90 分钟教学组织。正式 PPT 以中文为主，可保留必要英文术语、论文标题和工具名；它应在内容、节奏和映射三道启动门通过后从正式讲义与教案提炼，而不是复制或改名试讲 PPT。每份 PPT 制作后需渲染检查，并同时准备课堂练习的可编辑版本。

参考材料进入课堂前按角色登记：研究论文、正式规范、新闻/评论/Careers feature、产品或项目文档不得混用证据强度。例如 [Nature Careers 的 AI 工具指南](../references/library/papers/d41586-025-01069-0.pdf) 只用作 2025 年工具生态快照和“如何选择工具”的课堂案例；它不是同行评议研究证据，也不能直接作为 2026 年工具推荐清单。

## 六、双引擎备课协作

教师可使用 Claude Code 与 Codex 双引擎，但每个工作包只能有一个主笔：

1. 主笔读取 `AGENTS.md` 和规范课程文件，完成初稿与自检。
2. 另一引擎按事实准确性、教学节奏、跨文档一致性、可执行性和表述口吻审阅。表述口吻维按 [review-checklist.md](./review-checklist.md) 逐项核对，重点去除 AI 生成痕迹（对仗句式过密、meta 自白、机械编号、标题腔），同时保留课程固有的结构化术语和限定式风格。
3. 主笔处理反馈并运行检查；两者不并发修改同一文件。
4. 重要来源、时间敏感信息和 PPT 渲染结果由人工最终确认。

建议按“课程起步、文献证据、问题假设、实验工程、Agent Workflow、写作评审”拆分工作包，而不是按工具或模型拆分。

## 八、主要风险与预案

| 风险 | 预案 |
| --- | --- |
| OpenCode 安装或后端不可用 | 课前环境检查；准备远程/浏览器替代和录屏；不把排障计入学习目标 |
| 学生把课程理解为工具或 Prompt 课 | 每个案例必须映射到研究链路、工件、证据和人工判断 |
| Skills 演示变成照抄配置 | 要求反向分析设计逻辑，并为个人科研动作重新定义任务契约和评价 |
| 个人项目负担过大 | 正式提交限制为四次；第 8、15 课提供反馈但不新增作业 |
| 同伴组变成隐性小组作业 | 每人独立仓库和答辩；反馈留痕，作者独立决定和修改 |
| Agent 权限过宽或泄露敏感数据 | 默认最小权限；敏感目录禁止访问；外部发送和执行动作设人工确认 |
| 自动化只保留成功结果 | 固定评价协议、预算和停止条件；失败日志是验证门必查材料 |
| AI 生成文本掩盖证据缺口 | 关键结论绑定直接证据和上游决定；抽查原文、实验 ID 或 trace |
| 第 16 课分享时间不足 | 根据选课人数采用分会场、海报/演示轮转或课前短视频；论证门标准不变 |

## 九、完成标准

备课进入可授课状态需同时满足：

- 16 次课均有可独立阅读的学生正式讲义。
- 16 次课均有教师教案、中文正式课堂 PPT、课堂练习和退出卡；试讲材料不计入这一完成度。
- 四门检查表、评分 rubric、第 8 课分享表和第 15 课同行评审表可直接使用。
- OpenCode 最小演示和备用路径已实测。
- 课程设计、备课规划、项目模板、申请表中英文概要和考核口径一致。
- 每课只有一套现行内容母稿；历史稿、试讲稿和视觉试制稿不会参与正式制作链。
- 90 分钟流程逐段可执行且合计准确，课堂最小产出与第一次学生动手时间明确。
- 所有规范、论文、新闻/评论和产品文档均按来源角色使用，不以二手整理或期刊品牌代替证据判断。
- 所有交付文件完成链接、内容和视觉检查。

## 十、备课案例池

> 本段承接 `course/resources.md` 精简后移出的教师备课内容，不发布到学生站点，仅供授课准备。

### 备课清单

授课前建议准备：

- 一个小型、可在课堂演示的 ML 任务
- 一个带有明显局限的 baseline
- 一组可快速运行的实验配置
- 一个 AI 错误总结或错误代码示例
- 一个正确但不充分的实验结论示例
- 一个含有编造引用或错误归因的负面案例
- 一个数据隐私、版权许可或 AI 使用披露不充分的伦理案例

### 推荐课堂案例

适合选择满足以下条件的案例：

- 数据公开、规模小、运行成本低
- baseline 简单，学生容易复现
- 结果存在可分析错误，而不是单纯追求高分
- 能设计消融或对照
- 适合展示 AI 辅助但不能完全自动化的科研判断

可选案例类型：

- 文本分类或信息抽取小任务
- 小规模检索增强生成评估
- 表格数据分类或回归
- 轻量图像分类
- LLM 输出评价或提示词鲁棒性实验
