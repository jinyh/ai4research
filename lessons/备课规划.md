## 一、执行原则

1. 课程主线是八阶段研究链路，不是 AI 工具清单。
2. Pi Agent 从第 1 课起作为主要课堂工作平台，但不限制模型或后端，也不因平台选择加分。
3. 不以安装、记忆或调用现成 Skills 为教学目标。案例用于分析任务契约、Context、Memory、工具与权限、状态与工件、执行循环、Evals、人工审核点和失败恢复。
4. 每位学生独立维护项目仓库、证据、判断、实验、个人 Agent Workflow、AI 使用记录和反思。
5. 个人项目、研究判断与评分均由个人承担；讨论、自愿协作和同伴评审可以提供外部信息，不设置固定配对、固定小组或相互签认条件。
6. 正式提交只有四次：第 6、9、13、16 课。第 8 课分享和第 15 课预检是形成性活动，不增加正式作业。
7. AI 可以检索、分析、生成、执行、评审和提出改进。输出的研究地位按用途判断：AI 行为可作为被研究对象的数据，AI 生成的事实主张须回到来源或运行证据核验；关键结论至少绑定一项可核验的直接证据或实验结果及上游决定，`stable` 结论原则上有两项相互独立的证据。
8. 伦理、权限、可追溯性、失败记录和人工核验贯穿所有课次。
9. “第一性原理分析”只指识别问题的基本约束、作用机制和不可违背条件，并由此推导待验证前提；它不是脱离文献、数据和既有工作的通用捷径，推导结果必须继续接受外部证据检验。
10. 来源的载体级别与论证角色分开判断：研究论文可支持研究主张，正式规范可支持行为边界，新闻、评论与 Careers feature 只用于背景、案例或线索，产品文档只支持经核验的产品行为。
11. 涉及课程中的 AI 使用边界时，先以学校当前正式规范为最近制度基线，再按任务补充国家/学会规范、出版或会议政策及服务条款；二手整理不能替代正式原文。
12. 处理未发表教学素材的任何环节（脱敏、制图、润色）不得送入外部 LLM 或在线服务；脱敏由教师人工执行、用户复核后入库。
13. 每课明确区分三层要求：课堂只完成可在当前时段内观察和反馈的最低闭环；课后只补全直接服务下一课或研究门的现有项目工件；研究门按 `course/assignments.md` 检查完整条件。课堂最低产出不得被写成新的正式提交，研究门完整条件也不得全部塞入一次课堂练习。

### 第 7-16 课虚构学生练习案例口径

第 7-16 课的虚构阅读卡案例使用同一套教学规格；真实 MI 案例继续用于教师演示，两条案例线不得混写。

- **任务与对照**：同一批 20 篇公开计算机论文分别进入结构化阅读卡条件和自由摘要条件；同论文配对比较，模型版本、解码参数、最大输出长度、论文版本和评价协议保持一致。
- **运行规模**：每篇论文、每个条件运行 3 次，共 `20 篇 × 2 条件 × 3 次 = 120 次输出`。这是虚构教学规格，不冒充真实实验结果；课堂只运行或检查足以走通方法链的子集。
- **主指标**：限定条件遗漏率 = 相对于人工建立并经复核的限定条件基准，摘要遗漏的限定条件数 / 该论文应保留的限定条件数。指标需要人工基准标注和盲评，不得简化成“缺失字段数 / 5”。
- **假设编号**：H1=阅读卡字段约束使限定条件更易被保留和核验；A1=任务转移，限定条件遗漏下降但其他错读上升、总错读未改善；A2=标注提示效应，差异来自评价者看到字段提示；A3=文档结构效应，效果只出现在特定论文结构，不能外推。
- **结果解释**：统一写“支持／反驳／仍不能判断”，并报告估计差异、不确定性和适用边界。未达到统计显著不得直接写成“机制不成立”；证据不足、噪声过大或替代解释未排除时写“仍不能判断”。
- **结果样例**：`0.18±0.03` 与 `0.31±0.04` 仅作为虚构教学数据，表示 3 次运行的汇总示例。它可以说明方向与 H1 一致，但在 A1/A2/A3 未排除时不能标记为 `stable`。

### 前两课整改原则

前两课只建立一个连续闭环，不并列铺开全部课程概念：第 1 课让学生完成一次“AI 建议 → 人工判断 → 有限写回 → 留下 diff/log”的可观察操作；第 2 课在同一个操作上补写材料边界、权限和披露要求。八阶段链路与四个研究门用于定位这次操作，不要求首课背诵完整术语或一次填满所有工件。

### PPT 启动门

前两课进入新一轮 PPT 制作前，依次满足：

1. 内容门：讲义、教案、逐页内容母稿、课程规则和来源角色已对齐，只有一套现行口径。
2. 节奏门：完成 90 分钟桌面推演，各段只以整数时长呈现且合计恰好 90 分钟，个人实践每段 ≤15 分钟（超出拆两段并插教师中点点评），学生第一次动手的距开课时长和最小课堂产出明确。
3. 映射门：每页先写清页面任务、对应内容母稿位置、证据角色和预期学生动作，再决定版式。
4. 视觉门：前三门通过后才制作 PPTX；交大样例只提供品牌元素与版式线索，不被当作完整设计系统。

上述启动门继续作为修订既有 PPTX 的强制顺序。当前 16 课均已有可编辑 PPT；课程 2.0 后续批次若改变内容或逐页母稿，须按 `prepare-course-lesson` 的修订流程重走受影响门控，不能以既有 PPT 已完成为由跳过。

## 第 12 课｜Agent/Skill 背后的逻辑与个人工作流设计

**2026-10-12 核心判断：**这个任务需要 Agent 自主选择吗？ [学生任务](./lesson-12/judgment-task.md)。 本人迁移：在个人副本接入 L10 校验，或增加分组盲化/任务状态持久化等一个实质环节。对真实输入走通输入→处理→人工检查→评价 trace；输出标明 accepted/rejected 与理由，正常项守恒。


教学目标：

- 能从现成 Agent/Skill 中抽取可迁移的设计逻辑。
- 能说明何时用确定性脚本、workflow、单 Agent 或更复杂系统。
- 完成个人 Agent Workflow 的设计与最小实现。

分析框架：

| 维度 | 核心问题 |
| --- | --- |
| 任务契约 | 输入、输出、成功标准和不适用范围是什么？ |
| Context | 使用哪些材料、论文、代码、数据和项目工件？ |
| Memory / 状态 | 哪些信息跨步骤保留，保存在哪里？如何写回可审计工件？ |
| 工具与权限 | 能读、写、执行和联网到什么范围？ |
| 执行循环 | 如何计划、行动、观察、评价和停止？ |
| 工件与追踪 | 输入、日志、输出和上游决定如何关联？ |
| Evals 与人工审核 | 与什么 baseline 比、用什么指标或 rubric？哪些判断和外部动作必须确认？ |
| 失败恢复 | 超时、无效输出、工具失败或越权时怎么办？ |

90 分钟安排以 [本课教案](./lesson-12/teaching-plan.md) 与逐页母稿首页路由为准。

课堂产出：个人 Agent Workflow 说明、可运行或可演示原型、评价计划。
课后推进：执行评价并记录至少一个失败或局限，不正式提交。

## 第 13 课｜工作流评价、结果分析、失败审计与验证门

**2026-10-12 核心判断：**总均值较好是否足以采用改动？ [学生任务](./lesson-13/judgment-task.md)。 本人迁移：在同一输入上比较 baseline 与实质修改版，分别报告正确处理、误拒、失败和成本；实际执行证据与构造输出分开。给出结论强度与一项采用/修订/停止决定。


教学目标：

- 评价工作流是否改善目标科研动作，而不只是“能够运行”。
- 将实验结果映射回假设、判断和证据。
- 完成失败分析、有效性威胁和验证门提交。

评价至少选择适合项目的维度：

- 正确性与可追溯性
- 时间或成本
- 失败率
- 人工修订量
- 权限越界或风险
- 相对 baseline 的改善

90 分钟安排以 [本课教案](./lesson-13/teaching-plan.md) 与逐页母稿首页路由为准。

正式提交 3：验证门材料，包含个人 Agent Workflow 的运行、评价和失败记录。

## 第 14 课｜论文式写作、证据回写与 AI 使用披露

**2026-10-12 核心判断：**哪种写法与当前证据相称？ [学生任务](./lesson-14/judgment-task.md)。 本人迁移：用本人真实比较写一个论证段，附一条结论追踪和实际 AI 披露；把已积累的问题、方法、评价、局限直接组织成短报告初稿。


教学目标：

- 形成“主张—证据—推理—边界”的论证结构。
- 将验证结果回写到研究判断和证据地图。
- 正确披露 AI 对检索、代码、实验和写作的参与。

核心活动：

- 审计一段流畅但证据断裂的 AI 文本。
- 用证据编号和实验 ID 重写摘要或结果段。
- 检查 `stable` 结论的独立证据与限制说明。

90 分钟安排以 [本课教案](./lesson-14/teaching-plan.md) 与逐页母稿首页路由为准。

课堂产出：论文式短文初版、结论追踪表、AI 使用披露。
课后推进：准备同行评审，不正式提交。

## 第 15 课｜同行评审、论证门预检与修改

**2026-10-14 核心判断：**这条评审意见指向的证据是否成立，先处理哪项会改变论证？[学生任务](./lesson-15/judgment-task.md)。本人迁移：每人独立评审分配的一份匿名稿件；由教师进行非互惠分配并转交意见，作者对实际收到的意见作出决定并完成相称回应。


教学目标：

- 按统一 rubric 检查论证链、可复现性、工作流评价和伦理边界。
- 区分致命问题、重要问题和表达建议。
- 形成具体修改清单和回应。

90 分钟安排以 [本课教案](./lesson-15/teaching-plan.md) 与逐页母稿首页路由为准。

课堂产出：个人评审表、作者回应、实际修改与论证门预检；缺少外部反馈时由教师／助教补充，不建立固定互评关系。
本课不正式提交，论证门与期末项目合并到第 16 课。

## 第 16 课｜学生最终分享、论证门与期末项目

**2026-10-14 核心判断：**展示结论能一路反查到什么？新条件怎样改变判断？[学生任务](./lesson-16/judgment-task.md)。本人迁移：全员 2 分钟个人展示后独立完成证据反查与新条件书面题；教师抽查部分学生口头解释。教师抽查和全员书面证据分别记录。


教学目标：

- 用可核验证据回答研究问题并说明边界。
- 展示个人 Agent Workflow 的实际作用、失败和本人采用理由。
- 完成论证门和期末项目合并提交。

展示必须回答：

1. 研究问题和关键判断是什么？
2. 哪些证据或实验支持、反驳或尚不能判断？
3. 个人 Agent Workflow 改善了哪个科研动作，如何评价？
4. AI 在哪里有效、哪里误导、如何核验？
5. 当前结论的适用边界与下一步是什么？

90 分钟安排以 [本课教案](./lesson-16/teaching-plan.md) 与逐页母稿首页路由为准。

正式提交 4：论证门 + 期末个人项目。全员完成书面迁移检验，教师可抽查一次复现、一个引用或一条工作流 trace。

## 六、多引擎备课协作

教师可使用 Claude Code、Codex、OpenCode 或其他受控工具，但每个工作包只能有一个主笔：

1. 主笔读取 `AGENTS.md` 和规范课程文件，完成初稿与自检。
2. 复核引擎按事实准确性、教学节奏、跨文档一致性、可执行性和表述口吻审阅，并使用 [review-checklist.md](./review-checklist.md) 的通用核心与适用条件模块。
3. 事实、路径、版本和可复现的客观错误可由 AI 在明确文件边界内直接修复并登记；教学取舍、规范解释、授权和正式通过进入教师复核台账。多个引擎不并发修改同一文件。
4. 重要来源、时间敏感信息和 PPT 渲染结果由人工最终确认。

建议按“课程起步、文献证据、问题假设、实验工程、Agent Workflow、写作评审”拆分工作包，而不是按工具或模型拆分。

全课程教师复核统一使用 [teacher-review-ledger.md](./teacher-review-ledger.md)，顺序固定为 L2 → L4-L6 → L7-L9 → L10-L13 → L14-L16 → L1/L3 回归；AI 先审并修客观项，教学取舍、授权边界与正式通过由教师确认。

## 八、主要风险与预案

| 风险 | 预案 |
| --- | --- |
| Pi Agent 安装或后端不可用 | 课前环境检查；准备远程/浏览器替代和录屏；不把排障计入学习目标 |
| 学生把课程理解为工具或 Prompt 课 | 每个案例必须映射到研究链路、工件、证据和人工判断 |
| Skills 演示变成照抄配置 | 要求反向分析设计逻辑，并为个人科研动作重新定义任务契约和评价 |
| 个人项目负担过大 | 正式提交限制为四次；第 8、15 课提供反馈但不新增作业 |
| 同伴组变成隐性小组作业 | 每人独立仓库和答辩；反馈留痕，作者独立决定和修改 |
| Agent 权限过宽或泄露敏感数据 | 默认最小权限；敏感目录禁止访问；外部发送和执行动作设人工确认 |
| 自动化只保留成功结果 | 固定评价协议、预算和停止条件；失败日志是验证门必查材料 |
| AI 生成文本掩盖证据缺口 | 关键结论绑定直接证据和上游决定；抽查原文、实验 ID 或 trace |
| 第 16 课分享时间不足 | 根据选课人数采用分会场、海报/演示轮转或课前短视频；论证门标准不变 |

## 十、备课案例池

> 本段承接 `course/resources.md` 精简后移出的教师备课内容，不发布到学生站点，仅供授课准备。

### 备课清单

授课前建议准备：

- 一个小型、可在课堂演示的 ML 任务
- 一个带有明显局限的 baseline
- 一组可快速运行的实验配置
- 一个 AI 错误总结或错误代码示例
- 一个正确但不充分的实验结论示例
- 一个含有编造引用或错误归因的负面案例
- 一个数据隐私、版权许可或 AI 使用披露不充分的伦理案例

### 推荐课堂案例

适合选择满足以下条件的案例：

- 数据公开、规模小、运行成本低
- baseline 简单，学生容易复现
- 结果存在可分析错误，而不是单纯追求高分
- 能设计消融或对照
- 适合展示 AI 辅助但不能完全自动化的科研判断

可选案例类型：

- 文本分类或信息抽取小任务
- 小规模检索增强生成评估
- 表格数据分类或回归
- 轻量图像分类
- LLM 输出评价或提示词鲁棒性实验

### Agent harness 对照案例（2026-08-12 增补，教师专用）

Pi Agent 是主要课堂平台，第 12 课进一步作结构拆解；Prime Agent 供第 11 课分析，**不进学生必装清单**；完整对照表、钉死版本、证据分级与待核验清单见 `references/notes/pi-and-prime-agent.md`。

- **Pi Coding Agent**（pi.dev，`earendil-works/pi`，钉 commit `9795d602`）：第 12 课八要素拆解的最小对照组——默认仅 read/write/edit/bash 四工具，权限与计划/子 Agent 刻意移出核心，与 OpenCode 的显性权限配置对照。源码本地快照可参考 handsonlab 仓库 `raw/框架/pi/`（2026-05-26 快照，仅供讲师查阅）。
- **Prime Agent**（PrimeIntellect，钉 commit `965941c7`）：第 11 课四约束与停止条件的对照案例簇——`/autonomous` 预算与质量门（官方自述"通过门只证明该门所验证的内容"）、Continual Harness 状态持久化；配两篇预印本（arXiv:2605.09998、arXiv:2512.24601），只作分析对象，不外推能力结论。
- **演示隔离要求**：任何实机演示必须在容器或一次性隔离环境中进行，不在备课机直接安装（其安装方式为 curl|sh 且以用户权限执行模型生成代码，官方自述非安全沙箱）；演示记录写入 AI 使用记录与权限矩阵。
- **回退预案**：国内可用性核验不过或仓库剧变时，演示降级为纯文档/源码拆解（对照笔记 §3 对照表与 §6 映射表可独立支撑）；课程材料不随仓库后续变化漂移。
