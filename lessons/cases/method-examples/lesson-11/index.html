    L11 按需方法案例输入¶

    身份：保留的教学构造或具名来源分析；按各段说明区分。它不是学生的默认个人项目，也不要求跨课连续完成。以下保留原案例叙述；其中跨课措辞描述该构造包的历史关系，不规定当前课堂进度。

    六、方法示例：把可重复动作改写为受限循环¶

    使用可复演小包。固定任务是回放三份构造源文本的两条件输出，共六项；输出来自预制素材，无模型调用。真实项目可把回放步骤替换成受限生成，但须重新记录版本、配置与评价。

    1. 两种循环分别看¶

    固定队列保持方法与输入规则，收集全部输出；优化循环改变候选方法，并依据开发评价作保留决定。两者都保留失败，优化还须规定搜索空间与总预算。本课主演为固定队列。

    2. 固定约束¶

    • 指标：人工基准限定条件遗漏率，生成/回放端不参与打分。
    • 预算：六项任务，最多八次尝试；恢复也计入尝试。
    • 停止：完成六项或达到尝试上限；输入改变必须另建版本。
    • 恢复：第一次人为注入的 T02-card 技术失败保留；人工查看后重放未完成项，使用新 run ID。

    3. 从事件到账本¶

    events.jsonl 逐项保留 attempt_started、controlled_failure、replayed 等事件，state.json 指出已完成项与下一动作。恢复不删除原失败，也不重复记已完成成功项。

    4. 技术失败与评价结果¶

    完成六项后，T01 改善、T02 无改善、T03 为负例。技术失败属于一次执行事件；无改善与负例属于输出评价，不能靠重新运行或删掉输入消除。在这个阅读卡构造例中，Q1 指“结构化摘要是否减少遗漏”，只在部分输入上方向一致；H1/A2 指约束格式是否通过注意关键条件发挥作用，现有输出不能区分提示内容和格式的作用；A1 指核验负担是否下降，未测时间故不能评价；A3 指能否迁移到其他论文类型，当前三段输入不足以支持。这里的编号只属于阅读卡案例，不沿用 RSI 选优模拟的编号。

    5. 课堂到项目¶

    先完成一条有状态的执行与恢复说明，并能复原三类记录。借用教师包时标记使用素材及回放身份，个人项目仍缺的运行入口或评价数据写入既有离场卡，课后补到本人项目。

    固定池选优的历史观察¶

    身份：既有合成环境的实际CPU运行，原始数据与运行器保持原位。本段由方法讲义移入，未新增研究运行。

    固定指标与选择误差¶

    协议没有漂移，反复选优也可能使历史最佳分数过于乐观。RSI 实际 CPU 案例在所有候选真实成功率均为 0.65 的条件下，历史选优 K=64 的平均乐观偏差为 0.1882，独立最终成功率为 0.6508；参考选择损失为零。数值来自合成环境实际运行，不是 Dream-RSI 或工业任务的表现。

    这里没有偷换指标、删除失败或越过预算。需要补上的约束是：声明选择反馈和最终评价的角色，冻结候选后再揭示最终证据，最终结果不得继续驱动本轮优化。独立均匀验证与等预算随机验证都参与候选选择，其结论仍由单列的最终评价检查。

    检查图表时分别回答：历史分数是否乐观？是否真的选错？哪份证据参与选择？资源是否相同？四个问题不能只用一条 Keep/Discard 记录代替。完整日志与固定指标使过程可追踪，独立最终评价支撑结论。系统短分析保留四约束与人工判断边界，完整比较材料仍为按需参考。

    理解这个现象可以先写“观察分数＝候选实际表现＋本次评价误差”。在许多候选中选择最大观察值，也会偏向有利误差。上面的同质候选没有真实优劣，历史分数升高仍可能只是选中了高估；异质候选则还需问是否真的选错。这个分解是教学解释，具体数值来自链接内的合成实验。

    方法依据：Cawley & Talbot (2010), On Over-fitting in Model Selection and Subsequent Selection Bias in Performance Evaluation，摘要与模型选择讨论。有限样本上的选择准则也可能被过拟合；本课将此用于解释 RSI 教学模拟，不把模拟数值外推到真实 Agent。

    系统分析资料（按需查阅）¶

    本节用第 12 课的 Agent Workflow 八部分框架拆解两类系统。它们是分析对象，不是结论外推的依据——分析目的是看清每个维度上"哪些已由系统处理、哪些仍需人工判断"，而不是断言"AI 已能自主科研"。

    1. 两个分析对象¶

    系统 一句话描述 在本课的角色
    AI Scientist（Lu et al., Nature 2026） 端到端自动化 AI 研究：想法→代码→实验→分析→论文→审稿 端到端自动化的边界案例
    AutoResearch（Karpathy） 单次训练限时、固定指标、保留/丢弃与日志的工程循环 受限循环的最小骨架

    来源参考：Lu, C. et al. "Towards end-to-end automation of AI research." Nature (2026). DOI: 10.1038/s41586-026-10265-5。用途：分析端到端自动化的任务范围、评价证据和仍需人工判断的边界。不外推为通用自主科研能力——论文报告的是特定机器学习研究设置下的系统表现；三篇送审稿中一篇评分超过工作坊平均接收阈值，但按预设协议在审后撤回；该工作坊接收率为 70%，研究团队内部判断三篇均未达到 ICLR 主会标准。这不等于顶会正式接收，也不适用于所有学科。

    来源参考：Karpathy. AutoResearch（commit 228791f）。用途：分析固定时间预算、固定 val_bpb 评价、keep/discard/crash 日志和回退的最小循环骨架。它是 2026 年工程案例，不是经典理论，也不证明通用自主科研能力。

    该系统的工件分析绑定该 commit 的 program.md，只摘出可核对字段：仅修改 train.py、单次固定时间预算、以 val_bpb 为评价指标，并记录 keep / discard / crash。这是源文档字段的课堂重绘，不是系统运行截图或实验结果。

    2. 八维框架拆解¶

    维度 AI Scientist（Lu et al. 2026） AutoResearch（Karpathy） 仍需人工判断的部分
    任务契约 系统自带任务模板（生成想法→跑实验→写论文）；输入是开放的研究主题 任务由用户写明（program.md），输入是具体研究动作 主题是否值得研究、范围是否合理、非例是否清晰
    Context / Memory 系统维护 idea archive、实验结果、论文草稿的上下文 启动步骤指定README、prepare.py与train.py等范围内文件 哪些材料应进入 Context、敏感数据是否被排除
    工具与权限 系统调用 Python 执行、文件写入、网络检索；权限范围由系统设计者决定 用户明确只读/可写/可执行范围；单次时限写明，外层总次数与总时长需另加 越权动作如何被识别、外部写入如何被审核
    状态与 Memory 系统跨步骤保留状态；状态结构由系统定义 状态保存在可审查的项目工件和日志中 状态是否被悄悄修改、跨迭代是否一致
    执行循环 端到端串联：想法→代码→实验→分析→论文→审稿 Edit → Evaluate → Keep/Discard → Repeat 循环是否允许修改指标、停止条件是否预先承诺
    工件与追踪 系统产出代码、实验日志、论文稿件、审稿报告 保留所有迭代的日志与 Keep/Discard 决策 失败迭代是否被保留、是否可从工件复原决策
    Evals 与人工审核 系统内置自动评审（AI 审稿）；人工审核在系统之外 评价用预先写明的指标；启动前确认规则；已授权的 Keep/Discard 可自动执行 自动评审是否能替代同行共识、Keep/Discard 是否遵守授权与评价规则
    失败恢复 系统对失败实验有处理逻辑；但选择性保留的风险存在 失败作为循环的一部分被记录；按指标保留或退回候选版本 失败是否被选择性删除、回退是否真的回到稳定状态

    3. 两个边界判断¶

    边界一：端到端自动化 ≠ 通用自主科研。 Lu et al. 2026 报告的是特定机器学习研究设置下的系统表现；三篇送审稿中一篇评分超过工作坊平均接收阈值，但按预设协议撤回，且研究团队判断三篇均未达到 ICLR 主会标准。这不等于"AI 已普遍具备独立科研能力"，也不等于该系统能处理需要专家判断、伦理审查或跨学科证据整合的研究问题。在本课中，它只作为"端到端自动化在哪些维度上仍需人工判断"的分析对象。

    边界二：自动评审 ≠ 同行共识。 AI Scientist 内置的自动评审可以提供问题发现和评价证据，但模型评审不等同于真实同行共识。学生可比较 AI 评审、人类评审和预设评价协议，说明意见的适用范围与处理理由；对外部事实主张仍需追溯原始材料。

    来源参考：Huang, Q. et al. "MLAgentBench: Evaluating Language Agents on Machine Learning Experimentation." ICML 2024, PMLR 235, 20271–20309. PMLR 正式页面。用途：用任务、成功标准、轨迹和失败类型评价 ML 实验 Agent——它提供了评价 Agent 实验轨迹而不仅看最终分数的方法，可用来检查循环是否真的在受限条件下运行。

    4. 不外推清单¶

    本课对 AutoResearch / AI Scientist 的分析不得被改写为以下结论：

    • "AI 已能自主完成科研"；
    • "Agent 工作流可以替代研究判断"；
    • "自动评审可以替代同行评审"；
    • "端到端自动化适用于所有学科"；
    • "失败实验可以被自动删除"。

    这些表述都超出了来源证据的适用范围。任何在作业或 slides 中出现类似表述，都应被标记为越界并改写为带边界的形式。

    5. 同谱系对照案例簇（延伸，仅分析对象）¶

    另一个按固定版本保留的分析对象是 Prime Agent（PrimeIntellect，构建于极简 harness pi 之上）代表另一个值得对照的设计方向：把循环的约束本身做成可持久化的状态——其 /autonomous 模式在 turn/token/time 预算内运行并可配置质量门，官方明确自述"通过一个门只证明该门所验证的内容，到达预算上限不等于任务成功"；其 Continual Harness 机制则尝试让 harness 的补充说明、记忆与子 Agent 规格以证据支撑的小步更新持久化（支撑论文 arXiv:2605.09998 与 arXiv:2512.24601 均为预印本，未经同行评议）。

    用本课四约束审视它：预算与质量门设计可与 讲义第三节 逐项对照，但"通过门 ≠ 任务成功"恰恰说明——无论 harness 多复杂，停止条件的解释权和回退决定仍必须由研究者保留。本课程现有材料未提供该版本的独立复现，因此只把它作为分析对象：钉死版本的 README 见 reading-list.md 第 11 课新增案例条目；不进学生安装清单，不外推为"AI 已能自主科研"的任何变体。

    2026-10-22 原文校准：单次限时与总循环额度¶

    复核上述固定版本的program.md：单次训练固定5分钟，另给单次异常超时处理；外层明确要求持续循环，直到人工停止。因此不能把它描述为已具备有限总次数／总时长的完整课程循环。课程另加总额度、失败计数和最终评价隔离，是课程设计要求。原文件用0作为崩溃指标占位，读表必须同时读crash状态；本课程未知用量仍记为未知，不能抄成零成本。规则声明也不证明系统权限隔离已被验证。
