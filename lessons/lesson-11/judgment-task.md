# 第 11 课共同诊断｜恢复、负结果与停止

## 先独立判断

**问题：应该恢复、回退还是停止，哪些记录必须保留？**

输入：L10 已核准的动作；冻结队列与预算。先记录判断和依据，再与同伴比较；课堂校准后可修订并写明改变原因。答案有分歧时回到具体记录。已有示例可作方法参考，不替代本人的初始判断。

## 原始材料与待比较选项

教学构造运行账本；与可运行回放包的受控失败分支相同类型。

| 尝试 | 任务 | 结果 |
| --- | --- | --- |
| run-001 | T01-card | 成功 |
| run-002 | T01-free | 成功 |
| run-003 | T02-card | 受控 timeout；未完成 |

冻结配置：6 个任务，最多 8 次尝试；已经成功的任务不应重跑。另有已完成评价：T02 两条件相同；T03 阅读卡更差。

同学建议：“换一个随机种子，删掉 T03 和 timeout，只报告历史最佳；这样曲线更稳定。”

**待决定：**为技术失败、无改善和负结果分别选下一动作；若恢复前输入变了怎么办？

把“初始判断—证据位置—仍缺什么—核验后决定”写在现有笔记中。允许回答“仍不能判断”，同时指出下一项能改变判断的证据。

实际实现入口：[个人微型项目](../../course/micro-project.md)，与原回放包服务同一个人项目。

## 迁移到本人项目

在同一微型项目执行 changed.py，使用 execute --fault-once；检查失败后状态，人工批准后恢复，比对 run_id 与完成任务，解释预算耗尽、完成或停止决定。

**验证：**验证中断保留、重启不重复成功任务、输入或实现改变须新建目录。保留无改善和负结果；原阅读卡 replay 仅作相邻示范，权限接口不等于系统隔离。

**保存位置与达标证据：**本人队列运行目录、恢复证据与停止决定。

**下课去向：**L12 以已验证动作设计一个实质工作流环节。

## 完成标准

| 尺度 | 判断依据 |
| --- | --- |
| 需支持 | 完成操作，但理由、证据定位或验证仍有缺口。 |
| 达标 | 独立决定，证据可定位，完成相称验证，并更新本人项目。 |
| 优秀 | 识别替代解释或有效性威胁，以额外检查改变或加强判断。 |

课堂尺度对应课程的待改、达标、卓越；不新增每周成绩或提交。优秀依判断质量，不要求更多课外时长。

断网时保留同样的判断要求，使用包内文本、存档或本地工件。工程课纸面诊断仅作备用练习，最终仍须补本人实际执行、实质修改和对照评价。提前完成者可寻找一个使自己决定改变的反例；不增加课后任务。
