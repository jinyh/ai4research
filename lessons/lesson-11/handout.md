# 第十一讲｜实验自动化与 AutoResearch 循环

## 导读

第 10 课你在受限权限下完成了一次 Agent 辅助代码或调试任务，并留下了 diff、日志和失败记录。"Agent 能跑"和"Agent 能在固定指标、预算和停止条件下被反复运行、被评价、被回退"之间，还有一段距离。这段距离就是本课要处理的实验自动化循环。

本课对应八阶段研究链路的阶段七"原型验证（实验追踪）"，属于"受限 Agent、实验自动化与自主工作流"模块（第 10-13 课）。它的核心转换是：

> 从"Agent 帮我跑通了一次"转向"一个可重复执行的实验机制——固定指标、固定预算、固定停止条件，结果与失败都被追踪，回退路径预先写明"。

本课不是教你复刻 AI Scientist 或 AutoResearch 整套系统。这两个系统是**分析对象**，不是**结论外推的依据**。我们会用第 1 课建立的 Agent Workflow 八部分框架（任务契约 / Context / 工具与权限 / 状态与 Memory / 执行循环 / 工件与追踪 / Evals 与人工审核 / 失败恢复）拆解它们的边界，看清哪些判断仍必须由人作出。第 12 课你将把这些设计要素重新组合成自己的个人工作流。

## 学习目标

完成本讲后，你应该能够：

1. 说明 `Edit → Evaluate → Keep/Discard → Repeat` 循环的适用条件与不适用条件；
2. 为一个自动迭代机制设置固定指标、预算、停止条件和回退机制，并说明为什么这四项缺一不可；
3. 区分"指标可被工作流篡改"与"指标只反映运行结果"两种实现，避免评价协议漂移；
4. 用八维框架拆解 AutoResearch / AI Scientist 一类系统，指出每个维度上"哪些已由系统处理、哪些仍需人工判断"；
5. 写出失败实验的保留规则，避免选择性删除；
6. 把自己一个可重复科研动作改写为受限循环，并标出人工审核点与回退路径。

## 一、实验自动化循环在研究链路中的位置

八阶段研究链路中，阶段七"原型验证"在第 10 课是"起始"（受限 Agent 执行一次），在第 11 课升级为"实验追踪"——不只跑通，而是可重复地跑、可被评价地跑、可被回退地跑。第 13 课将进一步升级为"评价报告"，第 14 课进入回写。

| 输入（来自第 10 课） | 本课处理 | 输出（向第 12-13 课） |
| --- | --- | --- |
| 受限执行记录（diff、日志、越权处理） | 把受限执行扩展为可重复运行的循环 | 可重复执行机制（实验队列或配置扫描） |
| 实验规格（第 9 课七字段 + 停止条件） | 把停止条件落到循环的预算与终止逻辑 | 固定指标 + 预算 + 停止条件 + 回退路径 |
| 任务契约草稿（第 10 课） | 把任务契约升级为"输入/输出/成功标准/不适用范围"四要素 | 可重复执行的受限循环说明 |
| baseline 与可复现说明（第 9 课） | 在循环中保留可复现字段，避免指标漂移 | 指标变化轨迹与失败记录 |

> 与第 1 课的连接：第 1 课 §2.7 已要求"工作流何时停止"——本课把这一要求具体化为循环的预算与停止条件；第 1 课 §2.7 还要求"失败日志是否保留"——本课把失败保留写进循环本身。

本课产出不是论文实验段成稿，也不是验证门材料包（验证门在第 13 课后）。本课只要求学生跑通一次"可重复动作 → 受限循环 → 指标轨迹 → 失败保留"的链路。

## 二、实验自动化循环：假设→运行→度量→评价→回写/回退

### 1. 循环的五步

实验自动化循环不是一个新方法，它只是把研究者手工做的事用受限 Agent 串起来，并在每一步留下可审查的工件：

| 步骤 | 动作 | 必须留下的工件 |
| --- | --- | --- |
| 假设（Edit 前） | 写明本次迭代要验证的子假设、预期方向、何为支持/削弱/推翻 | 假设条目（含对应 H1/A1/A2/A3） |
| 运行 | 在固定配置、固定预算、固定种子下执行 | 运行日志（配置、种子、时长、token/算力消耗） |
| 度量 | 用预先写明的操作定义计算指标 | 指标记录（含分母、分子、缺失处理） |
| 评价 | 对照预先写明的支持/削弱/推翻阈值判断 | 评价记录（含是否触发停止条件） |
| 回写/回退 | 支持则回写到研究判断；不支持或触发停止条件则回退到上一稳定配置 | 决策记录（Keep/Discard + 理由） |

> 关键约束：每一步都不能"事后补"。假设在运行前写明，度量口径在评价前固定，停止条件在循环启动前承诺。任何一个步骤允许事后补写，循环就会退化为"跑到出现有利结果为止"。

### 2. `Edit → Evaluate → Keep/Discard → Repeat` 的适用条件

这个循环并非对所有科研动作都适用。它适用的前提是：

- **可重复运行**：同一配置能在另一台机器上被重新跑出可比结果（沿用第 9 课可复现最小集合）；
- **指标可机器计算**：度量有操作性定义，能由脚本算出一个数，而不是依赖人工主观判断；
- **迭代有界**：预算（时间、token、算力、运行次数）有限，停止条件预先写明；
- **失败可识别**：循环本身能识别"这次运行无效"（如协议错误、数据污染、超时），并把它和"结果不支持假设"区分开。

不适用的情况：

- 研究动作依赖人工判断（如论文阅读质量、伦理审查）——这些动作可以用 Agent 辅助，但不能完全交给循环；
- 指标无法机器计算或需要专家标注才能得到——循环可以跑，但评价必须人工；
- 每次运行成本不可控或不可复现（如调用不可重现的在线服务且不记录版本）。

> 来源参考：Sandve, G. K. et al. "Ten Simple Rules for Reproducible Computational Research." *PLOS Computational Biology* 9(10):e1003285 (2013). DOI: [10.1371/journal.pcbi.1003285](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1003285)。用途：建立结果—脚本—参数—输入—随机种子的可执行追踪链。该文是本课核心阅读。

### 3. 循环与"跑更多次"的区别

循环不等于"把实验跑很多次"。一个公平的循环必须满足：

- 每次迭代的配置变化是预先列出的（配置扫描）或受控的（自动优化有边界），而不是结果不利就随意改；
- 指标的计算口径在所有迭代间一致；
- baseline 与实验组在循环中使用相同的预算和停止条件；
- 失败的迭代不被静默跳过，而是记录为一次 Keep/Discard 决策。

如果循环允许"这次结果不好，换一个指标再算"，它就退化成了隐性 p-hacking（沿用第 9 课 §三·2）。

## 三、固定指标、预算、停止条件与回退机制

实验自动化循环的四项硬约束——固定指标、预算、停止条件、回退机制——是第 9 课停止条件在循环场景下的扩展。缺一项，循环就从"受限执行"退化为"无界搜索"。

### 1. 固定指标

固定指标意味着：指标的计算口径、分母分子、缺失处理、标注协议在循环启动前写明，循环运行期间不可被工作流自身修改。

常见的失败模式：

- 工作流在发现结果不利后"自动尝试下一个指标"——评价协议漂移；
- 工作流在运行中"自动修订 rubric 版本"——baseline 与实验组失去可比性；
- 工作流在数据缺失时"自动跳过该样例"——分母被悄悄缩小。

判断指标是否被篡改的检查：循环运行前后，指标定义文件、rubric 版本号、数据划分是否一致。任何不一致都应触发循环停止并人工审核。

### 2. 预算

预算不是"大概要花多久"，而是预先写明的硬上限。至少包括：

- 时间预算（总时长、单次运行时长上限）；
- 资源预算（token、API 调用次数、算力、存储）；
- 运行次数预算（最大迭代轮数、每组运行次数）；
- 失败预算（连续失败多少次触发停止）。

预算触顶时循环必须停止，而不是"再跑一次说不定就成了"。

### 3. 停止条件

停止条件在第 9 课是"运行次数与停止规则"，在本课扩展为多种触发器：

- **正常停止**：达到预算或完成配置扫描；
- **提前停止（协议性）**：发现数据污染、配置错误、指标定义被修改——这类停止不是因为结果不利，而是因为循环本身出了问题；
- **禁止的停止**：因为当前结果不利就停、因为当前结果有利就停——这构成隐性 p-hacking。

> 与第 1 课 §2.7 的连接：第 1 课把"工作流何时停止"列为原型验证必须回答的问题；本课把它细化为正常/协议性/禁止三类触发器。

### 4. 回退机制

回退是循环在失败或停止后的处理路径。一个完整的回退机制至少回答：

- 回退到哪个稳定配置（最近一次通过人工审核的配置，不是"上一次看起来不错的配置"）；
- 回退后已运行的迭代是否保留（必须保留，作为失败记录）；
- 回退后是否触发研究判断的修订（如原假设是否需要修改、预算是否需要调整）；
- 回退是否需要人工确认（默认需要，因为回退通常意味着循环未按预期推进）。

回退不是"重跑到成功"。回退是"承认这次循环没达成目标，记录原因，回到上一个可审查状态"。

## 四、AutoResearch 元模式与 AI Scientist 案例分析

本节用第 1 课 §四·2 的 Agent Workflow 八部分框架拆解两类系统。**它们是分析对象，不是结论外推的依据**——分析目的是看清每个维度上"哪些已由系统处理、哪些仍需人工判断"，而不是断言"AI 已能自主科研"。

### 1. 两个分析对象

| 系统 | 一句话描述 | 在本课的角色 |
| --- | --- | --- |
| AI Scientist（Lu et al., Nature 2026） | 端到端自动化 AI 研究：想法→代码→实验→分析→论文→审稿 | 端到端自动化的边界案例 |
| AutoResearch（Karpathy） | 固定预算、固定指标、保留/丢弃、留下日志的最小循环 | 受限循环的最小骨架 |

> 来源参考：Lu, C. et al. "Towards end-to-end automation of AI research." *Nature* (2026). DOI: [10.1038/s41586-026-10265-5](https://www.nature.com/articles/s41586-026-10265-5)。用途：分析端到端自动化的任务范围、评价证据和仍需人工判断的边界。**不外推为通用自主科研能力**——论文报告的是特定机器学习研究设置下的系统表现；三篇送审稿中一篇评分超过工作坊平均接收阈值，但按预设协议在审后撤回；该工作坊接收率为 70%，研究团队内部判断三篇均未达到 ICLR 主会标准。这不等于顶会正式接收，也不适用于所有学科。

> 来源参考：Karpathy. [*AutoResearch*（commit `228791f`）](https://github.com/karpathy/autoresearch/tree/228791fb499afffb54b46200aca536f79142f117)。用途：分析固定时间预算、固定 `val_bpb` 评价、`keep/discard/crash` 日志和回退的最小循环骨架。它是 2026 年工程案例，不是经典理论，也不证明通用自主科研能力。

PPT 中的工件视图直接绑定该 commit 的 [`program.md`](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/program.md)，只摘出可核对字段：仅修改 `train.py`、单次固定时间预算、以 `val_bpb` 为评价指标，并记录 `keep / discard / crash`。这是源文档字段的课堂重绘，不是系统运行截图或实验结果。

### 2. 八维框架拆解

| 维度 | AI Scientist（Lu et al. 2026） | AutoResearch（Karpathy） | 仍需人工判断的部分 |
| --- | --- | --- | --- |
| 任务契约 | 系统自带任务模板（生成想法→跑实验→写论文）；输入是开放的研究主题 | 任务由用户写明（program.md），输入是具体研究动作 | 主题是否值得研究、范围是否合理、非例是否清晰 |
| Context / Memory | 系统维护 idea archive、实验结果、论文草稿的上下文 | 用户明确指定 Context（哪些论文、哪些数据、哪些工件） | 哪些材料应进入 Context、敏感数据是否被排除 |
| 工具与权限 | 系统调用 Python 执行、文件写入、网络检索；权限范围由系统设计者决定 | 用户明确只读/可写/可执行范围；预算与停止条件写明 | 越权动作如何被识别、外部写入如何被审核 |
| 状态与 Memory | 系统跨步骤保留状态；状态结构由系统定义 | 状态保存在可审查的项目工件和日志中 | 状态是否被悄悄修改、跨迭代是否一致 |
| 执行循环 | 端到端串联：想法→代码→实验→分析→论文→审稿 | `Edit → Evaluate → Keep/Discard → Repeat` | 循环是否允许修改指标、停止条件是否预先承诺 |
| 工件与追踪 | 系统产出代码、实验日志、论文稿件、审稿报告 | 保留所有迭代的日志与 Keep/Discard 决策 | 失败迭代是否被保留、是否可从工件复原决策 |
| Evals 与人工审核 | 系统内置自动评审（AI 审稿）；人工审核在系统之外 | 评价用预先写明的指标；人工审核在 Keep/Discard 前 | 自动评审是否能替代同行共识、Keep/Discard 是否人工确认 |
| 失败恢复 | 系统对失败实验有处理逻辑；但选择性保留的风险存在 | 失败作为循环的一部分被记录；回退到上一稳定配置 | 失败是否被选择性删除、回退是否真的回到稳定状态 |

### 3. 两个边界判断

**边界一：端到端自动化 ≠ 通用自主科研。** Lu et al. 2026 报告的是特定机器学习研究设置下的系统表现；三篇送审稿中一篇评分超过工作坊平均接收阈值，但按预设协议撤回，且研究团队判断三篇均未达到 ICLR 主会标准。这不等于"AI 已普遍具备独立科研能力"，也不等于该系统能处理需要专家判断、伦理审查或跨学科证据整合的研究问题。在本课中，它只作为"端到端自动化在哪些维度上仍需人工判断"的分析对象。

**边界二：自动评审 ≠ 同行共识。** AI Scientist 内置的自动评审能发现部分问题，但模型评审不等同于真实同行共识。在本课中，自动评审只能作为循环内部的 Evals，不能替代研究判断中的人工审核（沿用第 1 课 §一·2）。

> 来源参考：Huang, Q. et al. "MLAgentBench: Evaluating Language Agents on Machine Learning Experimentation." *ICML 2024*, PMLR 235, 20271–20309. [PMLR 正式页面](https://proceedings.mlr.press/v235/huang24y.html)。用途：用任务、成功标准、轨迹和失败类型评价 ML 实验 Agent——它提供了评价 Agent 实验**轨迹**而不仅看最终分数的方法，可用来检查循环是否真的在受限条件下运行。

### 4. 不外推清单

本课对 AutoResearch / AI Scientist 的分析不得被改写为以下结论：

- "AI 已能自主完成科研"；
- "Agent 工作流可以替代研究判断"；
- "自动评审可以替代同行评审"；
- "端到端自动化适用于所有学科"；
- "失败实验可以被自动删除"。

这些表述都超出了来源证据的适用范围。任何在作业或 slides 中出现类似表述，都应被标记为越界并改写为带边界的形式。

### 5. 同谱系对照案例簇（延伸，仅分析对象）

本课的两个分析对象都来自"固定预算的受限循环"这一谱系。2026 年新出现的 Prime Agent（PrimeIntellect，构建于极简 harness pi 之上）代表另一个值得对照的设计方向：**把循环的约束本身做成可持久化的状态**——其 `/autonomous` 模式在 turn/token/time 预算内运行并可配置质量门，官方明确自述"通过一个门只证明该门所验证的内容，到达预算上限不等于任务成功"；其 Continual Harness 机制则尝试让 harness 的补充说明、记忆与子 Agent 规格以证据支撑的小步更新持久化（支撑论文 arXiv:2605.09998 与 arXiv:2512.24601 均为预印本，未经同行评议）。

用本课四约束审视它：预算与质量门设计可与 §三 逐项对照，但"通过门 ≠ 任务成功"恰恰说明——无论 harness 多复杂，停止条件的解释权和回退决定仍必须由研究者保留。该项目发布仅数日、无独立复现，课程只把它作为分析对象：钉死版本的 README 见 [reading-list.md](../../course/reading-list.md) 第 11 课新增案例条目；不进学生安装清单，不外推为"AI 已能自主科研"的任何变体。

## 五、失败实验记录与不选择性删除

### 1. 为什么失败记录是循环的一部分

循环的价值不只在于成功迭代，更在于失败迭代被保留。失败记录能够回答：

- 这个方法在什么条件下不工作；
- 哪些迭代触发了协议性停止（如数据污染、指标被修改）；
- 回退到了哪个稳定配置；
- 是否有迭代结果与原假设相反——这往往是机制假设需要修订的信号。

如果失败被静默删除，循环就只剩"看起来有效的迭代"，这构成选择性报告（沿用第 1 课 §一·1 表格"实验迭代"行的风险列）。

### 2. 失败保留的最低字段

每次失败迭代至少记录：

| 字段 | 内容 |
| --- | --- |
| 迭代 ID | 与运行日志对应 |
| 假设对应 | 本次迭代验证的子假设 |
| 失败类型 | 协议错误 / 数据污染 / 超时 / 结果不支持 / 越权 / 其他 |
| 触发的停止条件 | 正常 / 协议性 / 禁止 |
| 回退目标 | 回退到哪个稳定配置 |
| 是否人工确认 | 是 / 否；审核人 |
| Keep/Discard | Discard（但记录保留） |

### 3. 不选择性删除的检查

循环运行后，至少检查：

- 失败迭代数 + 成功迭代数 = 总迭代数（数账对得上）；
- 每个失败迭代都有失败类型和回退目标；
- 没有迭代被"看起来没跑过"（日志存在但记录缺失）；
- 失败迭代的指标记录与成功迭代格式一致（不能只记成功迭代的指标）。

> 与第 13 课的连接：第 13 课的失败复盘和证据充分性检查会直接使用本课保留的失败记录。本课不要求完成复盘，只要求失败被保留。

## 六、贯穿案例：把可重复动作改写为受限循环

承接第 9 课贯穿案例（自由摘要 vs 阅读卡摘要，H1：字段约束 → 生成时强制标注 → 限定条件遗漏率下降）。第 10 课已把"生成阅读卡"这一步用受限 Agent 跑通一次。本课把它改写为一个受限循环。以下数字、commit、rubric 版本和日志均为**课程教学示意**，用于展示工件结构，不是已发生的实验结果。

### 第一步：写出可重复动作（§二·1 假设步骤）

可重复动作：给定一篇论文，生成阅读卡摘要并计算限定条件字段缺失率。这个动作可重复运行（同模型、同温度、同 rubric），指标可机器计算（缺失字段数 / 应有限定条件字段数）。

### 第二步：写循环四约束（§三）

- 固定指标：限定条件字段缺失率；分母=应有限定条件字段数（5），分子=缺失字段数；缺失处理=字段缺失即计 1，不补全；
- 预算：20 篇论文 × 2 组 × 3 种子 = 120 次运行；总时长 ≤ 60 分钟；token 上限按学校后端配额；
- 停止条件：正常停止=完成 120 次运行；协议性停止=发现 rubric 被修改、数据划分不一致、API 版本变化；禁止=因结果不利而停；
- 回退机制：回退到第 9 课判断门通过时的配置（commit abc123，rubric v1.2）；回退后保留所有失败迭代；回退触发 J2 研究判断的待验证项升级。

### 第三步：写循环骨架（§二·1 五步）

```text
for paper in papers:              # 配置扫描（固定论文集）
  for seed in [100, 200, 300]:    # 随机化
    for group in [treatment, baseline]:
      run_once(paper, seed, group)        # 运行
      metric = compute_missing_rate(...)  # 度量（固定口径）
      decision = evaluate(metric, H1)     # 评价（对照阈值）
      keep_or_discard(decision, reason)   # 回写/回退
```

### 第四步：标出人工审核点（§四·2）

| 审核点 | 谁审核 | 审核什么 |
| --- | --- | --- |
| 循环启动前 | 学生 | 指标定义、rubric 版本、数据划分是否固定 |
| 协议性停止时 | 学生 | 是否真的协议错误，还是结果不利被伪装为协议错误 |
| 回退触发时 | 学生 | 回退目标是否为上一稳定配置 |
| 循环结束后 | 学生 | 失败迭代数 + 成功迭代数 = 总迭代数 |
| 研究判断修订时 | 学生 | 是否需要把 H1 标记为待验证或修改 |

### 第五步：写 AutoResearch / AI Scientist 对比分析（§四）

在贯穿案例上做一次对比：

- 我的循环与 AutoResearch 的相似处：固定预算、固定指标、Keep/Discard、失败保留；
- 我的循环与 AI Scientist 的差异处：我的循环不端到端生成想法和论文，只覆盖"生成摘要 + 计算指标"这一可重复动作；我的指标需要人工盲评一致性（kappa），不能完全机器评价；
- 仍需人工判断的部分：主题是否值得研究、kappa 是否达标、回退是否真的回到稳定配置、结论是否被外推。

### 第六步：写失败保留记录（§五）

至少保留一次失败迭代记录，含七字段（迭代 ID、假设对应、失败类型、触发的停止条件、回退目标、是否人工确认、Keep/Discard）。

本课不要求循环在课堂内跑完 120 次，只要求跑通"可重复动作 → 四约束 → 五步骨架 → 审核点 → 对比分析 → 失败保留"的链路，并产出受限循环说明与至少一次失败迭代记录。

## 七、常见错误

1. **循环无预算**：跑"直到结果好为止"。应预先写明时间、token、运行次数与失败预算。
2. **停止条件只写"跑完为止"**：缺协议性停止与禁止停止。应写明三类触发器。
3. **指标在循环中被修改**：工作流在结果不利时换指标或改 rubric。应在循环启动前固定指标定义文件并版本化。
4. **失败被静默跳过**：循环只记成功迭代。应保留所有迭代日志，失败迭代与成功迭代格式一致。
5. **回退到"上一次看起来不错的配置"**：不是稳定配置。应回退到最近一次通过人工审核的配置。
6. **把端到端自动化外推为通用自主科研**：AI Scientist 只在特定 ML 设置下验证。应只作分析对象，不外推。
7. **把自动评审当作同行共识**：AI 审稿不是真实同行评审。应只作为循环内部 Evals。
8. **循环无人工审核点**：全部交给 Agent 决策。应在启动、协议性停止、回退、结束、判断修订五个点人工审核。
9. **把"Agent 能跑"当"循环成立"**：能跑一次不等于可重复运行。应满足 §二·2 四项适用前提。
10. **回退后不修订研究判断**：回退了但没把假设标记为待验证。应在回退时触发判断记录更新。

## 八、课堂练习

### 练习 1：判断循环适用性

判断以下科研动作是否适合改写为受限循环，并说明理由：

1. 用固定模型对 20 篇论文生成阅读卡摘要并计算限定条件遗漏率。
2. 让 Agent 自动判断哪篇论文值得深入研究。
3. 在固定配置扫描下测试三种 prompt 模板的摘要质量分数。
4. 让 Agent 自动改写论文直到"读起来更好"。

参考判断：1 适合（可重复、指标可机器计算）；2 不适合（依赖人工判断）；3 适合（配置扫描、有界）；4 不适合（"读起来更好"无操作性定义）。

### 练习 2：写四约束

为你第 10 课的受限执行动作写四约束：固定指标、预算、停止条件、回退机制。检查停止条件是否包含正常/协议性/禁止三类。

### 练习 3：识别指标篡改

下面这段循环日志有什么问题？

> 迭代 3：限定条件遗漏率 0.42，未达阈值。自动切换到"字段覆盖率"指标，迭代 3' 字段覆盖率 0.85，达到阈值，Keep。

参考：评价协议漂移——循环在结果不利时切换指标。应回退到迭代 2 的稳定配置并人工审核。

### 练习 4：拆解 AutoResearch

用八维框架拆解 AutoResearch（Karpathy README + program.md）。每个维度写一句"系统已处理"和一句"仍需人工判断"。

### 练习 5：拆解 AI Scientist 的边界

用八维框架拆解 Lu et al. 2026 的 AI Scientist。重点写"自动评审"维度上它做了什么、不能替代什么。指出至少两处不能外推为通用自主科研的边界。

### 练习 6：写循环骨架

为你自己的一个可重复科研动作写五步循环骨架（假设/运行/度量/评价/回写回退）。标出至少三个人工审核点。

### 练习 7：失败保留

让你的循环至少跑一次失败迭代，按 §五·2 的七字段记录。检查：失败迭代数 + 成功迭代数 = 总迭代数？

### 练习 8：不外推清单自查

检查你的循环说明和对比分析中是否出现 §四·4 列表中的越界表述。出现则改写为带边界的形式。

## 九、术语表

| 术语 | 本课程中的含义 |
| --- | --- |
| 实验自动化循环 | 把可重复科研动作用受限 Agent 串成 假设→运行→度量→评价→回写/回退 的机制，每步留下可审查工件 |
| Edit → Evaluate → Keep/Discard → Repeat | 受限循环的最小骨架；适用前提见 §二·2 |
| 固定指标 | 计算口径、分母分子、缺失处理、标注协议在循环启动前写明，运行期间不可被工作流修改 |
| 预算 | 时间、资源、运行次数、失败次数的硬上限 |
| 停止条件 | 正常停止 / 协议性停止 / 禁止停止三类触发器 |
| 回退机制 | 循环失败或停止后回到上一稳定配置并保留失败记录的路径 |
| 评价协议漂移 | 工作流在结果不利时修改指标、rubric 或数据划分，构成隐性 p-hacking |
| 失败保留 | 失败迭代按与成功迭代一致的格式记录，不被选择性删除 |
| AutoResearch 元模式 | 固定预算、固定指标、保留/丢弃、留下日志的最小循环骨架；本课作分析对象 |
| AI Scientist | Lu et al. 2026 报告的端到端自动化 AI 研究系统；本课作分析对象，不外推为通用自主科研 |
| 自动评审 | AI Scientist 内置的 AI 审稿；只作循环内部 Evals，不替代真实同行共识 |
| MLAgentBench | Huang et al. 2024 提出的 ML 实验 Agent 评价基准；提供任务、成功标准、轨迹和失败类型评价方法 |
