# 第 11 课逐页脚本｜实验自动化与 AutoResearch 循环

## 一、使用说明

### 本课唯一主目标

> 学生把第 10 课的受限执行扩展为一个可重复运行的受限循环——固定指标、预算、停止条件、回退机制齐全，失败被保留，AutoResearch / AI Scientist 被拆解而非外推。

本课不追求在 90 分钟内跑完一个完整循环，也不要求复刻 AI Scientist 整套系统。目标是让学生亲手完成一次"可重复动作 → 四约束 → 五步骨架 → 审核点 → AutoResearch/AI Scientist 八维拆解 → 失败保留"的可复盘链路。本课产出为第 12 课个人工作流设计直接铺垫。

- 21-40 人；
- 连续 90 分钟；
- 中文授课，英文仅保留论文名、工具名和必要术语；
- 正式 PPT 已通过技术、教学和视觉三重检查，视觉规则见 [ppt-quality-gates.md](../../course/ppt-quality-gates.md) 与 [ppt-design-criteria.md](../ppt-design-criteria.md)；
- OpenCode、Git 和模型后端尽量在课前确认；
- 学生优先使用自己的可重复科研动作（第 10 课产出）；没有者沿用贯穿案例；
- 本课无正式提交（验证门在第 13 课后）。

## P04｜循环五步：假设→运行→度量→评价→回写/回退

### 屏显内容

| 步骤 | 动作 | 必须留下的工件 |
| --- | --- | --- |
| 假设 | 写明本次迭代要验证的子假设 | 假设条目（对应 H1/A1/A2/A3） |
| 运行 | 固定配置、预算、种子下执行 | 运行日志 |
| 度量 | 用预先写明的操作定义计算指标 | 指标记录（含分母分子） |
| 评价 | 对照阈值判断支持/削弱/推翻 | 评价记录 |
| 回写/回退 | Keep/Discard + 理由 | 决策记录 |

> 每一步都不能事后补。

### 视觉结构

主链轮廓：五节点单线 + 回退箭头从"回写/回退"指回"假设"节点。底部一句"假设在运行前写明，度量口径在评价前固定，停止条件在循环启动前承诺"。

### 教师讲述备注

循环不是新方法，是把研究者手工做的事用受限 Agent 串起来。关键约束：假设在运行前写明，度量口径在评价前固定，停止条件在循环启动前承诺。任何一步允许事后补写，循环就退化为"跑到出现有利结果为止"。

### 互动／操作

快问：你之前做实验时，假设是先写的还是结果出来后补的？只听回答。

### 建议时间

6:45-9:00。

### 来源与事实边界

handout §二·1；第 1 课 §2.7 工作流何时停止。

## P05｜适用条件与不适用范围

### 屏显内容

适用前提：

- 可重复运行（同配置能另一台机器跑出可比结果）
- 指标可机器计算（操作性定义，脚本算出数）
- 迭代有界（预算有限，停止条件预先写明）
- 失败可识别（能区分"无效运行"与"结果不支持"）

不适用：

- 依赖人工判断（论文阅读质量、伦理审查）
- 指标需专家标注才能得到
- 每次运行不可控或不可复现（不可重现的在线服务）

> 循环 ≠ 跑很多次。

### 视觉结构

对照轮廓：左栏"适用"四项 + 一句正面对照，右栏"不适用"三项。底部"循环 ≠ 跑很多次"。

### 教师讲述备注

这个循环并非对所有科研动作都适用。适用前提四项缺一不可。不适用的情况：研究动作依赖人工判断、指标需要专家标注、运行不可复现。注意"循环 ≠ 跑很多次"——公平的循环要求配置变化预先列出、指标口径一致、baseline 与实验组预算相同、失败不被跳过。

### 互动／操作

追问：判断"Agent 自动判断哪篇论文值得深入研究"是否适合改写为循环？为什么？

### 建议时间

9:00-11:15。

### 来源与事实边界

handout §二·2-3；Sandve et al. 2013（可复现追踪链）。

## P06｜固定指标：循环启动前写明，运行期间不可被工作流修改

### 屏显内容

固定指标 = 计算口径 / 分母分子 / 缺失处理 / 标注协议 在循环启动前写明。

常见失败模式：

- 结果不利后"自动尝试下一个指标"——评价协议漂移
- 运行中"自动修订 rubric 版本"——baseline 失去可比性
- 数据缺失时"自动跳过该样例"——分母被悄悄缩小

检查：循环运行前后，指标定义文件、rubric 版本号、数据划分是否一致。

### 视觉结构

工件视图轮廓：主体为一份"指标定义文件"重绘（含版本号、分母、分子、缺失处理、rubric 版本），下方三个失败模式短标签，底部检查项。

### 教师讲述备注

固定指标不是"用什么指标"，而是"这个指标怎么算出来，且不可被工作流自身修改"。三个失败模式都是评价协议漂移的常见表现。判断指标是否被篡改：循环运行前后，指标定义文件、rubric 版本号、数据划分是否一致。任何不一致都应触发循环停止并人工审核。

### 互动／操作

无。

### 建议时间

11:15-13:30。

### 来源与事实边界

handout §三·1；第 9 课 §三·3 度量标准与标注协议。

## P07｜预算与停止条件：三类触发器

### 屏显内容

预算（硬上限）：

- 时间 / 资源（token、算力、API 调用）/ 运行次数 / 失败次数

停止条件三类触发器：

| 类型 | 触发 | 例子 |
| --- | --- | --- |
| 正常 | 达到预算或完成扫描 | 120 次跑完 |
| 协议性 | 数据污染、配置错误、指标被修改 | rubric 版本变化 |
| 禁止 | 因结果不利而停 / 因结果有利而停 | 隐性 p-hacking |

> 预算触顶必须停，不是"再跑一次说不定就成了"。

### 视觉结构

阶梯轮廓：左侧预算四项，右侧停止条件三类（正常/协议性上升 + 禁止下降标注），底部禁止类用警示色。

### 教师讲述备注

预算是预先写明的硬上限，而非"大概要花多久"。停止条件在第 9 课是"运行次数与停止规则"，本课扩展为三类触发器。协议性停止指循环本身出了问题（数据污染、配置错误、指标被修改），与结果是否有利无关。禁止的停止是"因为结果不利就停、因为结果有利就停"——这构成隐性 p-hacking。

### 互动／操作

追问：你的循环如果"跑 100 次都没出现显著结果"，应该停还是继续？为什么？

### 建议时间

13:30-15:45。

### 来源与事实边界

handout §三·2-3；第 9 课 §三·2 停止条件；第 1 课 §2.7 工作流何时停止。

## P08｜回退机制：回到稳定配置，不是“上一次看起来不错”

### 屏显内容

回退至少回答：

- 回退到哪个稳定配置（最近一次通过人工审核，不是"上一次看起来不错"）
- 回退后已运行迭代是否保留（必须保留）
- 是否触发研究判断修订（原假设是否需修改、预算是否需调整）
- 回退是否需要人工确认（默认需要）

> 回退不是"重跑到成功"。回退是承认这次没达成目标，记录原因，回到上一个可审查状态。

### 视觉结构

责任分工轮廓：左栏"回退到"（稳定配置 + 保留失败迭代），右栏"回退不是"（重跑到成功 / 删除失败 / 不修订判断）。

### 教师讲述备注

回退机制是循环在失败或停止后的处理路径。关键区分：回退到"最近一次通过人工审核的配置"，不是"上一次看起来不错的配置"——这两者经常被混淆。回退后失败迭代必须保留，并触发研究判断的修订。回退默认需要人工确认，因为回退通常意味着循环未按预期推进。

### 互动／操作

无。

### 建议时间

### 来源与事实边界

handout §三·4；第 9 课 §三·4 失败预案。

## P09｜反例：指标篡改（评价协议漂移）

### 屏显内容

课程教学反例（虚构日志）：

```
迭代 3：限定条件遗漏率 0.42，未达阈值。
       自动切换到"字段覆盖率"指标。
迭代 3'：字段覆盖率 0.85，达到阈值，Keep。
```

问题：循环在结果不利时切换指标——评价协议漂移。

改写：循环启动前固定指标定义文件并版本化；结果不利触发 Discard + 回退，而非换指标。

### 视觉结构

工件视图轮廓：主体为循环日志重绘（等宽字体），问题用警示色高亮"自动切换"，下方改写说明。

### 教师讲述备注

这是课程教学反例，对应一种可发生的失败模式。循环在结果不利时"自动尝试下一个指标"，看似在迭代，实际是评价协议漂移——baseline 与实验组失去可比性。改写方法：循环启动前固定指标定义文件并版本化；结果不利时触发 Discard + 回退到上一稳定配置，而不是换指标。

### 互动／操作

让学生指出日志中哪一行暴露了问题。追问：如果只看最终 Keep 决策，能发现这个问题吗？

## P11｜失败保留的最低字段

### 屏显内容

每次失败迭代至少记录七字段：

| 字段 | 内容 |
| --- | --- |
| 迭代 ID | 与运行日志对应 |
| 假设对应 | 验证的子假设 |
| 失败类型 | 协议错误 / 数据污染 / 超时 / 结果不支持 / 越权 / 其他 |
| 触发的停止条件 | 正常 / 协议性 / 禁止 |
| 回退目标 | 回退到哪个稳定配置 |
| 是否人工确认 | 是 / 否；审核人 |
| Keep/Discard | Discard（但记录保留） |

检查：失败迭代数 + 成功迭代数 = 总迭代数。

### 视觉结构

工件视图轮廓：主体为七字段表重绘，底部数账等式。

### 教师讲述备注

失败保留是循环的一部分。失败记录能回答"这个方法在什么条件下不工作""哪些迭代触发了协议性停止""是否有结果与原假设相反"。如果失败被静默删除，循环就只剩"看起来有效的迭代"，构成选择性报告。数账检查：失败迭代数 + 成功迭代数 = 总迭代数。第 13 课的失败复盘会直接使用这些记录。

## P19｜本讲知识点总结

### 屏显内容

1. **循环五步**：假设 → 运行 → 度量 → 评价 → 回写或回退。
