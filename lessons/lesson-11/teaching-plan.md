# 第 11 课教师教案｜实验自动化与 AutoResearch 循环

## 一、本课定位

- 学时：2 学时，90 分钟
- 研究链路：阶段七"原型验证（实验追踪）"
- 教学类型：讲授 + 教师演示 + 个人实践 + 同伴互查
- 核心问题：如何在固定指标、预算和停止条件下自动迭代，而不让评价协议漂移或失败被删除？
- 课堂产出：受限循环说明（四约束 + 五步骨架 + 审核点）+ 至少一次失败迭代记录 + AutoResearch/AI Scientist 八维拆解表
- 正式提交：无（验证门在第 13 课后）

本课必须建立三项共识：

1. 实验自动化循环不是"跑很多次"，而是"假设→运行→度量→评价→回写/回退"五步在固定约束下可重复运行，每步留下可审查工件。
2. 固定指标、预算、停止条件、回退机制四项缺一不可；缺一项循环就退化为无界搜索或隐性 p-hacking。
3. AutoResearch / AI Scientist 是分析对象，不是结论外推的依据；它们在哪些维度上"已由系统处理"、哪些维度上"仍需人工判断"是本课的核心判断训练。

本课承接第 10 课受限 Agent 执行——把"跑通一次"扩展为"可重复运行的循环"。本课为第 12 课个人工作流设计铺垫——第 12 课会把本课的循环骨架重新组合为服务于学生自己科研动作的工作流。

## 二、学习目标

完成本课后，学生能够：

1. 说明 `Edit → Evaluate → Keep/Discard → Repeat` 循环的适用与不适用条件；
2. 为自动迭代设置固定指标、预算、停止条件和回退机制；
3. 识别指标被工作流篡改的失败模式，避免评价协议漂移；
4. 用八维框架拆解 AutoResearch / AI Scientist，指出每个维度上系统已处理与仍需人工判断的部分；
5. 写出失败实验保留规则，避免选择性删除；
6. 把自己一个可重复科研动作改写为受限循环，标出人工审核点与回退路径。

### 教师

- [ ] AI Scientist（Lu et al. 2026）八维拆解表样例（可投屏）
- [ ] 同伴互查用循环四约束检查卡

### 学生

- [ ] 已完成第 10 课产出：受限执行记录（diff、日志、越权处理）
- [ ] 第 9 课实验规格（七字段 + 停止条件）与 baseline 可复现说明

### 安全与资源口径

- 不要求学生自费购买 API token；循环可在纸面或 Markdown 模板中完成骨架设计。
- 不向外部模型发送未公开论文、敏感数据或学生私人材料（沿用第 2 课伦理检查）。
- 循环运行如使用大模型 API，记录 API 提供方、版本、调用日期；费用由学生自控，不构成评分项。
- 本课不要求循环跑完所有迭代，只要求跑通骨架与至少一次失败迭代记录。

## 六、教师演示脚本

### 演示前状态

- 演示项目只含公开或贯穿案例内容；
- 投屏前确认终端不显示凭据；
- 准备贯穿案例的受限循环骨架（五步 + 四约束）；
- 准备"指标篡改"反例（循环日志显示结果不利时换指标）；
- 准备失败迭代记录样例（七字段）；
- 准备 AutoResearch 核心循环截图（课程固定 commit `228791f`）与 AI Scientist 八维拆解表。

### 演示步骤

1. **循环五步与四约束（0-18 分钟段）**：在贯穿案例上展示 假设→运行→度量→评价→回写/回退 五步。重点演示：固定指标（限定条件字段缺失率，分母=5，分子=缺失数）、预算（120 次运行 / 60 分钟 / token 上限）、停止条件（正常/协议性/禁止三类）、回退（回退到 commit abc123 + rubric v1.2）。画面必须标注“课程教学示意”，避免把虚构参数误认成实验结果。

2. **指标篡改反例（18-35 分钟段）**：展示一个标注为“课程教学反例”的虚构循环日志，结果不利时自动切换到"字段覆盖率"指标。让学生指出评价协议漂移。改写为固定指标版本：循环启动前固定指标定义文件并版本化。

3. **AutoResearch 八维拆解（35-55 分钟段）**：投屏 AutoResearch README + program.md 核心循环。逐维度拆解：任务契约（用户写明）、Context（用户指定）、工具权限（只读/可写范围写明）、状态（项目工件）、执行循环（Edit→Evaluate→Keep/Discard→Repeat）、工件（保留所有迭代日志）、Evals（预先写明指标）、失败恢复（回退到上一稳定配置）。

4. **AI Scientist 边界（35-55 分钟段）**：投屏 Lu et al. 2026 的端到端流程。重点在"自动评审"维度：AI 审稿能发现部分问题，但不替代真实同行共识。强调不外推清单：不表述为"AI 已能自主科研""端到端适用于所有学科""失败可被自动删除"。

5. **失败迭代记录（55 分钟前）**：演示七字段记录——迭代 ID、假设对应、失败类型、触发停止条件、回退目标、是否人工确认、Keep/Discard。

### 演示判断点

1. 循环和"跑很多次"的区别是什么？
2. 为什么指标必须在循环启动前固定，而不是"边跑边调整"？
3. 回退到"上一次看起来不错的配置"和回退到"上一稳定配置"有什么区别？
4. AutoResearch / AI Scientist 在哪些维度上仍需人工判断？
5. 自动评审能替代同行共识吗？为什么？

### 失败演示

可预先准备两个反例：

- **反例一：指标篡改**。展示循环在结果不利时换指标的日志，让学生指出评价协议漂移。改写为固定指标版本。

- **反例二：无界循环**。展示一个没有预算和停止条件的循环（"跑直到结果好为止"），让学生指出这是隐性 p-hacking。改写为带四约束的版本。

失败不重跑到成功。让学生指出问题，再改写为受限版本。

- [ ] 五步骨架（假设/运行/度量/评价/回写回退）写明

## 八、讲后复盘

教师课后记录：

- 学生是否把循环当成"跑很多次"？
- 四约束中哪一项学生最容易缺？（经验上：停止条件与回退机制）
- 指标篡改反例是否被学生识别？
- AutoResearch / AI Scientist 拆解中，哪些维度学生最难判断"仍需人工"？
- 是否出现把 AI Scientist 外推为通用自主科研的表述？
- 失败迭代记录是否真的保留，还是只记成功？
- 第 12 课需要在工作流设计中重点补哪个环节？
