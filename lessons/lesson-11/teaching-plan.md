# 第 11 课教师教案｜实验自动化与 AutoResearch 循环


## 整体复审补充：板书、诊断与串词（2026-09-15）

本节替换同类口头提示，不增加既有时段。开场诊断嵌入现有开场/回顾，后续再沿原实践时段操作。

- **板书主线**：固定队列 ≠ 优化循环；任务数 / 尝试数 / 样本数。
- **诊断问题**：恢复一次失败是否增加一个研究样本？
- **预期回答**：没有；只是同一任务的新尝试，旧失败要留存。
- **常见误答后的追问**：如答“重跑直到好结果”，回到预算和停止规则。
- **过渡串词**：“接下来把执行、评价与人工审核组织成一个可追踪工作流。”
- **当堂最小产出**：预算、权限、停止、审核四约束及一次恢复检查。
- **退出记录**：写“已完成的动作、本人项目仍缺的证据/工件、下次补齐位置”。使用教师包时标明课堂方法练习，不能据此宣称本人研究门通过；正式提交课次仍为第 6、9、13、16 课。


## 一、本课定位

- 学时：2 学时，90 分钟
- 研究链路：阶段七"原型验证（实验追踪）"
- 教学类型：讲授 + 教师演示 + 个人实践 + 同伴互查
- 核心问题：如何在固定指标、预算和停止条件下自动迭代，而不让评价协议漂移或失败被删除？
- 课堂产出：受限循环说明（四约束 + 五步骨架 + 审核点）+ 至少一次失败迭代记录 + 四约束短分析
- 正式提交：无（验证门在第 13 课后）

本课必须建立三项共识：

1. 实验自动化循环不是"跑很多次"，而是"假设→运行→度量→评价→回写/回退"五步在固定约束下可重复运行，每步留下可审查工件。
2. 固定指标、预算、停止条件、回退机制四项缺一不可；缺一项循环就退化为无界搜索或隐性 p-hacking。
3. AutoResearch / AI Scientist 是分析对象，不是结论外推的依据；它们在哪些维度上"已由系统处理"、哪些维度上"仍需人工判断"是本课的核心判断训练。

本课承接第 10 课受限 Agent 执行——把"跑通一次"扩展为"可重复运行的循环"。本课为第 12 课个人工作流设计铺垫——第 12 课会把本课的循环骨架重新组合为服务于学生自己科研动作的工作流。

## 二、学习目标

完成本课后，学生能够：

1. 说明 `Edit → Evaluate → Keep/Discard → Repeat` 循环的适用与不适用条件；
2. 为自动迭代设置固定指标、预算、停止条件和回退机制；
3. 识别指标被工作流篡改的失败模式，避免评价协议漂移；
4. 用八维框架拆解 AutoResearch / AI Scientist，指出每个维度上系统已处理与仍需人工判断的部分；
5. 写出失败实验保留规则，避免选择性删除；
6. 把自己一个可重复科研动作改写为受限循环，标出人工审核点与回退路径。

### 安全与资源口径

- 不要求学生自费购买 API token；循环可在纸面或 Markdown 模板中完成骨架设计。
- 不向外部模型发送未公开论文、敏感数据或学生私人材料（沿用第 2 课伦理检查）。
- 循环运行如使用大模型 API，记录 API 提供方、版本、调用日期；费用由学生自控，不构成评分项。
- 本课不要求循环跑完所有迭代，只要求跑通骨架与至少一次失败迭代记录。

## 四、90 分钟流程

> 各段只使用整数时长，合计 90 分钟。个人实践拆为两段，中间由教师处理共性卡点。

| 时间 | 内容 | 主要形式 | 产出 |
| --- | --- | --- | --- |
| 5 分钟 | 标记第 10 课受限执行中最缺的约束 | 个人标记 + 快问 | 当前缺口 |
| 15 分钟 | 执行队列与优化循环的区别；固定指标、预算、停止、回退 | 讲授 + 案例 | 四约束框架 |
| 15 分钟 | 教师演示：同一运行器的正常运行、无改善结果和受控失败；纠正指标漂移 | 教师演示 | 三种 trace + 人工停止 |
| 10 分钟 | AutoResearch / AI Scientist 四约束短分析与不外推边界 | 短讲 + 判断 | 系统边界 |
| 10 分钟 | 个人实践第一段：写四约束与执行/失败恢复骨架 | 个人实践 | 循环说明初版 |
| 5 分钟 | 教师中点点评：处理“把批量运行当优化”、“指标自评”和“回退目标不稳定” | 教师点评 | 修订方向 |
| 10 分钟 | 个人实践第二段：补三种 trace 和人工审核点 | 个人实践 | 正常/无改善/失败 trace |
| 15 分钟 | 同伴互查：四约束、执行类型、失败保留和审核点 | 2–3 人互查 | 互查问题与作者决定 |
| 5 分钟 | 总结与第 12 课输入确认 | 总结 + 个人回写 | 可封装的循环状态 |

**第一次学生动手**：开场即标记约束缺口。持续个人实践为两个 10 分钟段，中间含 5 分钟教师点评。

**最小课堂产出**：受限循环说明（四约束 + 执行/失败恢复骨架 + 人工审核点）+ 正常、无改善、受控失败三种 trace。完整八维系统对照不作课堂硬产出。

**课后补全**：将循环写成可重复调用的队列与失败恢复逻辑，准备第 12 课封装。虚构案例的 6 份构造输出是完整实验规格，不是所有学生的课堂通用要求。

**备用路径**：若现场环境故障，学生在纸面或 Markdown 模板中完成循环骨架与失败记录；同伴互查改为纸面交换检查；不把课堂时间用于逐台排障。循环的完整运行在课后完成，不要求课堂内提交。

## 六、教师演示脚本

1. 打开 assets/reading-card-workflow/README.md，说明全部输出为构造回放、无模型调用。
2. replay --fault-once 注入 T02-card 失败，查看 events 与 state 后决定恢复。
3. 再次 replay 只补未完成项，旧失败与新 run ID 均保留。
4. evaluate 显示 T01 改善、T02 无改善、T03 负例；区分技术失败和评价结果。
5. 用 AutoResearch 作方法选优的短对照，保留完整八维材料为课后参考。
