# 第 10 课共同诊断｜补丁意图与可区分测试

## 先独立判断

**问题：三个补丁中哪个修复契约，测试能区分它们吗？**

输入：L9 baseline、冻结协议及一项受限动作。先记录判断和依据，再与同伴比较；课堂校准后可修订并写明改变原因。答案有分歧时回到具体记录。已有示例可作方法参考，不替代本人的初始判断。

## 原始材料与待比较选项

教学构造补丁提案。输入契约：paper_id 与 summary 均为非空字符串；summary 首尾空白应去掉；正常输入必须保留。原实现仅访问字段并 strip。

```python
# 原实现（含待修缺口）
def normalize_record(record):
    return {"paper_id": record["paper_id"], "summary": record["summary"].strip()}
```

| 补丁 | 行为 |
| --- | --- |
| A | 只查 key 是否存在，缺字段给 ValueError |
| B | 遇到异常返回空对象，同时让下游略过空对象 |
| C | 字段存在、类型与去空白后非空都检查；不改评价代码 |

输入：正常文本、缺 summary、summary 为 None、summary 为全空白、paper_id 为全空白。既有测试只覆盖前两类。

**待决定：**A 已通过旧测试是否足够？为至少两项候选补丁给出行为预测，再设计能区分它们的测试。

把“初始判断—证据位置—仍缺什么—核验后决定”写在现有笔记中。允许回答“仍不能判断”，同时指出下一项能改变判断的证据。

实际实现入口：[个人微型项目](../../course/micro-project.md)，与原回放包服务同一个人项目。

## 迁移到本人项目

从现有 normalize_record 示例或本人同规模动作出发，先冻结正常/缺字段/空值/类型用例，再实际修改一个模块。与 baseline 在相同输入上比较，保留旧失败和新结果。

**验证：**检查 diff 仅在授权实现与本人新增行为测试内；gold/既有评价只读。若 AI 给出补丁，人工逐项审核；仅抄 after 示例不足以覆盖空值与类型。

**保存位置与达标证据：**受限补丁、失败用例、测试结果、trace 与人工决定。

## 完成标准

| 尺度 | 判断依据 |
| --- | --- |
| 需支持 | 完成操作，但理由、证据定位或验证仍有缺口。 |
| 达标 | 独立决定，证据可定位，完成相称验证，并更新本人项目。 |
| 优秀 | 识别替代解释或有效性威胁，以额外检查改变或加强判断。 |

课堂尺度对应课程的待改、达标、卓越；不新增每周成绩或提交。优秀依判断质量，不要求更多课外时长。

断网时保留同样的判断要求，使用包内文本、存档或本地工件。工程课纸面诊断仅作备用练习，最终仍须补本人实际执行、实质修改和对照评价。提前完成者可寻找一个使自己决定改变的反例；不增加课后任务。
