# 第 10 课教师教案｜AI 辅助编码、调试与受限 Agent 执行

## 一、本课定位

- 学时：2 学时，90 分钟
- 研究链路：阶段七"原型验证"中的受限 Agent 执行
- 教学类型：讲授 + 教师演示 + 个人实践 + 同伴互查
- 核心问题：如何让 Agent 帮忙修改代码、运行测试、归因错误，但不污染实验或越过权限边界？
- 课堂产出：任务契约（五字段）+ 代码 diff + 验证记录（测试与人工核验）+ 失败记录
- 正式提交：无（本课非正式提交门；产出回写个人项目，作为第 13 课验证门材料的过程证据）

本课必须建立三项共识：

1. 受限 Agent 执行的起点是任务契约，不是模糊 prompt——Agent 输出是候选，不是事实，必须被人工核验。
2. 权限分层（只读 / 可写 / 可执行 / 需确认 / 禁止）与人工审核点（diff 写回前、测试失败时、评价协议改动时、越权请求时）是"Agent 不污染实验"的底线。
3. 修复根因、绕过失败与污染实验是三类处理方式，对结论可追溯性的影响截然不同；后两类是学术规范红线。

本课是模块四（第 10-13 课）的起点。第 9 课判断门已过，实验规格中"哪些步骤拟用 Agent、哪些步骤必须人工"是本课任务契约的直接输入。本课的受限"一次执行"是第 11 课自动化循环的前提——没有边界的一次执行不能被安全地重复，更不能被自动化。

## 二、学习目标

完成本课后，学生能够：

1. 把一个模糊编码或调试请求改写为带验收标准的任务契约（Context / Permission / Non-goal / 人工审核点 / 失败恢复五字段）；
2. 为 Agent 设置分层权限，并说明为什么这样分层；
3. 对 Agent 产生的代码进行人工核验：diff 审查、测试先行、不把"模型建议这样做"当作研究判断的充分理由；
4. 区分修复根因、绕过失败和污染实验三种处理方式，并说明它们对结论可追溯性的不同影响；
5. 承接第 9 课实验规格，标出"哪些步骤拟用 Agent、哪些步骤必须人工"，并为本课选定的受限任务写出完整任务契约；
6. 记录失败与越权，按失败记录而非静默重跑到成功；
7. 说明本课产出如何成为第 11 课自动化循环与第 13 课验证门评价的输入。

### 安全与资源口径

- 不要求学生自费购买 API token；任务契约可在纸面或 Markdown 模板中完成。
- 不向外部模型发送未公开论文、敏感数据或学生私人材料（沿用第 2 课伦理检查）。
- Agent 执行如使用大模型 API，记录 API 提供方、版本、调用日期；调用费用由学生自控，不构成评分项。
- 本课非正式提交门，产出回写个人项目，不重复制作汇报文档。
- 演示项目只含公开或贯穿案例内容；投屏前确认终端不显示凭据；网络访问关闭或不在本任务中启用。

## 六、教师演示脚本

### 演示前状态

- 演示项目只含公开或贯穿案例内容；
- 投屏前确认终端不显示凭据；
- 准备第 9 课贯穿案例实验规格（"拟用 Agent"步骤标注）；
- 准备任务契约样例（`generate_summary()` 任务五字段）；
- 准备模糊 prompt 反例；
- 准备 diff 样例（一段授权修改 + 一段越权修改）；
- 准备失败记录样例（Agent 请求修改 `configs/` + 拒绝 + 记录）；
- 网络访问关闭或不在本任务中启用。

### 演示步骤

1. **模糊 prompt 反例（0-20 分钟段内）**：展示"帮我跑通 baseline，看看结果怎么样，有问题就改一下"。让学生指出四件事都被 Agent 自行解释的风险——可能修改无关代码、跳过失败测试、修改评价协议、把单次运行写成方法效应。引出任务契约五字段。

2. **任务契约五字段（0-20 分钟段内）**：在贯穿案例上填写五字段。重点演示：Context 不暴露最终 rubric 评分（防止 Agent 调整实现以迎合评分）；Permission 可写层只含 `src/generate.py`（不含 `configs/` 与 `experiments/`）；Non-goal 防止任务膨胀（不优化速度、不替换模型、不修改 prompt 模板）；人工审核点（diff 写回前、测试失败时、评价协议改动时）；失败恢复（超时终止、越权拒绝、不重试到成功）。

3. **Agent 执行与人工核验（20-40 分钟段）**：打开课次本地真实工件 `assets/agent-task-example/`，对照 `generate.diff` 审查授权修改，再运行 `python3 -m unittest assets/agent-task-example/tests/test_generate.py`，核验 2 项测试通过，并查看 `failure-log.md` 中保留的越权失败。强调：测试通过不等于修改正确，研究者仍须人工核验方法是否符合任务契约、是否引入数据泄漏。

4. **失败记录演示（20-40 分钟段尾）**：展示一段 Agent 请求修改 `configs/exp01.yaml` 以"让 baseline 更公平"的越权请求。让学生判断：这是授权范围吗？（否，`configs/` 在"需确认"层）；Agent 推理基于什么？（错误观察——当前温度已一致）；处理？（拒绝、记录、不修改任务契约）。演示把越权请求写入 `experiments/exp01/agent-traces/task-01-failure-log.md`。

5. **修复根因 / 绕过失败 / 污染实验三区分（20-40 分钟段尾）**：投屏三例对照表。重点演示：修复根因保留失败日志与根因分析；绕过失败注释断言让测试通过；污染实验调整 baseline 温度使两组接近。强调后两类是学术规范红线（沿用 [assessment.md](../../course/assessment.md)）。

### 演示判断点

1. 模糊 prompt 与任务契约的差别是什么？为什么模糊 prompt 无法追溯？
2. 权限分层为什么是任务级而不是项目级？任务结束后权限怎么办？
3. 人工审核点为什么是"停下来等确认"而不是"跑完再看一眼"？
4. 测试通过为什么不等于修改正确？SWE-bench 视角的局限是什么？
5. 修复根因、绕过失败与污染实验的差别是什么？后两类为什么是学术规范红线？
6. Agent 越权请求时应该怎么处理？为什么不重跑到成功？

### 失败演示

可预先准备两个反例：

- **反例一：绕过失败**。展示一段 Agent 在测试失败后注释掉断言让测试通过的 diff。让学生指出属于绕过失败。改写为修复根因版本：找到失败的机制原因（自由摘要路径误调用了字段约束逻辑），修改分支条件，失败日志保留。

- **反例二：污染实验**。展示一段 Agent 修改 `rubric` 或数据划分使结果看起来更好的 diff。让学生指出属于污染实验。强调：评价代码在"禁止"层，Agent 不得修改；任务契约的 Non-goal 应包含"不修改评价协议"。

失败不重跑到成功。让学生指出问题，再改写为受限版本。

## 八、讲后复盘

教师课后记录：

- 学生是否仍把任务契约当作 prompt 模板，而不是可被独立检查者复核的工件？
- 权限分层是否真正落到任务级，还是仍停在项目级？
- 人工审核点是否在 diff 写回前、测试失败时、评价协议改动时停下来，还是跑完才看一眼？
- 修复根因 / 绕过失败 / 污染实验三区分是否被学生理解，还是混淆？
- 越权请求是否被记录，还是口头拒绝就过去？
- 任务契约是否在执行中修订并记录理由，还是变通执行？
- 第 9 课实验规格中"哪些步骤拟用 Agent、哪些步骤必须人工"是否被学生填写？本课是否承接这一标注？
- 第 11 课需要在自动化循环中重点补哪个环节？本课的"一次执行"是否能被安全地重复？
