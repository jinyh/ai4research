# 第 10 课教师教案｜AI 辅助编码、调试与受限 Agent 执行


## 整体复审补充：板书、诊断与串词（2026-09-15）

本节替换同类口头提示，不增加既有时段。开场诊断嵌入现有开场/回顾，后续再沿原实践时段操作。

- **板书主线**：任务 → 权限 → diff → 测试 → 人工审核。
- **诊断问题**：测试通过后还需核对什么？
- **预期回答**：核对改动范围、测试覆盖与研究语义。
- **常见误答后的追问**：若把AGENTS声明当沙箱，要求指出真正拒绝动作的控制点。
- **过渡串词**：“一个受限改动可检查后，再讨论多轮执行与失败恢复。”
- **当堂最小产出**：一个任务契约和一条diff/测试审核结论。
- **退出记录**：写“已完成的动作、本人项目仍缺的证据/工件、下次补齐位置”。使用教师包时标明课堂方法练习，不能据此宣称本人研究门通过；正式提交课次仍为第 6、9、13、16 课。


## 一、本课定位

- 学时：2 学时，90 分钟
- 研究链路：阶段七"原型验证"中的受限 Agent 执行
- 教学类型：讲授 + 教师演示 + 个人实践 + 同伴互查
- 核心问题：如何让 Agent 帮忙修改代码、运行测试、归因错误，但不污染实验或越过权限边界？
- 课堂产出：任务契约（五字段）+ 代码 diff + 验证记录（测试与人工核验）+ 失败记录
- 正式提交：无（本课非正式提交门；产出回写个人项目，作为第 13 课验证门材料的过程证据）

本课必须建立三项共识：

1. 受限 Agent 执行的起点是任务契约，不是模糊 prompt——Agent 输出是候选，不是事实，必须被人工核验。
2. 权限分层（只读 / 可写 / 可执行 / 需确认 / 禁止）与人工审核点（diff 写回前、测试失败时、评价协议改动时、越权请求时）是"Agent 不污染实验"的底线。
3. 修复根因、绕过失败与污染实验是三类处理方式，对结论可追溯性的影响截然不同；采用或隐瞒绕过、污染，或伪造记录时按学术规范处理；被拒绝的建议本身不自动构成红线。

本课是模块四（第 10-13 课）的起点。第 9 课判断门已过，实验规格中"哪些步骤拟用 Agent、哪些步骤必须人工"是本课任务契约的直接输入。本课的受限"一次执行"是第 11 课自动化循环的前提——没有边界的一次执行不能被安全地重复，更不能被自动化。

## 二、学习目标

完成本课后，学生能够：

1. 把一个模糊编码或调试请求改写为带验收标准的任务契约（Context / Permission / Non-goal / 人工审核点 / 失败恢复五字段）；
2. 为 Agent 设置分层权限，并说明为什么这样分层；
3. 对 Agent 产生的代码进行人工核验：diff 审查、测试先行、不把"模型建议这样做"当作研究判断的充分理由；
4. 区分修复根因、绕过失败和污染实验三种处理方式，并说明它们对结论可追溯性的不同影响；
5. 承接第 9 课实验规格，标出"哪些步骤拟用 Agent、哪些步骤必须人工"，并为本课选定的受限任务写出完整任务契约；
6. 记录失败与越权，按失败记录而非静默重跑到成功；
7. 说明本课产出如何成为第 11 课自动化循环与第 13 课验证门评价的输入。

### 安全与资源口径

- 不要求学生自费购买 API token；任务契约可在纸面或 Markdown 模板中完成。
- 不向外部模型发送未公开论文、敏感数据或学生私人材料（沿用第 2 课伦理检查）。
- Agent 执行如使用大模型 API，记录 API 提供方、版本、调用日期；调用费用由学生自控，不构成评分项。
- 本课非正式提交门，产出回写个人项目，不重复制作汇报文档。
- 演示项目只含公开或贯穿案例内容；投屏前确认终端不显示凭据；网络访问关闭或不在本任务中启用。

## 四、90 分钟流程

> 各段仅使用整数时长，合计 90 分钟。个人实践拆成两段，中间由教师处理共性卡点。

| 时间 | 内容 | 主要形式 | 产出 |
| --- | --- | --- | --- |
| 8 分钟 | 回看第 9 课的“拟用 Agent / 必须人工”标注；学生先圈出一个不可让步的人工判断 | 个人标记 + 快问 | 当前任务边界 |
| 12 分钟 | 从模糊 prompt 到任务契约；只说明本任务所需的最小权限 | 讲授 + 案例 | 任务契约五字段 |
| 10 分钟 | 辨析根因修复、被拒绝的绕过建议和实验污染；区分普通失败与规范红线 | 讲授 + 判断 | 失败处理口径 |
| 15 分钟 | 教师演示课次真实工件：契约、diff、unittest、越权记录与人工决定 | 教师演示 | 可复盘 trace |
| 10 分钟 | 个人实践第一段：从项目规格选一个步骤，写契约与权限边界 | 个人实践 | 任务契约初版 |
| 5 分钟 | 教师中点点评：处理权限过宽、验收不可测和评价代码未隔离三类共性卡点 | 教师点评 | 契约修订方向 |
| 10 分钟 | 个人实践第二段：执行或审查预置 diff/测试，写一条处理决定和失败记录 | 个人实践 | diff/测试审查 + 决定记录 |
| 15 分钟 | 同伴互查：契约是否可执行，diff 是否在范围内，处理是否掩盖失败 | 2–3 人互查 | 互查问题与作者决定 |
| 5 分钟 | 回写退出卡，确认这次执行是否可在第 11 课安全重复 | 总结 + 个人回写 | 下课输入 |

**第一次学生动手**：开场即标记人工判断；**持续项目实践**：两个 10 分钟个人实践段，中间含 5 分钟教师点评。

**最小课堂产出**：任务契约（五字段）+ 一份真实执行或课次预置 diff/测试的审查 + 一条根因/绕过/污染处理决定 + 一条失败或越权记录。

**课后补全**：将契约、diff、验证和失败记录写入 `agent-tasks/` 与 `experiments/*/agent-traces/`，使本次受限执行能被第 11 课调用。第 13 课验证门完整条件不在本课课堂一次补齐。

**备用路径**：若现场环境故障，直接使用 `assets/agent-task-example/` 中的可核验 diff、真实 unittest 输出与失败日志，在纸面或 Markdown 中完成同一套审查和决策记录；不把课堂时间用于逐台排障。

## 六、教师演示脚本

1. 打开 assets/agent-task-example/task-01.md、before/after 和原测试。
2. 先预测缺 summary 时的行为：前版 KeyError，任务要求明确 ValueError。
3. 审查 generate.diff，再用 unittest 跑两项测试；保留输入、结果与人工判断。
4. failure-log 中改测试建议按预置回放处理；另列温度/rubric 修改反例，不假称来自同一 diff。
5. 核验任务与评价标准未变，再把可重复科研动作交给 L11。

## 八、讲后复盘

教师课后记录：

- 学生是否仍把任务契约当作 prompt 模板，而不是可被独立检查者复核的工件？
- 权限分层是否真正落到任务级，还是仍停在项目级？
- 人工审核点是否在 diff 写回前、测试失败时、评价协议改动时停下来，还是跑完才看一眼？
- 修复根因 / 绕过失败 / 污染实验三区分是否被学生理解，还是混淆？
- 越权请求是否被记录，还是口头拒绝就过去？
- 任务契约是否在执行中修订并记录理由，还是变通执行？
- 第 9 课实验规格中"哪些步骤拟用 Agent、哪些步骤必须人工"是否被学生填写？本课是否承接这一标注？
- 第 11 课需要在自动化循环中重点补哪个环节？本课的"一次执行"是否能被安全地重复？
