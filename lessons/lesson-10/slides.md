# 第 10 课逐页脚本｜AI 辅助编码、调试与受限 Agent 执行

## 一、使用说明

### 本课唯一主目标

> 学生把第 9 课实验规格中一个"拟用 Agent"步骤改写为受限 Agent 任务契约，亲手完成一次有任务契约、权限分层、人工审核点和失败记录的执行。

本课不追求在 90 分钟内完成完整自动化系统，也不要求 Agent 把 baseline 跑到最优。目标是让学生亲手完成一次"实验规格标注 → 任务契约五字段 → Agent 执行 → diff 审查与人工核验 → 失败与越权记录"的可复盘链路。本课产出是第 11 课自动化循环与第 13 课验证门评价的过程证据。

### 适用条件

- 21-40 人；
- 连续 90 分钟；
- 中文授课，英文仅保留论文名、工具名和必要术语；
- 正式 PPT 已通过技术、教学和视觉三重检查，视觉规则见 [ppt-quality-gates.md](../../course/ppt-quality-gates.md) 与 [ppt-design-criteria.md](../ppt-design-criteria.md)；
- OpenCode、Git 和模型后端尽量在课前确认；
- 学生优先使用自己第 9 课实验规格中已标注的"拟用 Agent"步骤；没有者沿用贯穿案例；
- 本课非正式提交门，产出回写个人项目。

## P03｜模糊 prompt 的问题不是可能出错，而是出错后无法追溯

### 屏显内容

最常见的请求形式：

> 帮我把 baseline 跑通，看看结果怎么样，有问题就改一下。

四件事都被 Agent 自行解释：

- "跑通" → 可能修改无关代码以"让结果看起来更好"
- "结果怎么样" → 可能把单次运行写成方法效应
- "有问题" → 可能跳过失败测试或注释断言
- "改一下" → 可能修改评价协议而不是修改方法

> 模糊 prompt 的核心问题不是"可能出错"，而是"出错后无法追溯"。

### 视觉结构

上方模糊 prompt 引文，中间四行"自行解释"清单。底部一句判断。

### 教师讲述备注

模糊 prompt 把范围、权限、验收、失败处理都交给 Agent 解释。核心问题是出错后无法追溯——研究者不知道 Agent 做了什么、为什么做、依据什么标准，因此无法判断结果是否仍属于当前实验。本课的起点是把模糊 prompt 改写为任务契约。

### 互动／操作

让学生说出自己最近一次给 Agent 的 prompt 属于模糊 prompt 的哪些特征。

### 建议时间

5:00-8:00。

### 来源与事实边界

讲义 §二·1。

## P04｜任务契约让 Agent 的每一步都有可检查边界

### 屏显内容

任务契约至少包含五字段（贯穿案例样例）：

| 字段 | 内容 |
| --- | --- |
| Context | `src/generate.py` 的 `generate_summary()`；实验规格 §步骤之 3；H1；不暴露最终 rubric 评分 |
| Permission | 只读 `experiment-spec.md`、`evidence-map.md`；可写 `src/generate.py`；可执行 `pytest tests/test_generate.py`；需确认任何对 `configs/` 的修改；禁止修改 `experiments/` 已有结果、修改 rubric、访问 `notes/` |
| Non-goal | 不优化速度；不替换模型；不修改 prompt 模板；不重跑历史实验；不写新测试 |
| 人工审核点 | diff 写回前；测试失败时；评价协议改动时 |
| 失败恢复 | 超时 60 秒终止；输出无法解析保留原始输出；越权拒绝记录 |

> 任务契约是可被独立检查者复核的工件。

### 视觉结构

五列表格，每行一个字段 + 贯穿案例样例。底部一句判断。

### 教师讲述备注

五字段必须落到贯穿案例样例。重点演示：Context 不暴露最终 rubric 评分（防止 Agent 调整实现以迎合评分）；Permission 可写层只含 `src/generate.py`；Non-goal 防止任务膨胀；人工审核点是"停下来等确认"；失败恢复不重试到成功。任务契约写在项目里（`agent-tasks/<task-id>.md`），与 diff、日志、人工核验一起留存。

### 互动／操作

让学生用自己的"拟用 Agent"步骤尝试填写五字段。

### 建议时间

8:00-11:00。

### 来源与事实边界

讲义 §二·2；Russell & Norvig 2020 Ch 2（[reading-list.md](../../course/reading-list.md) 第 10 课）。

## P05｜任务契约把模糊请求改造成可追溯执行

### 屏显内容

| 维度 | 模糊 prompt | 任务契约 |
| --- | --- | --- |
| 范围 | "把 baseline 跑通" | "修改 `generate_summary()`，阅读卡路径强制调用字段约束，自由摘要路径保持不变" |
| 权限 | 未声明 | 五层显式列出 |
| 验收 | "结果怎么样" | 测试通过 + diff 只含授权范围 + 未修改评价协议 |
| 失败处理 | "有问题就改一下" | 超时终止、越权拒绝、不重试到成功 |
| 可追溯 | 无法复盘 | 契约 + diff + 日志 + 人工核验一一对应 |

## P06｜权限必须落到任务级，审核点必须真正停下来

### 屏显内容

第 1 课项目级权限矩阵 → 本课任务级权限契约：

| 层级 | 任务契约含义 | 贯穿案例 |
| --- | --- | --- |
| 只读 | 可读以理解 Context | `experiment-spec.md`、`evidence-map.md`、`hypothesis-and-judgment.md` |
| 可写 | 可修改的具体文件 | `src/generate.py` |
| 可执行 | 可运行的明确命令 | `pytest tests/test_generate.py`、`python src/run_baseline.py --config configs/exp01.yaml` |
| 需确认 | 完成前须研究者审核 | 任何对 `configs/`、`rubric`、`experiments/` 已有结果的修改 |
| 禁止 | 无论任务如何都不允许 | 修改评价协议、删除失败日志、访问 `notes/`、联网上传项目数据 |

人工审核点是停下来等研究者确认的具体节点：

- **diff 写回前**：只允许授权范围的修改进入项目
- **测试失败时**：不自行"修复"失败的测试让它通过
- **评价协议改动时**：rubric、指标计算、数据划分的改动须确认
- **越权请求时**：拒绝、记录、报告研究者

> 预先写明停下来：「跑到结果好看为止」本身构成偏倚。

### 视觉结构

上方五层权限表格，下方四个审核点纵向排列。底部一句判断。

### 教师讲述备注

第 1 课 §四·3 已建立最小权限原则。本课把它从项目级落到任务级——任务变小时权限随之收紧，任务结束后权限回收，下一次任务重新授权。重点强调"需确认"与"禁止"层是"Agent 不污染实验"的底线：评价协议、失败日志、同伴反馈、联网上传都在禁止层。人工审核点是任务执行中必须停下来等研究者确认的节点，与第 9 课 §三·2 停止条件的逻辑一致：预先承诺。

### 互动／操作

让学生检查自己五字段中"可写"是否过宽——是否包含整个 `src/` 而不是具体文件？并标出至少四个审核点。

### 建议时间

14:00-17:00。

## P07｜ReAct 的错误会循环传播，失败恢复必须阻断它

### 屏显内容

LLM coding agent 常采用 reasoning—action—observation 循环。错误可在任一环节传播：

- 推理错误 → 错误行动
- 行动错误 → 错误观察
- 错误观察 → 强化错误推理

失败恢复不重跑到成功。至少回答：

- 超时 → 终止并记录
- 输出无法解析 → 保留原始输出与错误日志
- 工具失败 → 记录失败工具与原因，不切换未授权替代工具
- 越权请求 → 拒绝、记录、报告研究者
- 测试失败 → 停，记录，等研究者判断根因

> 删除失败日志 = 伪造实验记录（学术规范红线）。

### 视觉结构

上方 ReAct 循环三环节，中间错误传播箭头，下方失败恢复五行清单。底部一句判断。

### 教师讲述备注

ReAct 循环说明 Agent 输出必须被核验：错误会在推理、行动、观察任一环节传播并自我强化。任务契约与日志让错误传播可被观察。失败恢复不重试到成功——失败日志与成功结果同等重要，删除失败日志等同于伪造实验记录（沿用 [assessment.md](../../course/assessment.md) 学术规范红线）。

### 互动／操作

让学生检查自己任务契约的失败恢复段是否覆盖超时、越权、测试失败三种情形。

## P08｜diff 审查把候选实现变成可验证实现

### 屏显内容

第 1 课 §一·2：AI 可以生成候选，但不承担研究责任。Agent 产生的代码同理——它是候选实现，不是已验证实现。

研究者必须核验：

- **diff 审查**：修改是否只在授权范围？是否引入未授权依赖或联网调用？
- **测试先行**：测试是否先于修改被研究者审查？是否覆盖关键路径还是只覆盖容易通过的路径？
- **不外包判断**：方法选择、baseline 公平性、指标定义、停止条件等研究判断不能由 Agent 决定

对 Agent 产生的每一次 diff，研究者至少检查：

1. diff 是否只包含任务契约"可写"层的文件？
2. 是否引入未授权的新依赖或外部调用？
3. 是否修改了"禁止"层的文件（评价协议、失败日志、实验结果、notes）？
4. 新增测试是否先于修改被审查？是否覆盖关键路径？
5. 修改是否在 Non-goal 层声明不做的事情上？
6. Agent 的 commit message 是否把模型推断误写成事实（"优化了方法"vs"修改了分支条件"）？

> "模型建议这样做""Agent 自动完成了"都不是研究判断的充分理由。任一项不通过，diff 不进入项目。

### 视觉结构

上方三行核验清单，下方六行 diff 审查清单。底部两句判断。

### 教师讲述备注

回扣第 1 课：AI 输出是候选不是事实。Agent 产生的代码同理——测试通过不等于修改正确，diff 看起来合理不等于未引入数据泄漏。方法选择、baseline 公平性、指标定义、停止条件等研究判断必须由研究者写出。diff 审查清单是人工审核点"diff 写回前"的具体内容。重点演示第 6 项：Agent 的 commit message 常把"修改了分支条件"写成"优化了方法"——这是把模型推断误写成事实，研究者必须改写为机制性描述。

### 互动／操作

让学生用贯穿案例的 diff 样例对照六项逐项检查。

### 建议时间

20:00-24:00。

讲义 §四·1 与 §四·3；第 1 课 §一·2 哪些判断不能外包；[AGENTS.md](../../AGENTS.md) 证据标准。

## P09｜只有修复根因能进入项目；绕过与污染都是红线

### 屏显内容

| 处理方式 | 含义 | 对可追溯性的影响 |
| --- | --- | --- |
| 修复根因 | 找到失败的机制原因，修改使根因消除 | 保留失败日志 + 修改记录 + 根因分析，结论可追溯 |
| 绕过失败 | 不找根因，让失败不再出现（注释断言、跳过测试） | 失败被隐藏，结论无法追溯，等同于伪造记录 |
| 污染实验 | 修改评价协议、数据划分或 baseline 使结果更好 | 方法效应与评价效应混淆，结论不成立 |

> 修复根因是唯一被接受的处理方式。后两类是学术规范红线。

### 视觉结构

三行表格，每行标注含义与影响。底部一句判断。

### 教师讲述备注

三区分决定 Agent 执行中哪些处理方式可接受、哪些是红线。重点演示：修复根因保留失败日志与根因分析；绕过失败注释断言让测试通过；污染实验调整 baseline 温度使两组接近。任务契约的"禁止"层与"人工审核点"层正是为了在 Agent 执行中阻止后两种——Agent 不允许修改评价协议、不允许删除失败日志、不允许在测试失败时自行修复。后两类是学术规范红线（沿用 [assessment.md](../../course/assessment.md)）。

### 互动／操作

让学生判断三段 diff 样例各属哪一类（教师提供）。

### 建议时间

24:00-28:00。

## P17｜退出卡：这次 Agent 执行可以被安全地重复吗

### 屏显内容

**常见错误**：

- 模糊 prompt 直接交给 Agent
- 权限开放到方便为止
- 人工审核点缺失（跑完才看一眼）
- Agent 输出被当作事实
- 绕过失败（注释断言让测试通过）
- 污染实验（修改评价协议使结果更好）
- 删除失败日志
- 重跑到成功

> 本课的"一次执行"是第 11 课"自动化循环"的前提：边界使执行可被安全地重复。第 11 课把 Edit → Evaluate → Keep/Discard → Repeat 落到固定指标、预算、停止条件和回退机制上。

**退出卡**：

- 今天最清楚的一点
- 仍然困惑的一点
- 我的任务契约五字段中哪一字最难写
- 我的权限分层是否落到任务级
- diff 审查六项中哪一项我没做到
- 我是否记录了至少一条失败或越权
- 我的产出是否回写了个人项目

### 视觉结构

上方常见错误清单，中间第 11 课预告，下方退出卡七项。底部一条"受限是循环的前提"提示。

### 教师讲述备注

回扣本课目标：学生只要任务契约五字段 + diff 审查六项 + 失败记录至少一条 + AI 使用记录一条，就已经形成第 11 课自动化循环的起点。第 11 课把本课的"一次执行"扩展为"循环"——Edit → Evaluate → Keep/Discard → Repeat，落到固定指标、预算、停止条件和回退机制。本课非正式提交门，产出回写个人项目。

### 互动／操作

学生提交退出卡或保存在个人项目。教师收集共性问题，用于第 11 课前调整。
