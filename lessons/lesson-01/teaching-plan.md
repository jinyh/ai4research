# 第 1 课教师教案｜AI 辅助科研导论、OpenCode 与八阶段研究链路

## 一、本课定位

- 学时：2 学时，90 分钟
- 研究链路：全链路概览
- 教学类型：讲授 + 演示 + 个人实践 + 同伴反馈
- 核心问题：如何让 AI 支撑科研，而不替代研究判断或破坏可追溯性？
- 课堂产出：个人 OpenCode 工作区、初步问题、八阶段链路草图、第一条 AI 使用记录
- 正式提交：无

本课必须同时建立三项共识：

1. 课程是 AI 增强的科研方法课，不是工具展示或现成 Skills 教程。
2. 八阶段研究链路和四个研究门是全课骨架。
3. OpenCode 是从第 1 课开始持续使用的工作平台，平台、模型和后端本身不构成评分项。

## 二、学习目标

完成本课后，学生能够：

1. 区分“AI 生成报告”和“有证据、有判断、有验证的科研闭环”。
2. 区分线索、证据、研究判断与结论。
3. 说出八阶段研究链路和四个研究门的基本关系。
4. 理解个人项目、固定同伴组和四次正式提交的组织方式。
5. 在 OpenCode 中完成一次范围受限、有人审核、留下记录的科研任务。
6. 为自己的研究兴趣写出初步问题和链路草图。

## 三、课前准备

### 教师

- [x] 按现行 33 页 `slides.md` 制作中文正式 PPT；必要英文只保留课程英文名、论文名、工具名和工件字段
- [x] 正式 PPT 继承 [交大模版.pptx](../../references/library/template/交大模版.pptx) 的母版、字体与品牌元素，并按设计准则扩展正文构图
- [ ] OpenCode 最小启动说明：安装、启动、模型/后端、项目目录和备用路径
- [ ] 演示仓库：只含 `AGENTS.md`、问题模板、AI 使用记录和 `notes/`
- [ ] 一次成功演示录屏或截图，防止现场网络/后端故障
- [ ] 一篇可快速拆解的短论文或论文片段
- [ ] 八阶段链路图、四门总览图和个人项目时间线
- [ ] [starter-template.md](../../course/starter-template.md)
- [ ] 同伴互看用的三问反馈卡

### 学生

- [ ] 笔记本电脑
- [ ] 可启动 OpenCode；无法启动者提前报告并使用备用环境
- [ ] 一个模糊研究兴趣即可，不要求已经有完整题目
- [ ] Git 和命令行基础环境

### 安全与资源口径

- 不要求学生自费购买 API token。
- 优先使用学校部署、开源或合规可用的模型和后端。
- 不将未公开论文、敏感数据、学生资料或私人凭据用于首课演示。
- 不要求开启全盘读写或无确认命令执行。

## 四、90 分钟流程

| 时间 | 内容 | 主要形式 | 产出 |
| --- | --- | --- | --- |
| 0-6 | 开场诊断：一份看似完整的 AI 研究输出，为什么仍不能提交 | 讲授 + 快问 | 风险判断 |
| 6-14 | 课程契约：个人项目、四次正式提交、同伴反馈与责任边界 | 讲授 | 课程预期 |
| 14-26 | 用同一条研究主张定位八阶段链路与四个研究门 | 讲授 + 反向检查 | 链路理解 |
| 26-43 | 教师演示：AI 提建议，研究者核验并只写回一处，保留 diff 与日志 | 教师示范 | 完整 trace |
| 43-48 | 发放练习任务、确认工作区与备用路径 | 任务说明 | 实践准备 |
| 48-75 | 个人实践：完成一次可审计交互并记录人工判断 | 个人实践 | 项目初稿 |
| 75-85 | 同伴互查：能否从工件复原"建议—判断—修改" | 2 人互查 | 反馈记录 |
| 85-90 | 知识点总结；退出卡与下一课衔接 | 总结 + 个人填写 | 知识回收与卡点 |

> 节奏对齐 `备课规划.md` v2.1.0 目标表。页码级修剪（如契约段 12 页→8 分钟）留待逐页映射门处理。

若现场环境故障，使用录屏完成 38-55 分钟的 trace 讲解，学生在纸面或 Markdown 模板中完成个人实践；不把课程时间消耗在逐台排障。

## 六、教师演示脚本

### 演示前状态

- 项目只含公开、虚构或可公开的内容。
- `AGENTS.md` 写明只读/可写范围和禁止访问目录。
- 终端不显示密钥。
- 网络访问关闭或不在本任务中启用。

### 演示判断点

1. 为什么第一轮只允许建议，不允许直接写？
2. 为什么第二轮只授权两个目标文件？
3. 如何检查 diff 和 AI 使用记录？
4. 如果 Agent 访问无关文件或提出越权动作，如何停止并记录？

### 失败演示

可预先准备一个越界请求：

> 扫描整台电脑，找到我以前所有相关论文和数据，自动整理到项目中。

让学生指出范围、隐私、版权、数据来源和不可逆写入风险，再改写为受限版本。

## 七、课堂产出验收

- [ ] OpenCode 或备用环境能够进入个人项目
- [ ] 项目与他人项目隔离
- [ ] 初步问题不是纯主题词
- [ ] 链路草图至少记录当前理解和主要不确定性
- [ ] AI 使用记录包含工具/模型、用途、Context、输出用途和人工核验
- [ ] 同伴反馈由作者自己决定是否采纳

本课不要求正式提交。学生保留并持续回写这些工件，第 6 课随问题门统一提交。

## 八、讲后复盘

教师课后记录：

- 实际安装/后端问题占用多少时间？
- 学生是否把 OpenCode 误解成课程目标？
- 哪个阶段概念最难理解？
- 学生问题规模是否普遍过大？
- 是否出现敏感材料、过宽权限或凭据风险？
- 第 2 课需要增加哪个伦理或权限案例？
