# 第 12 讲 · 个人工作流

将第 10–11 讲的同一科研任务组织为可运行、可审查的工作流。

## 带什么来

受限任务契约、循环说明、运行记录与失败恢复位置。

## 课堂怎么做

1. 比较确定性脚本、固定链与 Agent，选一种并说明理由。
2. 补齐任务、上下文、工具权限、状态、循环、评价、人工审核与恢复的必要字段。
3. 运行或演示最小路径，确认输入怎样变成输出。
4. 保留一条 trace，指出失败后在哪里停止或恢复。

## 做到哪里

一份最小工作流说明、可运行或可演示路径、一条 trace 和失败恢复位置；课堂不要求完成全部评价。

## 完成样例

[阅读卡回放包](../materials/reading-card.md)把源文本、预制输出、执行状态、人工标注和评价汇总连成一条路径。运行 `access-check`，观察 executor 请求 gold 被接口拒绝并记入日志；这验证指定接口的角色检查，不代表操作系统沙箱隔离。完整设计对应关系见[讲义](../lessons/lesson-12/handout.md)。

课后完善 `agent-workflow.md`，准备一次可用于第 13 讲评价的运行结果。本课不正式提交。
