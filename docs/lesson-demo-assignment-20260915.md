# 16 课助教演示准备清单

> 本轮落实：讲义、教案、母稿已按整体复审修订；16 课教案均有板书、诊断答案与过渡串词。核心包已通过实际复演。下表按当前材料更新；助教应对照现行 PPT 与母稿准备。见[内容实施记录](./course-integrated-revision-20260915.md)及[PPT 同步与验证](./course-ppt-sync-20260916.md)。

## 一、怎样分派

每课至少准备一个学生能看清“输入—操作—判断—结果”的完整案例。表中的“现场操作”要求打开实际文件、执行或修改；“材料回放”要求打开原文、存档或预制错误版本；“角色示范”要求教师与助教完整做一次学生将要进行的活动。

本清单依据现行教案与逐页母稿整理。已有教学文字不等于演示包已就绪；“待备”项需要助教实际制作或收齐。详细内容矛盾和板书、串词建议见[逐课教学审阅](./lesson-teaching-audit-20260915.md)。现行审阅职责与记录模板沿用[助教审阅协议](./ta-review-guide.md)及[记录模板](./ta-review-record-template.md)。

建议按连续案例分派，负责人姓名由教师填写：

| 工作包 | 课次 | 准备重点 | 依赖 |
| --- | --- | --- | --- |

## 核心材料已到位，助教接手后的验收

1. 打开[阅读卡运行包](../lessons/lesson-11/assets/reading-card-workflow/README.md)，使用新输出目录走受控失败、恢复、评价、接口拒绝四步。预期退出码为 2、0、0、3；其中两个非零码是故意设计的演示分支。
2. 独立复核 T01–T03 的 16 条条件标注：阅读卡缺 3/8，自由摘要缺 4/8；T02 无改善，T03 负向。程序只校验引用与汇总，语义由人核查。
3. 以实际日志填写演练记录：运行环境、日期、失败位置、恢复依据、完成用时和卡点。复演不需要模型账户。
4. 打开[评审校准包](../lessons/lesson-15/calibration-pack.md)，两人分别担任作者与评审者，完成意见、回应与改稿；然后转入学生真实项目。
5. 第 1–6 课的原文摘页、演示副本、浏览器书签，以及第 8、15、16 课人数与换场，仍按下列准备卡收齐并现场验收。不能把“内容已写好”记成“现场已通过”。

## 三、每课助教准备卡

### L01：一次建议如何变成项目变化

- **输入**：用“阅读卡能消除摘要遗漏”的构造问题建立小项目；预置权限说明和空日志，设定可恢复起点。
- **主演**：教师先在 P15–P22 用阅读卡相对自由摘要的同一问题解释研究链；P23–P28 助教操作，教师组织学生判断建议。只授权 Agent 修改 `problem-definition.md` 的“当前问题”段；核对实际 diff 后由人补修改记录与日志。结束回指 P16，明确本次只完成阶段 1，下一步定义遗漏并准备比较材料。
- **失败**：用预制副本展示多改了另一个段落；指出越界、保存证据、恢复后重新授权。不要等待现场模型碰巧犯错。
- **交付**：项目起点、完成版、实际 diff、一条日志、失败版与恢复步骤。P06 圈词核查是思考题；P07–P09 是论文及评论材料解读，无须运行 AI Scientist。

### L02：风险怎样进入执行边界

- **输入**：一份醒目标为虚构的合作稿对象描述、一段可公开的替代输入、过宽权限行。
- **主演**：原稿停留在不可读区，先只读审查，教师批准后写风险卡、权限行、日志三处；核对实际改动。
- **失败**：“已经发送”只做桌面情境推演；让学生提出第一步，再演示记录事实和切换路径。不得用真实未公开稿重现。
- **交付**：三份前后文件、批准范围、diff、离线填表包。原始规范摘页需由助教在授课前核对版本与适用对象。

### L03：查询和引用核验是两个动作

- **输入**：一个探索问题及查询式；另一张已知题名的 Keshav 身份核验卡。明确说明后者是核验动作校准，不声称它由前一条窄检索命中。
- **主演**：现场记录一条查询；再用题名/作者查元数据、打开 PDF 定位一条主张、写候选表。
- **失败**：MI §6 四条错引择一完整展开，其余列在存档；用题名查询找回正确 ID。
- **交付**：实际请求、日期、响应、PDF 必要页、核验后条目、错引与恢复记录；两个查询目的分开。无法核验的真实条目按实际状态记录，不为凑 `pending/rejected` 制造错误。

### L04：逐句比原文，才看得见“错读”

- **输入**：Keshav 原文 p.83–84、两句显著标记为课堂构造的错误转述、空阅读卡。
- **主演**：圈出“50%”“固定”，定位原文，改为原文支持的表述，写一行偏差审计。
- **扩展**：MI 先用普通话解释“改动更少就改变输出”和“真的找对了正常机制”的区别；从 C02 到 C31 只完成一次推断收窄，C16 作辅助材料。
- **交付**：原文书签、错误/正确转述对照、填好一行的卡、MI 术语便签及证据位置。

### L05：同一条记录如何成为综述

- **输入**：两条已核验阅读记录、一条不同设置的限制材料、一个空白子问题。
- **主演**：先问是否同问题、同条件、同指标；再把两条记录放进矩阵/地图，写四句综合。MI 五条证据全部备齐，现场展开核心两条。
- **失败**：把“不同设置的限制”误写成“直接反驳”，当场改回；把空行误当领域空白，改为缺少某子问题的证据。
- **交付**：卡→矩阵→地图→四句的前后状态，不重复录入同一信息。L06 接回阅读卡项目的过渡句一并准备。

### L06：问题取舍要可见

- **输入**：从现行讲义取 G1/C2/C3 候选，预填背景与已知材料；留取舍理由和问题句供现场填写。
- **主演**：选择一题，圈出对象、比较、指标，写非例和一项待检验前提，再指出什么观察会使结果主张站不住。
- **失败**：展示“失败预案”与“已发生的检索死路”两张记录，比较它们对问题门的作用；构造样例只训练判断，学生提交须用本人实际记录。
- **交付**：统一阅读卡项目的门状态表；主演已移除 MI 依赖；MI 仅作课后迁移阅读。

### L07：两个解释怎样被区分

- **输入**：同一问题的一条结果命题、一条机制候选，以及如“评价者看到字段提示产生评分差异”的另一解释；备两种明确标为教学构造的观察组合。
- **主演**：画出机制路径，比较能区分机制候选与测量解释的观察；具体命题已写入讲义与母稿，按课程阅读卡案例口径使用，不从头运行实验。
- **失败**：只测一个指标却声称机制成立；改为结果方向吻合、机制未决，并写下一项区分观察。
- **交付**：两行假设卡、观察卡、对应研究判断；另用一句话说明“其他错误增加”检查整体质量，“特定论文有效”检查范围，不把它们一律当作对遗漏下降的反驳。

### L08：必须真正演一次分享

- **输入**：与教案一致的阅读卡五段陈述稿；教师主讲、助教扮演反馈者。
- **主演**：一轮完整陈述、具体质询、含混意见的澄清、作者写一条处理决定，再改一处方案。
- **分组**：3–4 人组每人一次 3 分钟陈述＋2 分钟合并反馈；40 分钟中明确基础轮、追问、补记的次序。三人组每人仍收到两位同伴反馈。
- **交付**：按实际人数的组表、轮次表、记录入口、缺席预案。P10–P11 已与教案统一阅读卡案例，只演一套主线。

### L09：能运行，还要能发现记录不一致

- **输入**：现有四条合成记录和冻结配置；备一份将结果写错的副本。
- **主演**：运行校验，打开输入、配置、结果、日志；在副本中引入不一致，再运行并解释失败。
- **边界**：四条记录验证追踪与复算，不代表当前六份构造输出来自真实模型实验，也不证明阅读卡效果。
- **交付**：可复算包、错误副本、命令的工作目录说明、学生可用的离线记录。本次成功与不一致路径均已验证。

### L10：修代码与改标准的区别

- **输入**：现有 `before/generate.py`、`after/generate.py`、不可修改的测试。
- **主演**：先看缺字段测试希望什么行为；前版产生 `KeyError`，后版明确报告 `ValueError`；对照 diff 并运行两项测试。
- **失败**：使用现有“请求修改 tests”的记录，教师拒绝，并指出它改变验收标准。该文字记录的历史来源尚未在本轮验证为真实 Agent 会话，不标成新发生的模型越权。
- **交付**：一致的 task、函数名、测试框架和失败对象；SWE-bench 只解读任务/补丁/测试结构，无须下载并运行完整基准。

### L11：小队列与恢复

- **已有**：小输入集、配置、运行入口、账本、受控故障与恢复步骤均在阅读卡包。助教从新目录独立复演，记录实际用时；预置内容和真实回放日志分开标记。
- **主演**：逐项处理输入，保留一次结果无改善和一次技术失败；经人工决定后恢复未完成项，失败条目仍在账本。
- **对照**：另用固定版本 AutoResearch 文档说明“改方法并选优”的循环，与“固定方法收集全部结果”的队列区别。
- **交付**：任何一条运行都能反查输入和配置；三种情况不能靠现场随机输出碰运气；只回放既定六个任务，不追加随机输出。

### L12：从队列到可交接原型

- **已有**：直接使用 L11 小包的状态、评价入口和接口拒绝；工作流说明见本课讲义。助教补自己的实际演练记录，不另造主题。
- **主演**：给一个输入，走到输出，指认持久状态；执行端提出读 gold 的请求时展示拒绝点，再用新 run ID 走合规路径。
- **判据**：若只是用构造 trace 手动回放，就标明回放；如果声称权限实际强制执行，必须演示真正拦截，不能仅凭 prompt 写“禁止读取”推断权限已被限制。
- **交付**：可由另一名助教按说明复演的目录，外加 AutoResearch 固定版本的只读摘页；不安装或运行其训练循环。

### L13：评价输入必须先到位

- **输入**：本人已有结果，或教师明确构造的评价包。现有样例仅有汇总数和文字负例，不足以演示逐条复算。
- **已有**：三份构造源文本与逐项标注已经齐全；助教独立核验语义、分母8和T03负例，直接复演，不再反推历史数字。
- **主演**：只改一张对照、一项局限、一条判断；若只用现有汇总样例，就只演示解释和写回。
- **交付**：先修 L07 命题关系，再统一 A1/A2/A3；总体与子集负例各有清楚位置，原冻结样本中的负例继续保留；未定义 ± 从主演材料移除或补定义后重算。

### L14：亲眼看见段落形成

- **输入**：L13 同一评价对象、一段过度结论、对应日志和追踪行。
- **主演**：先定位结果，再逐句写主张、证据、推理、边界；最后从日志写一段披露，指出真实缺失项。
- **失败**：把“机制证实”改为观察范围内的结果；读者应能分清描述性结果与机制未决。
- **交付**：初稿、改后稿、可见 diff、追踪条目和披露摘要；课堂写作包里的数值与 L13 一致。

### L15：校准三种严重度

- **已有**：校准包已含主结论、关键记录和表达三个问题及教师判据；助教按角色完整演一次，再记录耗时与易混点。
- **主演**：学生先定位，教师解释为什么影响程度不同；助教给意见，教师作作者回应，再实际改文件。
- **失败**：单有“证据不足”不能一律改为“支持（待验证）”；没有支持时应记仍不能判断，有反向证据时按证据判断。
- **交付**：校准稿、参考评审、回应、实际修改、剩余缺口；真实评审轮次仍以学生个人初稿为主体。

### L16：演的是学生项目与现场组织

- **课前**：收齐按名单排序的展示页、分组表、项目入口和离线备份；明确每组记录人。
- **主演**：学生闪电报告只讲三项，深层证据与工作流移到分组；教师抽查 2–3 人，助教维护全员完成记录。
- **故障**：演练一个学生页打不开、一个日志打不开的情况；继续换场，缺口登记后补，不在台上处理环境。
- **交付**：25 人容量下包含换场的排程、每人展示记录、抽查记录；实际班额不同需重算。L16 内容门和正式 PPT 同步仍由教师／主笔完成。

## 四、每个演示包的统一交付

1. **一页运行说明**：对应课次/页码、教学问题、输入位置、操作步骤、关键停顿、预期观察、离线替代。
2. **起点和完成态**：足够复演的文件或原文片段，明确真实原件、教学构造、实际执行与静态回放的身份。
3. **一条失败分支**：学生能看见问题、教师能说明处理理由；重试与原失败均留记录。
4. **课堂试演记录**：实际耗时、首次学生动作、学生可能卡在哪、是否在教案时段内完成。录屏如需制作，仅使用已授权教学素材。
5. **验收签字位**：准备者、复演者、日期、通过项、未解决项、教师取舍。没有复演证据时状态写“待实测”。

准备稿先放 `.work/`。需要成为长期教学资产时，由主笔按课次归入 `lessons/lesson-NN/` 并同步讲义、教案和母稿；正式发布仍沿用原质量门。这里没有新增学生作业或研究门条件。
