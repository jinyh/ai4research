# 博士助教课前审阅与桌面推演协议

## 一、目标与角色边界

本协议用于开课前发现“材料已经写完，但学生仍无法找到、理解或执行”的问题。审阅者以两种身份工作：

1. **学生代理**：不依赖备课者口头补充，从课程网站和学生材料完成规定动作；
2. **博士研究者**：用真实研究经验判断案例、选题、实验与失败归因是否符合科研实践。

博士助教可以判断真实性、可执行性、认知负荷、术语清晰度和现场节奏，并提出证据清楚的修改建议。以下事项由任课教师最终决定：

- 评分比例、研究门条件和正式提交口径；
- 实际提交平台、截止时间和班级分组；
- 未发表材料的授权、脱敏和课堂使用范围；
- 正式材料定稿、对外发布和课程结构调整。

审阅不直接修改正式讲义、教案、PPT 或权威课程文件。需要修改时先提交反馈记录，由主笔按备课门控流程实施。

## 二、安全与材料边界

- 使用真实课题时，可提交公开论文、公开仓库和自行撰写的过程复盘；不在反馈记录中粘贴未发表数据、学生资料、凭据或受限稿件。
- 未发表 MI 素材只在教师授权范围内人工处理，不上传外部 LLM、在线制图或在线文档服务。
- 真实学生材料用于评审校准前必须取得授权并脱敏；无法确认时使用课程明确标注的虚构教学工件。
- AI 输出可以帮助发现线索，但反馈结论必须指向具体页面、字段、运行记录或现场观察。

## 三、执行包

### A. 学生完整路径试走

从[课程网站首页](../web/docs/index.md)开始，不预先打开仓库文件列表，完成以下动作：

1. 找到第 1 课讲义、早期研究脚手架和伦理模板；
2. 找到四个 Checkpoint 的时间、条件、提交形式和修订规则；
3. 找到第 9 课迁移后的完整项目模板；
4. 找到一个阅读卡示例、一个可复现工件、一个 Agent 任务示例、评价报告模板和同行评审模板；
5. 说明正式提交应进入哪个教师指定入口；若当前入口尚未发布，能否明确知道下一步应查看哪里，而不是自行选择邮箱或外部网盘。

记录每次出现的断点：入口不存在、链接降级、命名不一致、需要猜测、页面可达但用途不清。网站有链接但学生不知道为何使用，也应记录为问题。

### B. 真实课题试填（第 5–9 课）

选择一个可公开描述的真实研究方向，依次完成：

1. 生成至少三个候选题，覆盖至少两条问题生成路径，其中至少一个不来自文献空白；
2. 用意义、新颖性、可行性、兴趣四维标准比较并记录取舍；
3. 将选定问题写成有范围、非例和推翻条件的可证伪命题；
4. 写出一个主机制假设和一个可区分的替代假设；
5. 建立最小 baseline 与实验规格，标出拟用 Agent 和必须人工判断的步骤；
6. 对照 Checkpoint 1、2，标记哪些字段可直接完成、哪些需要教师解释、哪些不适用于该研究类型。

重点反馈：课程是否把“检索到 gap”误当成问题来源；四维标准是否能解释真实选题取舍；MI 案例的方法能否迁移到非 MI、非深度学习或非实验型 CS 课题。

### C. 失败分层归因

用公开或自行概括的研究经历，分别测试三类失败：

| 层级 | 最低案例要求 | 必须回答 |
| --- | --- | --- |
| 实现层 | 代码、环境、数据处理或配置错误 | 如何复现；修复后复测什么；写入哪条 failure log |
| 效度层 | 控制集、样本、随机性、领域或指标使结果不能推广 | 主张应收窄到哪里；缺什么对照；回写哪项研究判断或证据地图 |
| 假设层 | 实现与评价成立，但基本机制假设未获支持或被反驳 | 修改、替换还是放弃假设；停止条件是什么；保留哪些负向证据 |

若同一案例可以被无依据地分到多个层级，记录造成歧义的字段或诊断步骤。反馈应帮助形成“先排除实现，再检查效度，最后修改假设”的可执行顺序，而不是只给失败贴标签。

### D. 关键课次桌面推演

| 课次 | 推演任务 | 记录指标 |
| --- | --- | --- |
| L1 | 从打开项目到留下人工判断、一次有限写回、diff 和 AI 使用记录 | 环境准备时间；首次闭环时间；链路草图是否形成额外负担 |
| L2 | 把一个材料风险转成权限矩阵、确认点和风险卡 | 最易混淆字段；规范解释是否挤压个人实践 |
| L8 | 按当前人数完成 3 分钟陈述和结构化反馈 | 每人实际占用；单轮/双轮是否可行；反馈是否落到具体方案 |
| L15 | 完成一轮校准、同伴评审、作者回应和修改排序 | 评审是否落到五维 rubric；15 分钟单轮是否可完成 |
| L16 | 展示、复现抽查、论证门检查与课程复盘 | 实际人数可用方案；抽查深度；哪些环节必须移到课前或并行进行 |

推演按实际选课人数记录主方案和备用方案。不能只写“可能超时”；应指出超时发生在哪一步，以及缩减哪项仍能保持学习目标。

### E. 演示工件与模板检查

逐项确认以下材料是否存在、可打开、可复制、字段与讲义一致，并能在断网或无模型时使用：

- L2 权限矩阵、风险卡和 AI 使用记录；
- L6 完整问题定义与失败反例；
- L9 实验规格、不可复现实验反例和可复现工件；
- L10 任务契约、diff、测试输出和越权失败日志；
- L13 评价报告模板、失败审计和虚构样例；
- L14 评价报告到论文段的改写对象；
- L15 匿名评审校准对象、同行评审与修改计划模板；
- L16 收口版报告、评价报告、论证断裂反例和复现抽查清单。

缺少真实工件时，判断当前虚构工件是否已同时标明“虚构”和“不承担实证结论”。需要替换为真实材料时，单独标注授权与脱敏依赖。

### F. 网站、PowerPoint 与教室检查

- 网站：Windows/macOS 各至少一种常用浏览器；检查导航、表格、代码块、SVG、下载链接和窄屏横向滚动。
- PowerPoint：在实际授课电脑用 Microsoft PowerPoint 打开全部课件，抽查封面、长标题、关键表格、来源页和收束页。
- 投影：从教室后排检查教学信息、虚构标记、权限状态和研究门标签；记录字体替换、裁切、低对比或动画/切换异常。
- OpenCode：使用课堂计划中的主要环境和无模型备用路径各完成一次最小动作，不把安装排障计入学习目标完成。

## 四、统一反馈记录

开始审阅前复制[博士助教审阅记录模板](./ta-review-record-template.md)，一位审阅者或一次完整试走使用一份记录；不要直接在本协议中填写结果。

每条问题使用一行，避免只写总体感受：

| ID | 材料与位置 | 问题类型 | 复现或观察证据 | 影响等级 | 建议修改 | 是否涉及教师决策 | 状态 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| TA-001 |  | 内容 / 节奏 / 可执行性 / 网站 / PPT / 安全 |  | 阻塞 / 重要 / 建议 |  | 是 / 否 | 待处理 |

影响等级定义：

- **阻塞**：学生无法完成目标动作、找不到正式入口、存在事实/权限/隐私风险，或课堂主流程无法执行；
- **重要**：能继续但需要教师临场补充，容易形成错误理解、明显超时或产出不可验收；
- **建议**：不影响目标闭环，但可改善语言、可读性或便利性。

桌面推演另附一张记录：

| 课次 | 场景与人数 | 计划时间 | 实际时间 | 首次学生动作 | 最小产出完成度 | 卡点 | 建议 |

## 五、交付与关闭条件

本轮博士助教审阅至少交付：

1. 一份学生路径试走记录；
2. 一份真实课题的 Checkpoint 1–2 试填或字段差距表；
3. 三层失败案例与归因记录；
4. L1/L2/L8/L15/L16 桌面推演记录；
5. 演示工件缺口表；
6. 网站、Microsoft PowerPoint 和教室投影检查结果。

阻塞问题关闭后才能标记“可正式发布”；重要问题应在对应课次授课前关闭或登记明确备用路径。修改课程权威口径、正式材料或 PPT 后，仍须重新执行对应备课门和验证，不以助教“看过”代替门控。
