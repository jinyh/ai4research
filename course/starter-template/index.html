    早期研究脚手架模板¶

    本模板用于第 1-6 课的个人选题、文献和证据整理阶段。它的目标是帮助学生在 OpenCode 个人项目工作区中建立研究问题、AI 使用记录、Agent 权限边界、伦理意识和最小追踪关系，而不是提前搭建完整工程项目。

    不要在此阶段强制创建 src/、experiments/、复杂配置系统或完整论文结构。代码和实验脚手架应在第 7-8 课完成机制假设、研究判断和方案分享，并在第 9 课明确 baseline 和实验规格后再引入。

    使用时机¶

    • 第 1 课：选定研究方向，写出初步问题和八阶段链路草图。
    • 第 2 课：建立 AI 使用记录、Agent 权限矩阵、科研伦理检查清单和轻量工件追踪表。
    • 第 3-6 课：逐步补充文献、精读卡、证据地图、研究问题和第一性原理推导，通过问题门。
    • 第 7-8 课：继续补充机制假设、研究判断、实验设计和同伴反馈。
    • 第 9 课：baseline 和实验规格明确后，迁移到完整的 project-template.md。

    最小文件结构¶

    建议早期项目只维护以下文件：

    project/
├── AGENTS.md
├── problem-definition.md
├── reading-cards.md
├── failure-log.md
├── artifact-tracking.md
├── ai-usage-log.md
├── agent-permissions.md
├── ethics-and-compliance.md
└── notes/

    notes/ 可用于保存检索式、课堂反馈、临时想法和阅读摘记。进入问题门前，再将稳定内容整理为正式工件。

    AGENTS.md 最小模板¶

    AGENTS.md 是可执行的任务边界声明。建立个人项目时可直接使用以下最小版本，第 2 课起随任务逐次收紧或放宽：

    # 项目边界

- 只读：problem-definition.md、reading-cards.md、notes/、本课程提供的模板；
- 可写：仅 problem-definition.md、ai-usage-log.md、artifact-tracking.md、notes/；扩大需人工确认；
- 权限扩大与状态迁移（agent-permissions.md、ethics-and-compliance.md）必须等待人工确认；
- 命令执行：逐项确认，不批量放行；
- 网络：默认关闭；任务需要时先声明范围再确认；
- 不访问：项目外目录、私人路径、凭据、未公开或保密材料；
- 每次交互后列出实际修改文件，等待人工检查。

    4. 轻量工件追踪表¶

    早期只追踪必要工件，避免把精力耗在维护状态上。

    工件 状态 来源 依据 后续用途
    问题定义 draft 个人兴趣 / 领域现象 初步观察 文献检索、问题门
    候选文献列表 draft 检索式 问题定义 证据地图
    精读卡 draft 正式文献原文 原文位置与人工核验 证据地图、问题门
    失败记录 draft 检索、阅读或问题迭代 失败表现、原因与处理 问题门、后续研究判断
    AI 使用记录 draft 工具交互 人工核验 透明披露
    科研伦理检查清单 draft 数据和任务设定 课程规范 题目边界判断

    状态定义：draft（初稿）→ review（待审查）→ approved（已通过对应门）→ stable（可引用）。状态用于追踪成熟度，不作为孤立评分目标。

    关键结论至少绑定一项可核验的直接证据或实验结果。准备标记为 stable 的结论原则上需要两项相互独立的证据；只有单一证据时，记录支持强度、适用边界、缺失证据和待验证状态。

    5. AI 辅助精读卡¶

    问题门前至少完成 3 张与个人研究问题直接相关的精读卡。AI 可以先帮助建立阅读地图，但最终内容必须由学生回到原文核验。每张卡复制并填写以下字段：

    精读卡：______¶

    • 完整书目信息（作者、题名、年份、出版物、DOI / 稳定链接）：
    • 来源类型与证据角色：
    • 本文试图回答的问题：
    • 作者的中心主张：
    • 关键证据及原文位置（章节 / 页码 / 图表 / 公式 / 实验）：
    • 数据、实验设置或论证前提：
    • 适用范围、局限与可能反例：
    • 与本人项目的关系：
    • AI 初始阅读地图（标记为未核验）：
    • 人工核验过程与结果：
    • AI 的错误、过度概括、遗漏或已检查风险：
    • 最终人工判断：

    AI 辅助阅读采用“AI 导航→原文核验→AI 质疑→偏差审计→人工定稿”。至少记录两个可复查的原文位置。如果未发现明显 AI 错误，记录检查过的高风险判断及核验依据，不虚构错误。

    6. AI 使用记录¶

    日期 工具 / 模型 用途 关键输入 Context / 数据来源 输出用途 人工核验方式 问题或误导

    AI 可以辅助检索、阅读、改写、代码和调试，但不能替代研究问题是否重要、证据是否成立、实验是否公平和结论是否准确的判断。AI 生成的书目信息、页码、DOI 和引文必须回到正式来源逐项核验。

    7. 轻量失败记录¶

    只记录真实发生且改变过研究推进的失败、死路或放弃项。一次无结果检索、被证据排除的方向、被放弃的问题版本均可入表；不要为了通过门而虚构失败。

    记录 ID 日期 失败对象或死路 预期与实际 原因判断及依据 处理方式 回写位置 当前状态
    F-001 重试 / 收窄 / 放弃 / 保留待查 问题定义 / 检索记录 / 精读卡 / 证据地图 open / resolved / accepted

    问题门前至少选一条记录，确认它已经回写到对应研究工件，而不只停留在日志中。

    8. Agent 权限矩阵¶

    OpenCode 是课程主要工作平台，但早期默认最小权限。只开放当前科研动作需要的文件、工具和网络。

    对象或能力 只读范围 可写范围 是否允许执行 人工确认点 禁止事项
    项目 Markdown
    代码与命令
    文献与网络
    数据目录
    外部 API / MCP

    说明：

    • 不向外部模型发送未公开论文、核心实验数据、学生资料或其他敏感材料。
    • 不允许 Agent 自行扩大数据访问范围、修改评价协议或删除失败记录。
    • 权限变化必须写入 AI 使用记录并说明理由。
    • AGENTS.md 是权限矩阵的可执行任务边界声明；建立个人项目时直接使用"最小文件结构"中的最小模板。

    • 数据是否来自公开、合法、可使用来源：
    • 是否涉及隐私、敏感属性、人类受试者或高风险用途：
    • 是否需要更换题目、脱敏数据或缩小范围：

    对每一项计划交给 AI 或 Agent 的科研动作，可以再填写一张五字段风险卡，把判断落到具体动作而不是笼统的"注意伦理风险"：

    对象（Asset） 动作（Action） 风险（Risk） 控制（Control） 责任（Owner）
    涉及什么材料、数据、账户、文件或外部系统 读取、生成、修改、执行、发送还是公开什么 可能损害真实性、隐私、保密、许可、安全、公平或可复现性的哪一项 缩小 Context、脱敏、本地处理、只读、人工确认、日志或停止条件 谁决定是否继续，谁核验结果，谁对最终使用负责

    10. 进入完整模板前的条件¶

    满足以下条件后，再迁移到完整项目模板：

    • 已有一个清楚的研究问题和至少一个非例。
    • 已有 10 篇左右候选文献或等价外部材料。
    • 已有至少 3 张完整精读卡，能区分作者主张、原文证据、AI 建议和人工判断。
    • 已有初步证据地图或相关工作矩阵。
    • 已记录至少一条真实的失败或死路，并写明原因、处理方式和回写位置。
    • 已通过问题门，并根据第 8 课同伴反馈修订研究计划。
    • 已能说明一个可运行 baseline 或最小原型大致是什么。
    • 已知道哪些实验结果会支持或反驳核心假设。
    • 已明确初步 Agent 权限边界，不会在迁移时把外部或敏感数据纳入项目仓库。
