# 考核方案

## 课堂难度与课外总预算

面向已有编程、机器学习、英文论文阅读和 AI 使用经验、科研经验有限的计算机研究生。AI 可以参与真实研究动作；评价学生能否解释关键选择、核验结果，并在新证据或新条件下更新判断。讨论和同伴意见是可选输入，不要求固定搭档、同伴一致或签认。逐课输入、核心判断、验证和去向见[研究判断路径](./judgment-path.md)。

课外总投入每课最多 60 分钟，包含阅读、准备、安装排障、项目推进和提交整理。普通课为指定阅读 15 分钟＋准备 10 分钟＋项目补全 35 分钟；L6/9/13/16 为整理 15 分钟＋修订提交 45 分钟，不叠加新必读。所需主要操作与研究门检查在课堂完成。超出预算先缩小材料或任务范围，不把未完课堂任务整体转移到课后。

MI（机制可解释性）是教师贯穿全课的研究 Demo；学生从第1课起维护自己的个人项目，方向不限于 MI。短时共同诊断用于理解方法，个人实践回到本人课题。尚未确定课题者使用可替换的公开小问题，至L6收敛。L4–L6围绕本人问题累计三张核心精读卡；每人实际执行一个 AI 研究工作流并作一次有依据的改进。

本文件的“假设／机制”指可检验解释或方案依据，不专指神经网络机制；“实验”包括相称的验证，“baseline”包括现有方案或检查方法。理论、文献项目可用前提、推导、反例、覆盖审计与独立复核完成同等要求；保留评价关注未参与优化的证据，不统一要求数据集三分。实际AI工作流与一次有依据的改进仍须完成。

## 总体结构

课程采用过程性评价与最终个人项目结合的方式。核心考核不是"用了多少 AI 工具"或安装了多少现成 Skills，而是学生是否形成了可验证、可复现、可追溯、有门的科研闭环，并能为自己的科研动作设计、实现和评价一个可审计的 Agent Workflow。

课程不设置每周作业分。第 6、9、13、16 课的四次研究门材料作为过程性评分证据；第 8 课个人分享与公开质询、第 15 课独立匿名评审是形成性活动，不单独按演讲或课堂表现计分。个人产物和新情境下的解释构成独立判断证据。

| 项目 | 比例 | 说明 |
| --- | ---: | --- |
| 文献与问题定位 | 25% | 文献检索、证据角色判断、证据地图、阅读卡片、相关工作矩阵、研究问题质量、非例和可证伪命题、第一性原理推导 |
| 实验设计与可复现性 | 30% | 假设、baseline、指标、实验规格、研究判断记录、配置、日志、复现说明、结果可追溯性 |
| 原型与 Agent Workflow 实践 | 25% | 可运行原型、自主工作流设计与实现、权限边界、自动化或可重复执行机制、评价报告、失败分析、证据充分性说明 |
| 表达、伦理与复盘 | 20% | 论文式短文、展示、同行评审、结论可追溯性、科研伦理说明、AI 使用反思、门条件满足 |

### 课堂反馈与评分映射

| 尺度 | 判断依据 |
| --- | --- |
| 需支持 | 完成操作，但理由、证据定位或验证仍有缺口。 |
| 达标 | 独立决定，证据可定位，完成相称验证，并更新本人项目。 |
| 优秀 | 识别替代解释或有效性威胁，以额外检查改变或加强判断。 |

课堂尺度对应课程的待改、达标、卓越；不新增每周成绩或提交。优秀依判断质量，不要求更多课外时长。

### 四级表现锚点

下表与后续评分细则配套使用。教师先依据四次研究门中的实际工件判断证据，再在每个评分维度内确定等级；等级不是对论文是否发表、是否新颖或使用了多少 AI 的预测。

| 等级 | 可观察表现 |
| --- | --- |
| 卓越 | 关键判断有直接证据与清楚边界；能够主动发现冲突、失败或替代解释，并把它们回写到问题、实验或工作流；他人可复现主要过程并理解取舍。 |
| 达标 | 主要工件完整且可核验；问题、实验、权限、日志和结论基本一致；关键结论可追溯，局限与人工审核有明确记录。 |
| 待改 | 已形成部分工件，但存在重要证据缺口、不可复现步骤、权限或披露模糊、结论超出结果等问题；经明确修改可以达到门条件。 |
| 不达标 | 关键工件缺失或不可核验；编造来源、数据或结果；用工具完成报告替代研究判断；越权、隐瞒 AI 参与或无法说明个人贡献。 |

四个评分维度沿用同一等级名称，但依据不同：文献与问题定位看问题—证据关系，实验设计与可复现性看协议—结果关系，原型与 Agent Workflow 看任务—权限—评价关系，表达、伦理与复盘看结论—来源—责任关系。详细条目用于解释和复核等级，不要求每个项目机械满足同样数量的证据，也不保证研究工作能够发表。

## 研究门条件

项目推进需通过四个研究门。详细、可执行的门条件以 [assignments.md](./assignments.md) 为准，本文件只定义评分关系，避免维护两套重复清单。

| 研究门 | 时间 | 正式材料 | 主要对应评分维度 |
| --- | --- | --- | --- |
| 问题门 | 第 6 课后 | 问题定义、精读卡片、证据地图、非例、可证伪命题、第一性原理、周期可行性和一条已回写的失败/死路记录 | 文献与问题定位 |
| 判断门 | 第 9 课后 | 机制假设、研究判断、实验 baseline、本人已有 AI 工作方式与评价协议、复现说明、方案质询处理、风险和一条已遇执行失败/已放弃方案记录 | 实验设计与可复现性 |
| 验证门 | 第 13 课后 | 个人 Agent Workflow、运行或演示原型、权限边界、评价与迭代记录、失败分析 | 原型与 Agent Workflow 实践 |
| 论证门 | 第 16 课 | 论文式报告、最终工作流、伦理与 AI 使用披露、同行评审处理、展示与复盘 | 表达、伦理与复盘 |

前三个研究门第一次未通过时允许一周内修订。第 15 课进行论证门预检，不单独正式提交；第 16 课将论证门与最终个人项目合并检查。

## 评分细则

### 1. 文献与问题定位，25%

- 文献检索覆盖主要关键词、代表性方法和近年工作。
- 每篇候选文献标注了证据角色（主证据/补充证据/对比证据/探索线索）。
- 阅读卡片能区分作者主张、原文证据、实验设置或论证前提、适用范围、局限和学生自己的判断。
- 使用 AI 辅助阅读时，阅读卡保留未核验的 AI 初始地图、至少两个原文核验位置、偏差/遗漏或已检查风险及人工修正；不按 AI 使用多少评分，只评价核验质量。
- 证据地图不是简单摘要堆叠，而是组织了主证据、补充证据和空白，支持问题定位。
- 研究问题具体、重要、可检验，且能说明与已有工作的差异。
- 研究问题包含非例和至少一个可证伪命题。
- 第一性原理推导从基本原理出发，写出必要条件、关键约束或可检验前提。
- 至少一条真实失败或死路记录能说明原因、处理方式和回写位置；记录质量按其是否改变研究判断评价，不按失败数量评价。

### 2. 实验设计与可复现性，30%

- 假设清晰，能被实验支持或反驳。
- baseline、数据、指标和评价协议选择合理；写明证据角色、独立单位、反馈使用、搜索次数与成本，并区分结果、机制和采用判断。
- 实验规格完整：假设对应、变量、步骤和度量标准已写明。
- 研究判断记录写明取舍理由、适用边界和待验证状态。
- 实验配置、随机种子、环境依赖和运行命令记录完整。
- 结果表格或图表能追溯到具体实验记录。
- 能说明威胁有效性和可能的混杂因素。
- 已遇执行失败或已放弃备选方案有可追溯记录，并已回写到研究判断或实验规格；前瞻预案不替代已发生记录。

### 3. 原型与 Agent Workflow 实践，25%

- 原型可以运行，且与研究问题直接相关。L9–13 保留本人实际执行、实质修改、同输入对照与可追溯记录；预制回放证明流程可检查，不能直接证明模型或工作流改善。
- 个人工作流服务一个明确科研动作，而不是复刻工具功能或展示现成 Skill。
- 工作流写清任务契约、输入、输出、成功标准和不适用范围。
- 有可运行或可演示的实现，可以使用 `SKILL.md`、项目指令、脚本、MCP 或其他组合。
- Context、Memory、研究工件、工具、数据来源和状态传递方式清楚。
- 只读/可写范围、禁止访问项、预算、停止条件和人工确认点明确。
- 有至少一种自动化或可重复执行机制，例如参数扫描、实验队列、证据整理、结果汇总、失败分类或审计。
- AI 生成的代码、实验建议或分析结论经过人工审核。
- 自动优化有固定评价指标、搜索空间、停止条件和失败实验记录，不允许只保留成功结果。
- 工作流评价包含 baseline、前后对比、对照或等价依据，能说明它是否真正改善了研究动作；反复选优后的结论说明独立评价安排，等预算对照与独立评价分别检查。
- 失败实验、无效建议和局限有记录、有解释，不只提交成功结果。
- 评价报告说明实验/运行结果与原假设的关系，以及关键结论的证据来源、支持强度、冲突、缺失证据和待验证风险。
- 不因使用 Pi Agent、OpenCode、Claude Code、Codex 或其他特定平台获得额外分数。

### 4. 表达、伦理与复盘，20%

- 论文式短文结构完整，包括问题、方法、实验、结果和局限。
- 每个关键结论至少能追溯到一条证据和一个上游决策。
- 标记为 `stable` 的结论原则上有两项独立证据；证据不足时已降级状态并说明缺口。
- 图表说明准确，不夸大实验结论。
- 展示能清楚说明研究闭环和关键证据。
- 科研伦理与合规说明覆盖数据来源、隐私、许可、署名、AI 使用披露和潜在误用。
- AI 使用复盘具体，包括有效用法、误导案例、验证方法和自动化的适用条件与待验证部分。
- 能说明个人工作流输出如何通过证据、实验 ID、evals 或人工 review 被审计。
- 四个研究门的门条件已全部满足。

## 独立判断与工作流改进的评价

学生可以让 AI 参与问题、假设、实验、分析与评审。评分检查其能否解释采纳或否定建议的依据、识别替代解释，以及面对新证据或新条件时更新判断。讨论和自愿协作不改变个人评分；不按同伴一致、相互签认或反对 AI 的次数加分。

每人完成一次真实 AI 工作流运行与有依据的改进，并与原有 AI 工作方式作资源可比的评价。负结果、没有改进或有依据地保留原方案均可达标；深入 RSI 不设工具或轮数加分。GPT-2 是共同实验的研究对象，其前向计算本身不能替代 AI 研究动作。

## 最终提交物

每位学生提交一个个人项目仓库链接或压缩包，以下内容必须可定位。下列文件名为分文件组织示例，不要求逐一创建同名文件：

- `problem-definition.md`：问题定义（含非例和可证伪命题）
- `proposal.md`：研究计划（含第一性原理推导和机制假设）
- `evidence-map.md`：证据地图
- `hypothesis-and-judgment.md`：机制假设列表与研究判断记录（含取舍理由和适用边界）
- `experiment-spec.md`：实验规格
- `README.md`：运行说明和项目概览
- `experiments/`：实验配置、日志或结果记录
- `src/`、`notebooks/`、`skills/` 或等价目录：原型和工作流实现
- `agent-workflow.md`：个人 Agent Workflow 的任务契约、上下文、工具权限、评价和运行说明
- `evaluation-report.md`：评价报告
- `ethics-and-compliance.md`：科研伦理与合规说明
- `report.md`：论文式短文和复盘
- `ai-usage-log.md`：AI 使用记录
- `peer-review.md` 和 `revision-plan.md`：同行评审与修改处理
- 工件状态追踪表

### 按内容定位的两种组织方式

分文件版沿用建议结构；合并版可采用 `README.md` 索引＋一份研究主文档＋实现与原始记录。两种方式按相同内容验收，文件数量不作为评分依据。

主文档按问题与证据、命题与判断、实验协议、个人 Agent Workflow、评价结果、伦理与 AI 披露、同行评审处理及复盘组织。使用章节锚点和记录 ID 关联内容；命题文本只维护一份，实验与结果引用其 ID。原始配置、日志、trace 和 AI 使用记录可单独保存，由主文档引用。

| 必需内容 | 分文件示例 | 合并版定位示例 |
| --- | --- | --- |
| 问题、范围、第一性原理与研究计划 | problem-definition / proposal | 主文档 §问题与计划 |
| 精读卡、证据地图与来源 | reading-cards / evidence-map | 主文档 §证据，链接原文与精读记录 |
| 命题、替代解释、研究判断与反馈 | hypothesis-and-judgment / peer-review / revision-plan | 主文档 §命题与判断、§评审处理 |
| 实验规格、预算与复现说明 | experiment-spec / README | 主文档 §协议，README 提供运行入口 |
| 个人工作流与评价 | agent-workflow / evaluation-report | 主文档 §工作流、§评价 |
| 伦理、AI 使用与复盘 | ethics-and-compliance / ai-usage-log / report | 主文档对应章节与记录链接 |
| 工件成熟度与待办 | 工件状态追踪表 | 主文档状态表，保留记录 ID 与修订历史 |
| 实现与原始运行证据 | src / experiments / traces | 同样保留，按记录 ID 引用 |

四个研究门提交当前项目版本的链接、tag 或压缩包；保留阶段快照，不另复制制作阶段报告。内容合并不允许覆盖原始记录或丢失修订历史。合并填写示例见 [RSI 案例主文档](../lessons/lesson-11/assets/rsi-selection-case/README.md)。


## 基本验收条件

满足以下条件才进入评分：

- 项目问题与课程主题相关。
- 项目默认由学生个人完成；例外合作已获教师批准并分别提交个人判断、工作流、日志、贡献说明和答辩。
- 至少复现或实现一个 baseline。
- 至少有一组可追溯的实验结果。
- 至少有一次 AI 辅助科研动作被完整记录。
- 已实现一个服务本人科研动作的 Agent Workflow，并记录 context 来源、工具权限、预算上限、日志位置和人工审核方式。
- 已提交科研伦理与合规说明。
- 所有引用材料标注来源。
- 没有将 AI 生成内容冒充未经验证的事实或原创结论。
- 项目中的每个关键结论至少能追溯到一条证据和一个上游决策。
- 标记为 `stable` 的关键结论原则上有两项独立证据；不足时已标注限制和待验证状态。
- 四个阶段检查点的门条件已满足。

## 学术规范红线

普通技术失败、复现未通过、样本不足或结果不支持假设，只要如实保留记录、说明原因和边界，并按要求修订，就属于研究过程证据，不自动构成学术规范红线。只有编造、隐瞒、越权、覆盖记录，或明知结果不可核验仍冒充已验证结论时，才按下列红线处理。

以下情况应直接扣重分，严重者不予通过：

- 编造文献、数据、实验结果或引用。
- 隐瞒 AI 大量生成的核心文本或代码。
- 只提交无法运行、无法追溯来源的演示材料。
- 使用 AI 生成审稿、实验或数据后不做人工核验。
- 允许 agent 擅自扩大数据访问范围、修改评价协议、覆盖实验记录或删除失败结果。
- 将现成 Agent/Skill 的安装或运行截图冒充为个人工作流设计与实现。
- 违反数据集、模型、论文或软件许可要求。
- 未披露涉及隐私、敏感数据、人类受试者、潜在误用或高风险应用的伦理风险。
- 将 AI 生成内容、代码或实验结论作为未经说明的个人原创贡献。
- 结论无法追溯到证据或决策，直接凭空写入论文式短文。
