    OpenCode 最小启动说明（备选平台）¶

    课前完成准备。课堂只做最小环境确认，不把课堂变成安装排障课。

    一、定位与口径¶

    • 本课程主平台是 Pi Agent，先读 Pi Agent 最小启动说明。OpenCode 是备选平台；平台、模型与后端的选择不构成评分项。
    • 安装与后端连接尽量在课前完成；第 1 课只做最小环境确认（见 §九）。
    • 不要求学生自费购买 API token；优先使用学校部署、开源或合规可用的模型后端（见 §五）。
    • 无法在课前完成安装者，提前向助教报告，按 §四 备用路径参加课堂，不因此掉队。

    二、安装前检查¶

    • 能在终端执行基本命令（cd、ls 等）；
    • 已安装 Git，能初始化与查看仓库（第 1 课产出保存在个人项目中）；
    • 操作系统：macOS、Linux 或 Windows（Windows 建议走 WSL）；
    • 网络可访问你计划使用的模型后端。

    三、安装与启动¶

    以下命令取自 OpenCode 官方文档（核验日期见 §十一）。任选其一即可，无需全部安装。

    方式一：官方安装脚本（macOS / Linux）

    curl -fsSL https://opencode.ai/install | bash

    方式二：npm（跨平台）

    npm install -g opencode-ai

    使用 Bun 等价：bun install -g opencode-ai。

    方式三：Homebrew（macOS / Linux）

    brew install anomalyco/tap/opencode

    方式四：Arch Linux

    sudo pacman -S opencode

    Windows：建议先安装 WSL，再在 WSL 中安装 OpenCode；项目文件可经 /mnt/c/ 等路径访问。详见官方文档的 windows-wsl 一节。

    启动：进入个人项目目录后运行：

    opencode

    连接模型后端：在 OpenCode 界面中使用 /connect 选择提供方并录入凭据。

    项目初始化（可选）：/init 会分析项目并生成 AGENTS.md。本课程建议以课程模板预置 AGENTS.md（见 §六），不完全依赖自动生成。

    四、无法安装时的替代¶

    • 课前向助教报告，说明环境与卡点；
    • 两人临时共用设备：操作仍进入本人的个人项目目录，产出写回本人仓库；
    • 课堂上可跟随教师录屏，用任务契约、预期 diff 和使用记录在纸面或 Markdown 模板中完成同一任务；
    • 备用路径可以改变工具和载体，不降低学习目标。

    五、模型与后端选择原则¶

    按四条原则依次判断：

    1. 可用：在校园网或个人网络环境中能正常使用；
    2. 合规：学校现行 AI 使用规范与服务的数据条款允许处理你的材料；
    3. 成本可控：不自费购买，优先学校部署、开源或免费额度；
    4. 能留痕：能保留 AI 使用记录所需的工具、模型与用途信息。

    未公开论文、保密数据、学生资料或他人材料不得用于安装测试或首次交互。

    四条原则是选择标准；候选按以下三层依次安排，具体后端以授课前教师/助教公布为准：

    1. 学校部署：学校如有可用于教学的部署模型服务，优先使用（槽位：授课前由教师/助教填写接入方式与公告）；
    2. 本地开源：Ollama 等本地运行开源模型，数据不出本机、成本可控（连接方式授课前核验）；
    3. 合规免费额度：条款允许教学使用的服务免费额度；先读数据条款，再使用。

    校园网内海外 API 不可达是常见情况，不把课堂时间消耗在排障上；不可用者按 §四 备用路径参加课堂。

    六、项目目录与 AGENTS.md¶

    • 在课程仓库之外创建个人项目目录（位置与结构见第 1 课讲义 §七）。
    • 最小文件结构参照 早期研究脚手架：问题定义、权限矩阵、工件追踪、AI 使用记录等。
    • AGENTS.md 用于声明本次任务边界：默认只读范围、允许写入的目录、命令执行确认与网络访问边界。建立个人项目时直接使用 早期研究脚手架"最小文件结构·AGENTS.md 最小模板"，不需要从零设计；课前自取，课堂只校对。

    初始化（课前完成）：

    mkdir my-research-project && cd my-research-project
git init
# 按早期研究脚手架"最小文件结构"创建 AGENTS.md、problem-definition.md、
# artifact-tracking.md、ai-usage-log.md、agent-permissions.md、notes/
git add -A && git commit -m "baseline: 个人项目起点"

    基线提交是第 1 课"检查 diff"步骤的前提：没有基线提交，git diff 将无输出。

    七、OpenCode 最小操作速记¶

    完成第 1 课实践所需的最小操作（界面细节授课前复核）：

    1. 进入与启动：cd 进个人项目目录，运行 opencode；
    2. 发消息：粘贴任务契约（最小 prompt 见第 1 课课堂材料包与讲义 §五），把【可替换处】换成你自己的问题；
    3. 批准写入：课前确认所用版本已把目标写入操作配置为询问；出现确认时核对文件清单，只批准任务范围内的写入。若没有可核验的限制配置，先由 Agent 提供建议，再由人应用；
    4. 查看变更：终端运行 git diff，或在会话界面查看实际修改文件列表；
    5. 留记录：把工具、模型、用途、Context 与人工核验写入 ai-usage-log.md。

    八、权限与网络边界（第 2 课预告）¶

    • 默认最小权限：先只读，人工确认后写回，且只写目标文件；
    • 不启用全盘读写或无确认的命令执行；
    • 网络访问按任务需要开启，任务不需要联网时不联网；
    • 第 2 课将把这些边界正式化为权限矩阵与风险卡。

    九、课前自查清单¶

    课前逐项确认，并把未通过项与处理方式记下来：

    • [ ] opencode 能在终端启动，无报错；
    • [ ] 已通过 /connect 连接一个模型后端，能正常完成一次问答；
    • [ ] 个人项目已初始化并完成基线提交（§六 命令块）；
    • [ ] AGENTS.md 已按脚手架最小模板自取粘贴（课堂只校对）；
    • [ ] Git 可用；
    • [ ] 任一项失败：记录卡点，课前报告助教，并准备按 §四 备用路径参加课堂。

    十、课堂口径¶

    • 第 1 课只做最小环境确认，不做逐台安装；共性卡点由教师统一处理，个别环境问题不占用全班时间；
    • 环境问题记入退出卡，由助教在第 2 课前收集并统一处理。
