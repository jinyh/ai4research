### 各课程特色与借鉴点

**UC Berkeley CS294/194-196**：
- 特色：全球最大规模 Agentic AI MOOC（25,000+ 学习者），理论深度与应用广度兼备
- 借鉴：进阶路径设计（基础课 → 进阶课）；考虑录制核心讲座视频扩大影响力

**Johns Hopkins Agentic AI Certificate**：
- 特色：四大能力框架（感知-规划-学习-行动）；渐进式设计（Python→LLM→Agent→项目）；学分可计入硕士
- 借鉴：四大能力框架可与八阶段研究链路互补（感知→外部输入摄取，规划→问题定义，学习→证据整理，行动→原型验证）

**eCornell Agentic AI Architecture**：
- 特色：非开发者友好；深度使用 Claude Code 和 LangGraph；从原型到生产的完整路径
- 借鉴：模块化设计思路；降低非 CS 学生门槛的策略

**MIT MAS.664 AI Agents and Agentic Web**：
- 特色：前瞻性极强（"Internet of Agents" 愿景）；六大主题（身份/信任/声誉/支付/评估/协调）；去中心化架构
- 借鉴：信任和声誉机制可引入学生互评环节；前瞻性主题激发学生对未来科研形态的思考

**UNL AGST 492/892**：
- 特色：零门槛跨学科；伦理贯穿全课（非附加章节）；学生将 AI 代理应用到自己的研究方向
- 借鉴：伦理贯穿模式（与本课程设计原则第 8 条一致）；"应用到自己的领域"的项目设计

### 国外课程的共同趋势

1. **Agentic AI 成为独立学科**：不再是"AI 工具使用"的子集，而是有独立方法论和能力框架的领域
2. **项目驱动教学**：所有课程都要求学生产出可运行的系统或研究成果
3. **从简单工作流到代理系统**：课程案例普遍覆盖工具使用、状态管理、评价与多代理协作，但复杂度应由任务需要决定
4. **伦理贯穿**：从附加章节转向全流程嵌入
5. **从原型到生产**：研究也需要工程化思维
6. **跨学科开放**：不限于 CS 学生，降低技术门槛

### 本课程的差异化优势

国外课程普遍偏向 Agentic AI 的技术、架构、工作流和项目实践；本课程偏向研究方法论导向，训练研究者用 AI 支撑可审查、可追溯、负责任的科研链路。差异体现在：

- 有明确的研究链路（八阶段）而非松散的工具清单
- 有质量门控（四个研究门）而非仅有最终项目评估
- 有证据充分性检查而非仅要求"做了实验"
- 有工件状态追踪而非仅有代码提交
- 有伦理约束贯穿全流程而非独立模块

对本课程的启发：

- 保留 agentic AI 和实验自动化的前沿内容，但不让它压倒科研方法主线。
- 将 agent 框架、RAG、代码生成、MCP、Skill、评估和实验自动化作为分析工作流逻辑的案例，而非现成 Skills 使用教程。
- 明确加入评估、安全、科研伦理、人工监督和学术规范。
- 采用项目制，而非单次工具练习。

### AutoResearch 元模式

所有 AutoResearch 项目收敛于一个共同的元模式：

```
修改（Edit）→ 评估（Evaluate）→ 保留/丢弃（Keep/Discard）→ 重复（Repeat）
```

该模式适用于任何具备以下四个条件的领域：
1. 可测量的标量指标（如 val_bpb、R²、TFLOPS）
2. 可编辑的工件（代码、配置、提示词）
3. 固定的评估预算（5 分钟、10 次迭代等）
4. 二元的保留/丢弃决策门

跨领域验证案例：GPU 内核优化（18→187 TFLOPS）、Shopify Liquid（53% 加速）、棒球球速预测（R² 0.44→0.78）、比特币预测（RMSE 改进 50.5%）。

对本课程的启发：

- 自动化实验必须有受限执行边界、固定评价指标和可审查日志。
- 学生项目不要求“完全自动科研”，而要求“AI 辅助 + 人工审核”的科研闭环。
- 课程应要求披露 AI 使用，记录 prompt、工具、输出用途、核验方式和误导案例。
- Research Agent 的教学重点应从工具名称转向任务契约、Context、Memory、工具与权限、状态与工件、执行循环、Evals、人工审核点和失败恢复。
- Memory 应落实为可审计项目工件和日志，而不是依赖模型隐式记忆。

## 4. 方法论框架选择依据

来源：历史 harness-research 项目的方法论设计及本文件保留的适配记录。该源项目不在当前工作区，本轮不能直接复核；因此课程实施以本文件、课程大纲和模板中已经明确的通用化规则为准。结构化质量门思想另可参照 [BMAD Method](https://github.com/bmad-code-org/BMAD-METHOD)。

本课程选择引入 harness-research 项目的八阶段研究链路作为方法论框架，但进行了通用化适配。以下是选择依据和适配决策。

### 为什么选择 harness 八阶段研究链路

- harness-research 的研究方法论体系借鉴了 BMAD Method 的结构化思想，将软件开发的质量门机制适配为学术研究工作流的质量关卡。这套方法论已经在一个真实研究项目中实践，不是理论设计。
- 八阶段链路（问题定义→第一性原理分析→机制假设→外部输入摄取→证据整理→研究判断→原型验证→回写）比原有六阶段描述（文献→问题→假设→实验→分析→写作→评审）更精细，每个阶段有明确的输入、输出和退出条件。
- 研究门（Gate）机制解决了原有方案中"Checkpoint 条件不够明确"的问题。门条件是可逐条核对的验收标准，而非泛泛的"具备"描述。
- 证据分级和多源核验原则解决了原有方案中"文献综述容易沦为摘要堆叠"的问题。学生需要区分证据角色，组织证据地图，说明关键结论的证据来源、支持强度和缺失风险，确保结论不凭空得出。
- 工件状态追踪和追踪字段解决了"结论不可追溯"的问题。每个研究产出有状态，每个结论有依据和后续用途。

### 通用化适配决策

| Harness 原概念 | 课程适配 | 原因 |
| --- | --- | --- |
| 八阶段研究链路 | 八阶段研究链路（通用化） | 保留核心结构，去掉领域特有判断（thin-harness-thick-skill） |
| thin-harness-thick-skill | 不引入 | 领域特定概念，对通用科研课程不必要，会增加不必要的认知负担 |
| 工件 ID 体系（RB-/EM-/ADR-/ES-/EV-/SV-/IN-/BP-/ID-） | 简化为中文名称工件 | kebab-case ID 体系对 32 学时入门课程过于工程化，中文名称更直观 |
| 工件生命周期（5 状态） | 简化为轻量 4 状态（draft→review→approved→stable） | 去掉 archived 状态，32 学时课程不需要归档机制；状态用于追踪成熟度，不作为孤立评分目标 |
| 证据三角验证（论文+企业博客+项目代码） | 降级为证据分级与多源核验（理论证据、实践证据、对比证据、补充线索作为可选分类） | harness 领域的固定三角来源不适用通用科研课程；本课程保留"结论不能凭空得出"的思想，但不强制凑齐固定证据组合 |
| Gate 1-7 | 课程四门（问题门、判断门、验证门、论证门） | 四门对应四个 Checkpoint，不增加考核复杂度 |
| 追踪字段（upstream_ids/downstream_ids/source_refs） | 简化为"来源/依据/后续"三字段 | 降低学生实施负担，保持追踪意识 |
| 完整工程脚手架 | 分阶段引入 | 第 1-6 课使用轻量研究脚手架，第 7-8 课继续完善方案，第 9 课起迁移到完整项目模板 |
| 三路径产出（SV/BP/ID） | 不引入 | 对 32 学时课程过于复杂，学生只需完成一种产出 |
| 空白驱动工作流变体 | 不引入 | 属于进阶方法论，不适合入门课程 |

### 保留的核心思想

- 有门的科研工作流（研究推进需要通过质量关卡）
- 证据分级与多源核验（结论不能凭空得出）
- 工件状态追踪（研究产出有状态和追踪关系）
- 结论可追溯性（每个结论绑定证据和上游决策）
- 研究判断记录（关键取舍有理由、有适用边界）

## 5. 本轮迭代决策

本轮在既有结构化研究方法论基础上，进一步确定可执行的教学组织：

- OpenCode 从第 1 课起作为统一课堂工作平台；它是承载环境，不是学习目标，也不限制模型或后端。
- 课程不讲解现成 Skills 的安装和调用步骤，而是拆解任务契约、上下文、工具权限、状态与工件、执行循环、评价、人工审核和失败恢复。
- 每位学生独立完成一个真实或半真实研究项目，并为其中一个科研动作设计、实现和评价个人 Agent Workflow。
- 3-4 人固定同伴组只承担分享、互查和同行评审，不共同提交；确需双人完成的高计算量实验须事先批准，并分别提交个人工件和反思。
- 正式提交压缩为四次：第 6 课问题门、第 9 课判断门、第 13 课验证门、第 16 课论证门与期末项目合并提交。
- 第 8 课加入学生研究方案分享与设计诊所，不增加正式提交；第 15 课只做论证门预检、同行评审和修改。
- 关键结论至少绑定一项可核验的直接证据或实验结果及上游决定；`stable` 结论原则上需要两项相互独立的证据，不强制固定证据类型组合。
- 只有单一证据时，必须标注支持强度、适用边界、缺失证据和待验证状态；AI 输出只能作为线索，不能单独成为证据。
- 逐课阅读采用“正式书目 + 课堂案例”双层结构：正式书目以经典书籍选章、同行评议论文、共识报告和正式规范为主；GitHub、厂商文章、协议文档、大学课程讲义、演讲稿、转载讲义和真实回复只作为版本化案例。
- 英文经典保留原典，由教师提供中文阅读范围、术语和问题，不以来源不明的中文转载替代正式版本，也不制作未经授权的全文翻译。
- AI 辅助核心阅读采用“AI 导航→原文核验→AI 质疑→偏差审计→人工定稿”；AI 摘要不构成阅读完成或证据。精读卡记录原文位置、AI 偏差/遗漏或已检查风险和最终人工判断。
- 阅读记录持续进入个人项目，在第 6 课问题门抽查至少 3 张完整精读卡；不新增逐周正式作业，不改变四次研究门和评分比例。

本轮方法论框架来源为 harness-research 项目，但进行了通用化适配，去除了领域特定概念，降低了实施复杂度，确保适合 32 学时研究生入门课程。
