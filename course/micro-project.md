# 个人微型项目：阅读记录校验与评价可靠性

版本：v1.0.0
最后更新：2026-10-12

## 可以在一个项目里完成的研究问题

默认问题：**对冻结的小型阅读记录集，增加输入校验能否减少坏记录进入后续评价，同时保留正常记录及其内容？**

学生自行定义错误范围、选择校验方式并解释取舍。也可选择同等规模的分组盲化、评价审计或队列恢复问题。共同材料提供起点，选择、实现、验证与结论由本人完成。研究对象是这条处理流程；结果不能外推为模型阅读理解改善。

正常输入：paper_id 和 summary 都是非空字符串；输出保留 paper_id，清理 summary 首尾空白。必须同时检查坏记录拦截与正常记录保留。简单拒绝所有记录虽然拦截率高，却违背任务。程序测试通过后，仍要说明这些测试覆盖哪类研究风险。

## 运行起点

使用[微型项目运行包](../lessons/lesson-10/assets/micro-project/README.md)。Python 3 标准库即可运行，不调用模型、不要求付费额度。输入与参考判定是公开教学构造；它们是开发检查集，不能称为未见过的独立测试。

在自己的项目副本内操作。保留原 baseline.py，复制为 changed.py；修改实现，不改冻结输入和评价代码。运行目录区分版本。先执行 baseline，再执行改动版，使用同一 reference.json 分别评价；若确需修正参考判定，先解释协议变化并重评双方，保留旧报告。

## L9–L13 的接续

| 课次 | 本人实际动作 | 与研究判断的关系 |
| --- | --- | --- |
| L9 | 执行 baseline，冻结输入/协议，同伴复现 | 哪些是坏记录？正常内容是否被保留？ |
| L10 | 预测候选补丁行为，修改 changed.py，保留失败及对照 | 根因修复还是吞异常/删分母？ |
| L11 | 用 --fault-once 受控中断，再恢复；核对成功任务不重复 | 技术恢复、负结果与停止分别如何处理？ |
| L12 | 将本人校验接入实际队列；核对输入、输出、人工检查与评价 trace | 这个环节需要多少自主性？ |
| L13 | 汇总坏记录拦截、正常项误拒、失败和成本，做采用/修订/停止决定 | 改动是否改善了所定义的动作，证据支持到哪里？ |

原[阅读卡回放包](../lessons/lesson-11/assets/reading-card-workflow/README.md)的 replay、evaluate、access-check 保持不变；用于语义标注、保存输出回放与权限接口教学。本包执行学生代码，用于检验实质实现与队列行为。两者可以服务同一个研究问题，不形成第二个项目。

## 足够小且仍有判断难度

课堂先使用 8 条公开输入。本人需识别至少一个未覆盖的有效性威胁，例如合法空字符串是否真的应拒绝、ID 是否需要去空白、错误结构是否属于研究对象。若选择一个新边界，在 L10 修改前记录预期和理由；纳入开发的材料保持开发身份。没有独立测试时，就报告开发检查上的行为与未验证范围，不伪称泛化。

对照要保留所有输入的处理结果；成功、拒绝、异常和受控中断各自有事件，不通过删除记录使指标好看。运行时间为本机单次测量，不能据此声称性能提升。CPU 实现和记录均可在课堂完成；安装、准备及课后修补计入每课 60 分钟上限。

## 最终论证使用现成材料

短报告直接引用问题定义、冻结协议、diff、两个运行目录和评价报告，说明一次取舍、一个反例/失败或未决问题。无需额外制作一套表格，也不要求使用 Agent、MCP 或多个工具才能取得优秀评价。
