# research-question-to-search

本 skill 把"研究问题 → 可复盘检索式 → 公开源检索 → 身份核验 → 候选文献表行"变成带记录、带人工判断点的受限流程。方法论源是 `lessons/lesson-03/handout.md` §一-§七（v1.1.0 门控冻结版）与 `references/material-contracts.md` §三 四态定义；本文件不另立口径，两处修订时以源文件为准并同步本文件。

## 触发条件

满足任一即进入：

- 需要为一个研究问题或宽泛主题构造可复盘的检索式并执行检索；
- 需要对 AI 或检索给出的文献列表做回源身份核验与状态建议（来源审计）；
- 需要为个人项目或教师演示建立检索记录与候选文献表初稿。

## 任务契约

| 要素 | 内容 |
| --- | --- |
| 输入 | 研究问题（最小版：对象与场景、干预或观察、比较条件、结果指标四要素）或宽泛主题；可选：机制假设上下文（用于证据角色建议） |
| 输出 | 检索记录（七字段）、检索式迭代日志、身份核验证据链、候选文献表行（十字段，镜像 handout §五）、待精读移交项清单 |
| 成功标准 | 他人凭检索记录可复盘到同一结果集；每条候选行的状态建议有证据链；进入规则无违反 |
| 不适用 | 原读主张核验（第 4 课职责）、综述写作、订阅源获取、Zotero 库管理、研究问题定稿 |

## 执行循环（镜像 handout §七 七步）

1. **收敛问题**：宽泛主题 → 四要素最小问题建议；问题定稿由人工完成。
2. **抽词与扩展**：每个核心词扩展同义/上位/下位/相关词；扩展来源三分——已发表论文 keywords 字段、综述术语表、AI 候选词（AI 候选标为线索，进入最终检索式前须回源确认该词有真实文献支撑）。
3. **构造检索式**：布尔算子、字段限定、截断通配、引号短语、时间与文献类型限定；注明目标库语法差异。
4. **先写纳入排除**：检索前产出第一版（时间范围、文献类型、语言、研究类型、相关性）；检索中每次调整连同理由写入迭代日志。
5. **执行并记录**：公开 API 检索，命令与响应存档；检索记录七字段＝库、检索式、检索日期、时间范围、命中数、纳入/排除标准、纳入数。库语法实践注记：Crossref `query.bibliographic` 噪声大（题名相近的评论、书评可排前），优先拆 `query.title` + `query.author` 字段查询；Semantic Scholar 无 key 限流，失败即按失败恢复条款切换。
6. **来源审计（双层核验）**：
   - 身份层：题名、作者、年份、刊名/会议、DOI 是否在正式来源（Crossref、DOI 解析、出版社/会议官方页）一致；
   - 主张层：原文任务、设置、措辞强度、限定条件——只在开放全文可得且人工确认时进行，否则不启动；
   - 每条输出证据链（核验源链接与日期）与状态建议。
7. **按进入规则写表**：候选行列按 handout §五 十字段镜像；`rejected` 只入审计记录，永不入候选表；`pending` 只留线索区并显著标待核验；`verified-with-caveat` 必须同行携带 caveat 与原文页码/节号。

## 状态建议规则（material-contracts §三 镜像）

| 情形 | 状态建议 |
| --- | --- |
| 身份层通过、主张层未做 | `pending`（注明"身份已核，待主张核验"） |
| 身份层失败：来源不存在、DOI 无法解析、元数据与声称不符（张冠李戴、作者拼接） | `rejected` |
| 身份层+主张层均过，无限定 | `verified`（须人工确认） |
| 身份层+主张层均过，存在范围/方法/版本/措辞限定 | `verified-with-caveat`（须人工确认，保留限定与原文位置；不得单独支撑 `stable`） |

状态名使用精确拼写：`pending` / `verified` / `verified-with-caveat` / `rejected`，不得缩写为 `caveat` 或 `with caveat`。

## 证据角色建议

默认一律标探索线索（handout §三要点 4：AI 检索结果默认归此类）。主证据/补充证据/对比证据只在提供机制假设上下文时给出建议，附一句理由，最终角色由人工定。一条材料可承担多角色，主角色写在前。

## 人工审核点（不得代行）

- 研究问题定稿；
- 纳入/排除条件定稿与排除理由确认；
- 状态从 `pending` 升级到 `verified` / `verified-with-caveat`；
- 候选行最终写入个人项目工件。

skill 只产出建议与证据链；未经人工确认的条目保持建议态。

## 工具与权限

- 仅公开学术 API，用 curl/命令行直调并存档命令与响应：Crossref（`api.crossref.org`，身份核验首选）、arXiv（`export.arxiv.org/api`）、OpenAlex（`api.openalex.org`）、Semantic Scholar（`api.semanticscholar.org`，无 key 限流严格）、dblp；
- 可选只读查询本机 Zotero 库（Zotero MCP）作已有文献核对；不做集合创建、导入、去重；
- 写入仅限任务指定的产出文件；检索过程缓存进 `.work/`；
- 查询内容只来自公开问题描述；未发表素材、`.local/` 内容、学生敏感信息不得进入任何查询或外部请求；
- 订阅源（Scopus、Web of Science、CNKI、ScienceDirect 等）不做自动化访问；人工手动检索的结果可由人工提供后作为记录项登记。

## 工件与追踪

| 工件 | 内容 |
| --- | --- |
| 检索记录 | 七字段表，每次检索一条 |
| 迭代日志 | 检索式版本、修改内容、修改理由、时间 |
| 审计记录 | 逐条双层核验结果、证据链、状态建议；`rejected` 条目只在此保留 |
| 候选文献表行 | 十字段：编号 / 题名（核验后）/ 作者 / 年份 / 来源（DOI/会议/出版社）/ 证据角色 / 纳入排除 / 理由 / 核验状态 / caveat-允许主张 |
| 待精读移交项 | handout §四·2 清单第 3-7 项中未完成的核验项，逐条列出供第 4 课或人工跟进 |

非论文外部输入（仓库、规范、官方文档、工程文）登记为线索条目，做可达性检查（URL/仓库存在性），不套用论文身份核验流程，不假装已核验。

## 失败恢复

- 检索死路（0 命中或命中全不相关）：记录死路与当时检索式，给出修订建议，人工决定是否改式重试；
- API 限流或超时（Semantic Scholar 常见 429）：记录后切换备用源（OpenAlex），不静默重试同一请求；
- DOI 解析失败：标 `rejected` 候选留审计记录；
- 断网：停止执行，只保留已有记录；不编造任何离线"已核验"条目（handout §八练习 5 纪律）。

## Evals

- 复盘性抽查：另一人或另一 agent 凭检索记录重跑检索式，命中集合应一致（日期敏感时允许说明性差异）；
- 回归基线：重放 Keshav 2007 trace（`lessons/lesson-03/source-audit-demo.md`）输出应与已核验记录一致；
- 审计抽样：候选表随机抽样回原文核对身份层字段。

## 边界

- 不生成综述、摘要堆叠或"AI 综合报告"式叙述文本——输出只有结构化记录；该 skill 的设计立场是此类报告的审计方，不是生产方。
- 不设定数量目标；条目数以核验推进为准（handout §六错误 4）。
- 冲突证据双方保留，检索与筛选不为只收支持项服务（handout §六错误 2）。
- 不进入 `lessons/lesson-NN/` 三件套内容口径；作为教学工具资产在各课 README 单独登记。
- 完成后先报告产出、证据链与待人工确认项，不自动 commit 或 push。
